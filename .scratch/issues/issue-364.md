## 구현 목적

캐릭터 시트의 능력 식별자와 자원 현재량·최대량·회복 조건을 정본으로 관리한다.

## 범위

- 계획 식별자: plan-364.
- 능력 선택과 시트 설정·수정은 사용자 명령으로 확정하며, 런타임은 확정된 규칙 결과와 자원만 반영한다.
- 해당 제품·구조 명세의 이 수용 기준에 직접 필요한 기존 화면, API, 정책, 저장소 경계만 수정한다.

## 수용 기준

- 요구사항 추적: AC-37, BR-37, EX-03, G-11.
- 소유 경계: Character Sheet 자원 자료와 기존 자원 명령; 시행 지점: 자원 사용·회복 명령에서 현재량·최대량·회복 조건·멱등 키를 검증.
- 주문·기술에 필요한 자원 식별자, 현재량, 최대량, 회복 조건을 캐릭터 시트에 저장한다.
- 전투·비전투 실행은 조건이 충족되고 사용이 확정되면 캐릭터 시트가 소유한 해당 자원을 한 번만 소모한다. 효과가 없거나 GM이 엔진을 대신해도 확정 사용 비용은 유지한다.
- 사용 가능한 능력 식별자와 각 자원의 현재량·최대량·회복 조건을 시트 조회 응답에 보존한다. 현재량은 0 이상 최대량 이하이고 부족한 자원은 소모할 수 없다.
- 회복은 GM/모험 진행 규칙이 저장된 회복 조건 충족을 확인한 내부 명령에서만 적용하고 최대량을 넘지 않는다. 플레이어가 직접 조건 충족을 주장하는 시트 변경 요청은 허용하지 않는다.
- 같은 명령 식별자와 같은 입력을 다시 보내면 기존 결과를 돌려주며 상태를 다시 바꾸지 않는다. 같은 식별자를 다른 입력에 재사용하면 거부한다.
- 금지 사례: 확정 전 자원을 소모하거나 같은 명령 재전송으로 자원을 두 번 소모한다.

## 테스트 계약

- 개발용 진단 검증 (Architecture Spec §9.1·INV-01): 이 계획이 바꾸는 각 시작·완료·대체 경로·재시도·실패 분기에서 기존 `DevelopmentDiagnostics`(개발 진단 기능)와 `dev_` 개발 로그 형식을 확인한다. `ADVENTURE_RUNTIME_DIAGNOSTICS_ENABLED`(개발용 상세 진단 로그 설정)가 꺼졌을 때 상세 로그가 없고, 켜졌을 때 식별자·입력 크기/개수·기대/실제 값·선택 분기·소요 시간·실패 종류와 다음 복구 동작이 드러나며, 프롬프트·응답·인증 정보·불필요한 플레이어 입력·비공개 지도 정보를 기록하지 않고 실제 동작도 바꾸지 않는지 검사한다.

- 단위/정책: 0·최대량 경계와 초과 회복 제한, 부족 상태 거부, 확정 전 무소모·확정 후 단일 소모, 저장 회복 조건 일치, 동일 명령 재생 및 같은 명령 식별자의 입력 충돌 거부. API: 내부 런타임 명령으로 능력 식별자·자원 상태를 저장하고, 버전 확인·명령 식별자 재사용·권한 경계·저장 결과를 확인한다. 회복 명령은 GM 판정 뒤에만 호출한다. API·저장 검증: 내부 런타임 명령으로 자원 소모·회복을 실행하고, 명령 중복·버전 충돌과 저장된 정본을 확인한다. 시트 화면이 표시하는 현재량·최대량·회복 조건이 API 조회 결과와 일치하는지 확인한다. 전투 화면에서 능력을 실행하는 E2E는 #372, 비전투 GM 판정 E2E는 #373에서 검증한다. 요구사항 식별자: AC-37, BR-37, EX-03, G-11. 소유 경계와 실행 진입점: Character Sheet 자원 자료와 기존 자원 명령; 자원 사용·회복 명령에서 현재량·최대량·회복 조건·멱등 키를 검증. 추적 수용 조건: 주문·기술에 필요한 자원 식별자, 현재량, 최대량, 회복 조건을 캐릭터 시트에 저장한다. 반례: 확정 전 자원을 소모하거나 같은 명령 재전송으로 자원을 두 번 소모한다. 검증 사례: 단위/정책: 0·최대량 경계와 초과 회복 제한, 부족 상태 거부, 확정 전 무소모·확정 후 단일 소모, 저장 회복 조건 일치, 동일 명령 재생 및 같은 명령 식별자의 입력 충돌 거부.
- `ui ~ entity` E2E: 해당 없음 — 이 계획의 경계는 저비용 정책·단위·통합 검사로 확인하며, 실제 에이전트 포함 경로는 #369에서 한 번 검증한다.
