## 의존성

#367

## 구현 목적

전투가 시작될 때 그룹의 위치와 대열을 캐릭터별 전투 위치로 바꾸고 전투 종료 후 그룹을 복원한다.

## 범위

- 계획 식별자: plan-368.
- 전투 시작 위치와 전투 종료 뒤 그룹 구성 복원은 사용자가 조작하는 파티 캐릭터 전원에 적용한다. GM은 적만 조작한다.
- 해당 제품·구조 명세의 이 수용 기준에 직접 필요한 기존 화면, API, 정책, 저장소 경계만 수정한다.

## 수용 기준

- 요구사항 추적: AC-36, AC-41, BR-44, BR-45, BR-49, UC-005.
- 소유 경계: 기존 전투 지도 화면(`CombatMapView`)과 `AdventurePlayApi`가 Solo Player의 전체 배치를 받고 화면의 모험·지도 버전을 함께 제출한다. 모험 진행 서비스의 #367 전투 전환 정보와 전투 지도 서비스의 기존 전환 경계를 사용하며, 지도 적 토큰과 전투 참여자 대응, 적별·캐릭터별 인지 전달, 참여자별 첫 차례 기습 상태, 전투 캐릭터별 이동과 종료 뒤 그룹 복원을 검증한다.
- 2026-10-23 사용자 승인 결정: 각 탐험 그룹 토큰 위치를 기준점으로 가장 가까운 적 방향을 전열 방향으로 삼는다. 적이 없으면 북쪽, 거리 동률은 서버 식별자 순으로 결정한다. 전열·중열·후열 순서로 모든 구성원을 서로 다른 유효 칸에 배치한다. 고정 배정은 전열 깊이 0·중열 뒤 1칸·후열 뒤 2칸, 같은 대열은 서버 캐릭터 식별자 순 옆 간격 0, -1, +1, -2, +2, …를 사용한다. 정확한 좌표식은 Architecture Spec의 전투 전환 절을 따른다. 하나라도 무효이면 다른 빈칸을 자동 탐색하지 않는다. 지도는 기하·일괄 교체, 모험 진행은 그룹·대열·전투 진행 상태를 소유한다.
- 일반 탐험 그룹 토큰 동기화는 배치 대기·진입·전투 진행·종료 중 전투 캐릭터 토큰 식별자·위치·인지 상태를 덮어쓰지 않는다. 일반 조회나 동기화·재시작 복구도 저장된 전환 단계에 맞는 토큰 표현을 보존한다.
- 전투 이동은 캐릭터별 이동량으로 처리하며, 경로의 각 칸에서 지형·벽·문 통과 가능 여부, 남은 이동량, 발견·공간 요소 반응을 확인한다. 그룹 탐험 이동 속도는 전투 이동에 적용하지 않는다.
- 전원의 유효 칸을 한 번에 확보하지 못하면 지도·토큰·안개를 그대로 유지하고 배치 대기를 저장한다. Solo Player는 기존 전투 지도 화면에서 전원 배치를 선택·제출하고, 요청에 담긴 화면의 모험 버전과 지도 버전이 모두 최신인지 확인한 뒤 지도 소유자가 모험 소유자·전원 포함·중복·벽/지형/점유·도달 가능성을 검증하여 같은 작업을 재개한다. 어느 한 버전이라도 오래되면 배치나 지도 상태를 바꾸지 않고 거부한다. 일부 배치만 적용하지 않는다.
- 진입·종료 토큰 교체는 지도 소유자의 한 번의 원자적 작업이다. 모험 진행은 전투·방향별 서버 소유 작업 식별자와 원본 그룹을 먼저 저장하며, 같은 방향의 재시도·재시작에는 같은 식별자를 쓴다. 지도 작업 상태와 결과를 토큰 교체와 함께 저장한다. 응답 유실은 같은 작업 조회로 복구하고 중복·부분 전환을 금지한다. 지도 완료 확인 전에는 다음 전투/탐험 차례를 시작하지 않는다.
- 전투 진입 시 #367에서 전달한 서버 소유 지도 적 토큰과 전투 참여자의 대응 및 적 토큰별·캐릭터별 인지 관계를 받아, 대응하는 전투 참여자의 첫 차례 기습 상태를 보존한다. 적별 인지 관계를 합쳐 다른 적이나 참여자에게 적용하지 않는다.
- 전투 종료 시 원본 그룹 식별자·구성원·대열을 복원하고 그룹 토큰은 전열 캐릭터의 현재 칸에 둔다. 전열이 여러 명이면 서버 캐릭터 식별자 순 첫 구성원을 사용한다. 서로 다른 그룹은 자동 합치지 않는다. 유효한 전열 캐릭터가 없으면 다른 구성원을 자동 기준점으로 꾸미지 않고 지도를 그대로 둔 채 기존 전체 배치 대기로 복구한다. Solo Player는 기존 전투 지도 화면에서 전원 배치를 제출하고 지도 소유자는 요청에 담긴 최신 모험 버전과 지도 버전을 모두 검증한다. 어느 한 버전이라도 오래되면 대기 상태와 지도를 그대로 유지하고 거부한다.
- 금지 사례: 일반 탐험 그룹 동기화가 배치 대기·진입·전투 진행·종료 중 전투 캐릭터 토큰 식별자·위치·인지를 덮어쓴다. 유효한 전열이 없는데 다른 구성원을 자동 기준점으로 정한다. 고정 배정 칸이 무효인데 먼 빈칸을 몰래 찾아 자동 배치한다. 토큰 일부만 교체하거나 재시도·재시작에서 중복 생성한다. 지도 전환 완료 확인 전에 모험 진행의 전투·탐험 차례를 진행한다. 전투 종료 시 원래 그룹 대열을 복원하지 않거나 서로 다른 그룹을 자동 병합한다. 지도 적 토큰별 인지를 합집합으로 처리하거나 잘못 연결된 전투 참여자에게 기습 상태를 적용한다.

## 테스트 계약

- 개발용 진단 검증 (Architecture Spec §9.1·INV-01): 이 계획이 바꾸는 각 시작·완료·대체 경로·재시도·실패 분기에서 기존 `DevelopmentDiagnostics`(개발 진단 기능)와 `dev_` 개발 로그 형식을 확인한다. `ADVENTURE_RUNTIME_DIAGNOSTICS_ENABLED`(개발용 상세 진단 로그 설정)가 꺼졌을 때 상세 로그가 없고, 켜졌을 때 식별자·입력 크기/개수·기대/실제 값·선택 분기·소요 시간·실패 종류와 다음 복구 동작이 드러나며, 프롬프트·응답·인증 정보·불필요한 플레이어 입력·비공개 지도 정보를 기록하지 않고 실제 동작도 바꾸지 않는지 검사한다.

- 통합 검증: 배치 대기·진입 전후·전투 진행·종료 전후마다 일반 지도 조회와 탐험 그룹 동기화를 호출하고 프로세스를 재시작한다. 저장된 전환 단계에 맞는 그룹/캐릭터 토큰 표현, 동일 토큰 식별자·위치·인지와 전환 작업 식별자가 유지되어야 한다. 전열 없는 그룹의 종료는 지도 무변경·전체 배치 대기로 남고, Solo Player의 유효한 전체 배치 검증 후에만 복원된다.

- 승인 결정 검증: 가장 가까운 적 방향, 적 없는 북쪽 대체, 적 거리 동률·같은 대열의 서버 식별자 순서와 고정 깊이·옆 간격과 반복 실행의 같은 결과를 확인한다. 전열·중열·후열의 서로 다른 칸, 벽·닫힌 문·지도 경계·점유 및 그룹 간 배정 중복을 검증한다. 고정 배정의 칸 하나가 무효일 때 지도 다른 곳의 빈칸으로 자동 이동하지 않아야 한다.
- 공간 부족 검증: 한 구성원만 배치 불가해도 지도·토큰·안개가 그대로이고 배치 대기가 저장·복원되는지 확인한다. Solo Player의 일부·중복·불법 전원 배치는 대기를 유지하며, 오래된 모험 버전 또는 지도 버전의 제출은 각각 모험 상태와 지도 상태를 바꾸지 않고 거부한다. 유효한 전원 배치만 같은 작업으로 한 번에 적용한다.
- 복구 검증: 진입·종료 각각 지도 적용 전 장애, 적용 후 응답 유실과 프로세스 재시작을 같은 서버 작업 식별자로 복구하여 전체 교체가 한 번만 발생하는지 확인한다. 같은 식별자에 다른 입력은 거부한다. 종료 뒤 원본 그룹 식별자·구성·대열·전열 현재 칸과 별도 그룹이 유지되고, #367 인지·적 토큰/참여자 대응·첫 차례 기습 상태가 바뀌지 않아야 한다.
- 화면/API 계약 검증: `CombatMapFlow.test.tsx`에서 Solo Player가 기존 `CombatMapView`에서 파티 캐릭터 전원의 칸을 선택하면 요청에 화면의 모험 버전·지도 버전과 각 대상의 칸이 함께 전달되는지 확인한다. `HttpAdventurePlayApi`의 인증 경로 요청 본문이 두 버전과 전체 배치를 포함하는지 확인한다. Adventure API 검증은 `ExplorationEnvironmentControllerTest.ownerPlacementRejectsAnotherPlayerBeforeMapAccess`에서 모험 소유자가 아닌 인증 사용자의 요청을 지도 조회 전에 거부하는지 확인하고, 오래된 모험 버전을 지도 조회·저장 전에 거부하며 오래된 지도 버전은 모험 상태 저장과 지도 전환 요청 전에 거부하는지 확인한다. `adventure-exploration-cycle-unit` 프로필은 이 API·화면 검사를 포함한다.

- 단위/정책: 그룹에서 전투 배치로의 변환, 복원, 배치 불가 처리, 적별·캐릭터별 인지 관계 전달, 참여자별 첫 차례 기습 상태를 검증한다. 요구사항 식별자: AC-36, AC-41, BR-44, BR-45, BR-49, UC-005. 소유 경계와 실행 진입점: 모험 진행 서비스의 #367 전투 전환 정보와 전투 지도 서비스의 기존 전환 경계; 전투 진입에서 지도 적 토큰과 전투 참여자 대응 및 인지 관계를 보존하고, 종료에서 그룹을 복원한다. 반례: 서로 다른 적의 인지 관계를 합치거나 잘못 연결된 참여자에게 기습 상태를 적용한다. 검증 사례: 서로 다른 식별자를 가진 적 2명과 플레이어 캐릭터 2명의 혼합 인지 상태로 전환해, 각 적의 인지 관계가 대응하는 전투 참여자에게만 적용되고 미인지 개체별 첫 차례 기습이 보존되는지 확인한다. 캐릭터별 이동량과 경로 각 칸의 지형·벽·문·발견·공간 요소 검증, 전투 종료 뒤 전열 캐릭터 현재 칸으로 그룹 토큰 복원도 확인한다.
- `ui ~ entity` E2E: 해당 없음 — 이 계획의 경계는 저비용 정책·단위·통합 검사로 확인하며, 실제 에이전트 포함 경로는 #369에서 한 번 검증한다.
