## 상태

Planned

## 의존성

#373

## 구현 목적

주문 기본 효과 이후 허용된 환경 작업으로 응용하고 실패해도 기본 효과와 비용을 반복하지 않는다.

## 범위

- 계획 식별자: plan-374.
- 환경 응용은 사용자가 선택한 주문의 기본 효과와 비용을 확정한 뒤 처리하며, GM은 환경 결과만 판정한다.
- 해당 제품·구조 명세의 이 수용 기준에 직접 필요한 기존 화면, API, 정책, 저장소 경계만 수정한다.

## 수용 기준

- 요구사항 추적: AC-23, AC-24, AC-25, AC-26, BR-23, BR-24, BR-25, BR-26, BR-27, BR-28, EX-12, EX-13, EX-14, UC-004.
- 소유 경계: 기존 환경 작업 연결 경계와 주문 실행 상태; 시행 지점: 기본 효과·비용 이후에만 허용 작업을 수행하고 실패 시 기본 효과를 반복하지 않음.
- 주문 기본 효과·비용이 확정된 뒤에만 등록된 환경 작업 목록과 입력 제약을 GM에 제공한다.
- 목록에 있는 작업만 호출하고 판정은 기존 주사위 제출 흐름을 사용한다.
- 작업 오류는 GM에게 보정 가능한 구조로 반환하며 기본 효과 재실행과 추가 비용 차감을 금지한다.
- 제안·결과가 숨겨진 정보를 드러내지 않는다.
- 금지 사례: 환경 작업 실패 뒤 주문 기본 효과를 다시 실행하거나 숨겨진 정보를 응답에 노출한다.

## 테스트 계약

- 개발용 진단 검증 (Architecture Spec §9.1·INV-01): 이 계획이 바꾸는 각 시작·완료·대체 경로·재시도·실패 분기에서 기존 `DevelopmentDiagnostics`(개발 진단 기능)와 `dev_` 개발 로그 형식을 확인한다. `ADVENTURE_RUNTIME_DIAGNOSTICS_ENABLED`(개발용 상세 진단 로그 설정)가 꺼졌을 때 상세 로그가 없고, 켜졌을 때 식별자·입력 크기/개수·기대/실제 값·선택 분기·소요 시간·실패 종류와 다음 복구 동작이 드러나며, 프롬프트·응답·인증 정보·불필요한 플레이어 입력·비공개 지도 정보를 기록하지 않고 실제 동작도 바꾸지 않는지 검사한다.

- 단위/정책: 작업 허용 목록, 입력 제약, 실패 재시도, 기본 효과/비용 중복 방지. 요구사항 식별자: AC-23, AC-24, AC-25, AC-26, BR-23, BR-24, BR-25, BR-26, BR-27, BR-28, EX-12, EX-13, EX-14, UC-004. 소유 경계와 실행 진입점: 기존 환경 작업 연결 경계와 주문 실행 상태; 기본 효과·비용 이후에만 허용 작업을 수행하고 실패 시 기본 효과를 반복하지 않음. 추적 수용 조건: 주문 기본 효과·비용이 확정된 뒤에만 등록된 환경 작업 목록과 입력 제약을 GM에 제공한다. 반례: 환경 작업 실패 뒤 주문 기본 효과를 다시 실행하거나 숨겨진 정보를 응답에 노출한다. 검증 사례: 단위/정책: 작업 허용 목록, 입력 제약, 실패 재시도, 기본 효과/비용 중복 방지.
- `ui ~ entity` E2E: 해당 없음 — 이 계획의 경계는 저비용 정책·단위·통합 검사로 확인하며, 실제 에이전트 포함 경로는 #369에서 한 번 검증한다.
