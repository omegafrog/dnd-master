## 상태

Planned

## 의존성

#364, #371

## 구현 목적

지도에서 조준을 확인한 능력을 최신 전투·지도·캐릭터 상태로 재검증한 뒤 실행한다.

## 범위

- 계획 식별자: plan-372.
- 사용자가 행동과 비용·효과 선택을 확정한 요청만 실행한다. GM 판정 대체는 선택을 대신하지 않고 효과 해결만 맡는다.
- 해당 제품·구조 명세의 이 수용 기준에 직접 필요한 기존 화면, API, 정책, 저장소 경계만 수정한다.

## 수용 기준

- 요구사항 추적: AC-11, AC-15, AC-16, AC-38, AC-43, AC-45, AC-20, BR-14, BR-15, BR-17, BR-46, BR-47, EX-04, EX-07, G-04, G-05, ST-002, UC-002.
- 소유 경계: 전투 행동 처리 서비스(CombatActionApplicationService)와 기존 상태 소유 경계; 시행 지점: 최신 턴·지도·시트 상태·정의 버전을 재검증하고 효과와 비용을 한 번 확정.
- 지도에서 사용자가 확정한 주문·기술의 대상·선택·범위를 서버가 최신 상태로 재검증한다. 자연어 이동·주문·공격·투척 경로는 #375에서 이 지도 확정 경로와 비교한다.
- 사용자가 행동을 확정한 뒤 GM 판정 결과와 자원 변화를 런타임이 한 번 반영하며, 결과 반영마다 추가 승인을 요구하지 않는다.
- 행동 결과와 비용이 반영된 뒤에도 플레이어 차례는 자동 종료되지 않는다. 차례는 Solo Player가 턴 종료를 명시적으로 선택할 때만 끝난다.
- #363에서 준비한 선택 능력을 사용자가 확정하면 GM 판정 결과와 비용이 한 번 저장되고 추가 승인을 요구하지 않는지 통합 확인한다. 중요한 대화 선택의 결과 반영 경계는 #392에서 확인한다.
- 행동·사거리·대상·자원·집중·지속·발동·높은 등급 선택 등 정의된 규칙을 처리한다.
- 확정된 사용 비용은 효과가 없더라도 한 번만 차감하고 중복 요청은 상태 변경을 반복하지 않는다.
- 엔진이 효과를 처리하지 못하면 GM이 효과 해결 전체를 대신하되 비용 기록은 엔진이 보장한다.
- 금지 사례: 오래된 상태 또는 중복 요청에서도 자원을 다시 소모하거나 최신 상태 검증을 생략한다.

## 테스트 계약

- 개발용 진단 검증 (Architecture Spec §9.1·INV-01): 이 계획이 바꾸는 각 시작·완료·대체 경로·재시도·실패 분기에서 기존 `DevelopmentDiagnostics`(개발 진단 기능)와 `dev_` 개발 로그 형식을 확인한다. `ADVENTURE_RUNTIME_DIAGNOSTICS_ENABLED`(개발용 상세 진단 로그 설정)가 꺼졌을 때 상세 로그가 없고, 켜졌을 때 식별자·입력 크기/개수·기대/실제 값·선택 분기·소요 시간·실패 종류와 다음 복구 동작이 드러나며, 프롬프트·응답·인증 정보·불필요한 플레이어 입력·비공개 지도 정보를 기록하지 않고 실제 동작도 바꾸지 않는지 검사한다.

- 단위/정책: 최신 상태 재검증, 엔진 지원/GM 대체, 비용 멱등성, 효과 선택. 차례 유지 검증: 행동 결과와 비용을 반영한 뒤 입력 대기 상태가 유지되고, 명시적인 턴 종료 입력에서만 차례가 끝나는지 확인한다. 교차 흐름 검증: #363에서 준비한 선택 능력을 사용자가 확정하면 GM 판정 결과와 비용이 한 번 저장되고 추가 승인을 요구하지 않는지 통합 확인한다. 중요한 대화 선택의 결과 반영 경계는 #392에서 확인한다. 요구사항 식별자: AC-11, AC-15, AC-16, AC-38, AC-43, AC-45, AC-20, BR-14, BR-15, BR-17, BR-46, BR-47, EX-04, EX-07, G-04, G-05, ST-002, UC-002. 소유 경계와 실행 진입점: 전투 행동 처리 서비스(CombatActionApplicationService)와 기존 상태 소유 경계; 최신 턴·지도·시트 상태·정의 버전을 재검증하고 효과와 비용을 한 번 확정. 추적 수용 조건: 지도에서 사용자가 확정한 주문·기술의 대상·선택·범위를 서버가 최신 상태로 재검증한다. 반례: 오래된 상태 또는 중복 요청에서도 자원을 다시 소모하거나 최신 상태 검증을 생략한다. 검증 사례: 단위/정책: 최신 상태 재검증, 엔진 지원/GM 대체, 비용 멱등성, 효과 선택. 차례 유지 검증: 행동 결과와 비용을 반영한 뒤 입력 대기 상태가 유지되고, 명시적인 턴 종료 입력에서만 차례가 끝나는지 확인한다.
- `ui ~ entity` E2E: 해당 없음 — 이 계획의 경계는 저비용 정책·단위·통합 검사로 확인하며, 실제 에이전트 포함 경로는 #369에서 한 번 검증한다.
