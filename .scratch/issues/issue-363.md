## 상태

Planned

## 의존성

#376

## 구현 목적

모험 시작 시 초기 파티가 이미 가진 능력과, 이후 캐릭터가 새 능력을 배우는 시점에 그 능력만 현재 모험의 자료에서 구조화해 저장하고 MCP로 조회한다.

## 범위

- 계획 식별자: plan-363.
- 파티의 능력은 사용자가 선택·확정한 초기 시트 또는 능력 습득 결과만 준비한다. GM은 선택된 능력의 근거 정보만 조회한다.
- 사용자가 능력을 선택한 뒤에만 해당 능력의 근거 있는 상세정보를 준비하고, 판정·효과·비용은 행동 실행 단계에서 처리한다.
- 모험 시작 시 파티 캐릭터 시트에 이미 등록된 능력 식별자만 확인해 상세 정의가 없는 능력을 준비한다.
- 모험 중 새 능력을 배울 때는 습득 완료 전에 해당 능력만 준비한다.
- 시츄에이션 선택만으로 능력을 훑거나 준비하지 않는다. 전체 룰북·ScenarioPackage의 능력도 일괄 검토하지 않는다.
- 해당 제품·구조 명세의 수용 기준에 직접 필요한 기존 화면, API, 정책, 저장소 경계만 수정한다.

## 수용 기준

- 이미 유효한 `ACTIVE` 정의를 다른 캐릭터가 배울 때는 정의의 상태·내용을 그대로 재사용하고 새 캐릭터의 시트 등록만 완료한다.
- 같은 능력의 준비 요청이 동시에 들어와 저장 상태가 `PREPARING`이면 새 검색·정의·시트 등록을 만들지 않고 기존 준비 작업 하나에 합류한다. `PREPARING` 정의는 조회·사용 응답에 노출하지 않는다.

- 요구사항 추적: AC-01, AC-02, AC-03, AC-04, AC-21, AC-45, AC-27, AC-40, AC-42, BR-01, BR-02, BR-03, BR-04, BR-22, BR-29, BR-33, BR-34, BR-35, BR-36, BR-48, BR-50, EX-01, EX-02, G-01, G-02, ST-001, ST-006, UC-001.
- 소유 경계: 모험별 능력 정의 저장소와 모험별 능력 정의 준비 서비스(AdventureAbilityDefinitionPreparationService); 시행 지점: 모험 시작·능력 습득에서 시트의 실제 능력 ID를 준비하고 MCP 조회 권한·상태를 검증.
- 모험 시작 시 초기 파티 능력과 능력 습득 시점에 한정해, 현재 모험에 저장된 정의가 없는 능력만 RAG 검색한다.
- 기본 룰북과 선택 자료를 독립 검색하고, 고정 스키마와 출처 위치를 검증해 모험 DB에 저장한다.
- 저장된 정의는 같은 모험에서 재사용하고 다른 모험과 공유하지 않는다.
- 복구 실패 시 사용자에게 원문 입력을 요청하고, 취소하면 새 능력 습득을 완료하지 않는다.
- GM MCP 조회는 캐릭터 시트에 실제로 배운 능력 식별자만 허용하고 준비 필요·미습득·조회 오류를 구분한다.
- 캐릭터 시트 등록 뒤 응답이 유실되면 같은 학습 명령 ID로 결과를 확인·재시도하고, 기존 학습 작업을 재개해 능력 정의만 활성화한다. 캐릭터 시트 변경은 한 번만 반영한다.
- 선택 캐릭터 또는 필수 시나리오에 필요한 비활성 규칙 항목이 남으면 STARTED 전환을 차단한다. 복구 완료 뒤 같은 시작 요청을 재개한다. (ST-003)
- 금지 사례: 능력 정의를 전체 룰북에서 미리 일괄 적재하거나 다른 모험과 공유한다.

## 테스트 계약

- 개발용 진단 검증 (Architecture Spec §9.1·INV-01): 이 계획이 바꾸는 각 시작·완료·대체 경로·재시도·실패 분기에서 기존 `DevelopmentDiagnostics`(개발 진단 기능)와 `dev_` 개발 로그 형식을 확인한다. `ADVENTURE_RUNTIME_DIAGNOSTICS_ENABLED`(개발용 상세 진단 로그 설정)가 꺼졌을 때 상세 로그가 없고, 켜졌을 때 식별자·입력 크기/개수·기대/실제 값·선택 분기·소요 시간·실패 종류와 다음 복구 동작이 드러나며, 프롬프트·응답·인증 정보·불필요한 플레이어 입력·비공개 지도 정보를 기록하지 않고 실제 동작도 바꾸지 않는지 검사한다.

- 활성 정의 재사용: 서로 다른 두 캐릭터가 같은 능력을 배우면 정의 본문·버전·출처와 `ACTIVE` 상태가 유지되고, 두 번째 캐릭터의 시트 등록만 한 번 수행되는지 확인한다.
- 준비 동시성·비노출: 같은 모험·능력의 동시 학습 요청이 하나의 `PREPARING` 작업·정의·시트 명령을 공유하고, 진행 중 정의가 MCP 조회와 능력 사용에 나타나지 않는지 확인한다.
- 활성화 경계 장애: 시트 등록 확인 직전·직후와 신규 정의 활성화 직전·직후에 실패를 주입하고 재시작한다. 같은 operation/command ID 재개 후 시트 변경은 한 번, 신규 정의는 확인 전 `PREPARING`·확인 후 `ACTIVE`로 한 번만 바뀌며 이미 `ACTIVE`인 정의는 재사용 시 변하지 않는지 확인한다.

- 단위/정책: 정책 테스트: 모험 시작 시 초기 능력만 준비, 능력 습득 시 준비, 같은 모험의 정의 재사용, 자료별 검색, 스키마 검증, 실패 복구와 취소, MCP 조회 범위. 캐릭터 시트 등록 뒤 응답 유실을 주입해 같은 학습 명령 ID로 재개하고, 시트 변경은 한 번이며 정의 활성화까지 완료되는지 확인한다. ST-003 정책·통합: 지도 필요 여부와 무관하게 비활성 필수 항목은 모험 시작을 차단하고, 복구 뒤 같은 시작 요청이 한 번만 완료된다. 요구사항 식별자: AC-01, AC-02, AC-03, AC-04, AC-21, AC-45, AC-45, AC-27, AC-40, AC-42, BR-01, BR-02, BR-03, BR-04, BR-22, BR-29, BR-33, BR-34, BR-35, BR-36, BR-48, BR-50, EX-01, EX-02, G-01, G-02, ST-001, ST-006, UC-001. 소유 경계와 실행 진입점: 모험별 능력 정의 저장소와 모험별 능력 정의 준비 서비스(AdventureAbilityDefinitionPreparationService); 모험 시작·능력 습득에서 시트의 실제 능력 ID를 준비하고 MCP 조회 권한·상태를 검증. 추적 수용 조건: 모험 시작 시 초기 파티 능력과 능력 습득 시점에 한정해, 현재 모험에 저장된 정의가 없는 능력만 RAG 검색한다. 반례: 능력 정의를 전체 룰북에서 미리 일괄 적재하거나 다른 모험과 공유한다. 검증 사례: 정책 테스트: 모험 시작 시 초기 능력만 준비, 능력 습득 시 준비, 같은 모험의 정의 재사용, 자료별 검색, 스키마 검증, 실패 복구와 취소, MCP 조회 범위. 캐릭터 시트 등록 뒤 응답 유실을 주입해 같은 학습 명령 ID로 재개하고, 시트 변경은 한 번이며 정의 활성화까지 완료되는지 확인한다.
- `ui ~ entity` E2E: 해당 없음 — 이 계획의 경계는 저비용 정책·단위·통합 검사로 확인하며, 실제 에이전트 포함 경로는 #369에서 한 번 검증한다.
