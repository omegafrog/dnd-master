# 실제 브라우저 E2E 실행

## 도구 선택

- 이 저장소의 수동 모험 E2E에서는 **headed Chromium**을 사용한다. CUA Driver와 `@playwright/test`를 사용하지 않는다.
- Playwright CLI는 화면을 여는 도구로 쓴다. 에이전트 응답에 의존하는 단계는 미리 짠 흐름이나 고정 응답으로 실행하지 않는다. 실제 화면을 캡처해 읽고, 다음 행동을 하나씩 정한다.
- Playwright CLI 위치: `/home/jiwoo/.codex/skills/playwright/scripts/playwright_cli.sh`. 먼저 `command -v npx`로 실행 요건을 확인한다.
- 실제 GM 응답은 앱의 연결된 사용자 PC 에이전트에서 받아야 한다. 직접 API 호출, 응답 대체, 모의 응답을 쓰지 않는다.

## 브라우저와 서버 보존

- 시작 전 현재 체크아웃, 프런트엔드·백엔드 URL, 실행 프로세스의 작업 디렉터리를 확인한다. 현재 체크아웃에서 서버가 이미 실행 중이면 그대로 쓴다.
- 사용자가 브라우저나 서버를 열어두라고 했거나 오류가 나면 브라우저 세션 종료, Chromium 종료, 서버 종료, `Ctrl+C`, 재시작을 하지 않는다.
- 연결 또는 응답 오류가 나면 마지막 화면과 오류를 기록한 뒤 해당 E2E를 멈춘다. 요청을 재전송하지 않고 사용자에게 보고한다.
- 기존 모험·자료·데이터베이스를 초기화하거나 지우지 않는다. 테스트용 모험에 만든 데이터는 구분해 기록한다.

## 화면 조작

1. 기존 Chromium 세션이 있으면 재사용한다. 새 브라우저가 필요하면 headed Chromium으로 `http://127.0.0.1:5173/`을 연다.
2. DOM 스냅샷에 앱의 일부만 보이거나 로그인 화면이 없다고 나오면 앱이 비었다고 결론 내리지 않는다. 브라우저 스크린샷을 보고 실제 화면을 확인한다. 로그인 폼이 화면에 보이면 그 폼으로 진행한다.
3. 에이전트 응답이 없는 입력·자료 선택·지도 자르기·격자 조정은 최근 스냅샷의 대상과 화면 좌표를 확인한 뒤 Playwright CLI로 한 단계씩 조작한다. 중요한 저장 전후에 스크린샷을 보고 결과를 확인한다.
4. 에이전트 응답을 요청하기 전 현재 화면을 캡처한다. 요청은 한 번만 보낸다. 대기 중에는 10초 간격으로 같은 화면을 읽고, 최대 300초 안에 응답이나 명시적 실패가 나오는지 확인한다. 대기 중 재클릭·재제출·새 모험 생성은 금지한다.
5. 실제 응답이 나타나면 응답과 바뀐 UI를 캡처해 확인한다. 다음 행동은 그 화면에서 확인한 정보만 사용한다. 5xx, 연결 오류 또는 실패 메시지가 나타나면 중단하고 사용자에게 묻는다.
6. 사용자 요청이 없으면 데이터가 실제로 저장됐는지 확인하기 전에 같은 행동을 다시 제출하지 않는다.

## 지도 격자 조정

1. 지도 파일이 기존 파일과 같으면 사용자에게 저장된 격자 재사용 또는 직접 조정 중 무엇을 할지 묻고, 답변 전에는 저장하지 않는다.
2. 직접 조정을 선택하면 지도 여백 자르기에서 지도 인쇄 격자 영역을 화면으로 확인해 자른 뒤 적용한다.
3. 격자 맞추기에서는 원점 핸들과 겹치지 않는 내부 격자 교차점 두 곳을 고른다. 두 지점은 대각선으로 정확히 3칸 떨어져야 한다. 첫 지점을 선택한 뒤 화면 상태를 확인하고 두 번째를 선택한다.
4. 계산된 한 칸 크기를 적용하기 전에 화면의 격자선을 지도 인쇄 격자선과 대조한다. 격자 열·행 수도 인쇄된 격자 칸 수와 맞춘다. 원점 핸들을 지도 격자 왼쪽 위 모서리로 옮긴 뒤 전체 격자 범위를 확인하고 저장한다.
5. 격자가 화면에서 맞지 않거나 전체 영역을 덮지 못하면 저장하지 말고, 화면과 상태를 기록해 멈춘다.

## 증거와 정리

- 스크린샷, 스냅샷, 콘솔 기록, 실행 보고서는 Harness 세션의 `runtime/e2e/` 아래에 둔다. 인증 정보와 플레이어 입력 원문은 보고서에 남기지 않는다.
- 실행 전 artifact manifest와 대조해 이번에 생성된 항목만 정리한다. 사용자의 기존 미추적·무시 파일은 삭제하지 않는다.
- 결과 보고에는 실제 화면 단계, 모험·세션 식별자, 저장 결과, agent 응답의 성공 또는 실패, 서버·브라우저가 계속 실행 중인지 기록한다. 브라우저 준비만 된 것은 E2E 통과가 아니다.
