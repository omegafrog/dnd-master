# 전투·이동·주문 거리 수동 E2E

에이전트 응답에 따라 다음 화면과 진행이 달라지는 흐름은 실제 앱과 연결된 에이전트로 확인한다. CUA Driver는 사용하지 않는다. 응답이 없는 화면 준비는 headed Chromium의 Playwright CLI로 한 단계씩 조작할 수 있다. 응답이 필요한 단계에서는 요청 전후 화면을 캡처해 실제 결과를 읽고 다음 행동을 정한다. Playwright 테스트 코드, 고정 응답, 직접 API 호출, 미리 정한 화면 순서를 사용하지 않는다.

실행 전 [저장소 E2E 실행 절차](../../agents/EXEC.md), [브라우저 실행·연결 절차](../../agents/BROWSER.md), 그리고 아래 개별 테스트 Markdown을 읽는다. 서버·인프라는 `docs/agents/execution.json`의 프로필을 `harness-exec`로 시작한다. 테스트 로그·화면 증거는 Harness 세션 디렉터리의 `runtime/e2e/`에 둔다.

## 안전한 진행 규칙

- 기존 데이터베이스를 초기화하지 않는다.
- 룰북은 이미 추출된 `DnD_BasicRules_2018.pdf` 자료를 재사용한다. 시나리오 자료는 `~/workspace/dnd-master/docs/assets/`의 원본 세 파일을 아래 순서와 역할로 자료 설정 화면에 넣는다.
  1. `892902-A_Most_Potent_Brew.pdf` — **메인 시나리오** (`MAIN_SCENARIO`)
  2. `892902-A_Most_Potent_Brew_Player_Handout.pdf` — **핸드아웃** (`HANDOUT`)
  3. `892902-A_Potent_Brew_Map.pdf` — **지도** (`MAP`)
- 자료별 파일명과 역할이 화면에 맞게 표시되는지 확인한 뒤 세 자료를 준비하고 시나리오를 생성한다. 준비 완료 후 생성된 시나리오 자료에 사용 가능한 지도 정의가 하나 이상 있는지 확인한다. 지도가 없으면 모험을 시작하지 말고 자료 준비 결과와 실패 증거를 남긴다.
- 원본 시나리오 PDF의 재추출은 이 테스트를 위한 새 자료 묶음을 만들 때만 수행한다. 기존 룰북 추출을 다시 실행하지 않는다.
- 모험 준비에서 지도 파일이 기존 파일과 같으면 먼저 사용자에게 저장된 격자를 재사용할지 직접 고칠지 묻고, 답변 전에는 격자 값을 바꾸거나 저장하지 않는다. 직접 조정을 답하면 지도 인쇄 영역을 화면으로 확인해 자르고, 내부 교차점 두 곳으로 3×3칸 크기를 맞춘 뒤 원점을 지도 격자 왼쪽 위에 옮겨 저장한다.
- 지도 격자 조정은 모험 시작 전 준비 화면에서 한다. 모험을 시작한 뒤 지도를 고치는 경로는 실행하지 않는다.
- 사용자가 격자 입력을 이어서 하기로 했으면 격자 준비 화면에서 멈춘다. 적용과 모험 시작을 누르지 않고 브라우저를 열어 둔다.
- 에이전트 요청이 대기 중이면 같은 화면을 10초 간격으로 관찰한다. 5xx, 연결 오류 또는 명시적 실패가 나오면 다시 보내지 말고 중단해 사용자에게 보고한다. 브라우저와 서버는 요청이 없는 한 종료하지 않는다.
- 저장 여부를 확인하기 전에 변경 요청을 반복하지 않는다. 로그인 화면이 보이지 않는 불완전한 접근성 스냅샷만으로 로그인 페이지가 없다고 판단하지 말고 Chromium 스크린샷을 확인한다.
