# 모험 준비에서 지도 격자 화면까지 이동하고 사용자에게 인계

## 목적

DB를 비운 뒤 지정된 룰북과 Potent Brew 원본 파일을 새로 올려 시나리오 자료를 준비하고, 모험 시작 전 지도 격자 편집기를 연다. 격자 편집기가 표시되면 조정·저장하지 않고 사용자에게 넘긴다. 사용자가 격자를 맞춘 뒤 다음 진행을 요청하면 E2E를 재개한다.

## 준비

1. 저장소 루트와 `node .codex/scripts/harness-workspace-preflight.mjs --expected-root <저장소 루트> --json` 결과를 확인한다.
2. `docs/agents/EXEC.md`와 `docs/agents/execution.json`에서 서버 프로필과 준비 조건을 확인한다. 필요한 서버가 이미 실행 중이면 그 실행이 현재 체크아웃 소유인지 확인하고 재사용한다. 기존 데이터베이스를 초기화하는 것은 이번에 명시적으로 승인된 경우에만 한다.
3. Harness 세션 디렉터리를 `node .codex/scripts/harness-session-output.mjs --root <저장소 루트>`로 얻는다. 이번 실행만의 새 경로에 artifact manifest를 만들고 snapshot한다. 오래된 manifest로 cleanup하지 않는다.
4. `docs/agents/BROWSER.md`에 따라 headed Chromium을 열고, 스크린샷에서 실제 D&D Master 앱인지 확인한다. CUA Driver는 사용하지 않는다.
5. 로컬 개발 계정으로 로그인한다. 2018년 D&D 기본 룰북과 공통 E2E 안내에 적힌 세 시나리오 PDF를 파일명 순서대로 업로드하고 각각 메인 시나리오, 핸드아웃, 지도 역할을 지정한다.

## 실행

1. 앱의 자료 설정에서 세 PDF의 파일명과 역할이 공통 E2E 안내의 지정과 일치하는지 확인하고 자료 준비 및 시나리오 생성을 마친다. 새 시나리오 자료 묶음과 캐릭터·파티를 사용해 모험 준비로 진입한다.
2. 모험 준비 자료에 사용 가능한 지도 정의가 하나 이상 있고, 표시된 지도 자료가 `892902-A_Potent_Brew_Map.pdf`에서 온 것인지 확인한다. 지도 정의가 없거나 다른 파일이면 모험을 시작하지 말고 `inconclusive`로 기록한다.
3. 지도 준비 흐름을 진행해 격자 편집기를 연다. 화면과 지도 원본이 맞는지 확인한 뒤 편집기 상태를 캡처하고 멈춘다. 격자를 조정·저장하거나 모험을 시작하지 않는다.

## 통과 조건과 중단 조건

통과 조건은 새 룰북과 세 파일의 역할, 지도 자료, 모험 준비 내용이 확인되고 지도 격자 편집기가 열린 상태까지 도달하는 것이다. 사용자가 격자 조정 후 다음 진행을 요청할 때까지 아무 편집도 저장하지 않고 브라우저를 열린 채 둔다.

같은 지도 여부를 화면에서 확인할 수 없거나 저장된 지도·격자를 불러오지 못하면 임의로 새 파일을 만들지 말고 화면과 로그 증거를 남겨 `inconclusive`로 보고한다. 저장 요청의 오류·시간 초과·저장 상태 불일치가 있으면 재전송하지 말고 중단해 사용자에게 묻는다.

## 증거

Harness 세션의 `runtime/e2e/` 아래에 실행 명령과 프로필·receipt, 체크아웃 및 revision, 화면 URL, 사용 자료 식별 정보, 격자 화면 캡처, 관련 실패 로그, 브라우저·서버 유지 여부를 기록한다. 화면 캡처와 로그에는 비밀 값이나 불필요한 플레이어 입력을 포함하지 않는다.
