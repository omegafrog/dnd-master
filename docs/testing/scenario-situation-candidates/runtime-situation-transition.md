# 이야기 길이와 필수 상황 그래프 진행 실제 화면 확인

## 목적

실제 준비 화면에서 짧게·보통·길게 중 이야기 길이를 고르고, 정확한 상황 개수를 노출하지 않은 채 세션과 모험 진행에 보존되는지 확인한다. 실제 게임 마스터 응답에 따라 같은 단계의 자연스러운 선택 상황을 먼저 진행하거나, 조건을 만족하는 필수 상황으로 이동하고, 명시적 결말 상황 하나가 끝나면 모험이 완료되는지 확인한다.

## 준비

- [저장소 E2E 실행 절차](../../agents/EXEC.md), [브라우저 연결·복구 절차](../../agents/BROWSER.md), [ADR-024](../../adr/ADR-024-agent-driven-runtime-e2e.md)을 읽는다.
- 기존에 추출한 모험 자료와 룰북 자료를 재사용한다. PDF 재업로드, 재추출, 데이터베이스 초기화, 기존 모험 삭제는 하지 않는다.
- 새 검증 모험을 만들고 기존 모험은 수정하지 않는다. 실행 증거와 화면 캡처는 Harness 세션의 `runtime/e2e/<run_id>/`에 둔다.
- headed Chromium을 사용하고 CUA Driver를 쓰지 않는다. 실제 게임 마스터 요청을 자동 생성하거나 고정 응답으로 바꾸지 않는다. 요청 전후에 화면을 캡처하고 실제 응답을 읽은 뒤 다음 행동을 정한다.

## 절차

1. 현재 worktree의 서버와 브라우저를 확인한다. 열린 브라우저를 재사용하고 닫지 않는다. 시작한 서비스·브라우저는 소유 PID와 URL을 기록한다.
2. 로그인 후 기존 자료로 새 모험 준비를 진행한다. 같은 지도 파일의 저장 격자가 있으면 앞선 사용자 선택에 따라 직접 조정 흐름을 사용한다. 자료 추출 화면이 다시 열리면 중단하고 현재 상태를 확인한다.
3. 생성된 준비 상황을 확인한다. 필수 상황 사이의 연결에 중간 후보가 필요한 경우 구체적인 사건 후보가 준비됐는지 확인한다. 후보가 필요하지 않은 연결에서 0개 또는 1개라는 이유만으로 실패 처리하지 않는다. 이어 준비 화면에서 짧게·보통·길게 중 하나를 고른다. 선택 상황의 정확한 개수가 화면에 나타나지 않는지 확인한다. 준비 요청과 화면에서 같은 선택값이 사용되는지 확인한다.
4. 준비를 완료하고 새 모험을 시작한다. UI나 세션 상태가 `STARTING` 또는 `준비 중`이면 동일 요청을 다시 보내거나 다른 모험을 만들지 않는다. 같은 세션을 10초 간격으로 최대 2분 관찰한다. 계속 대기하면 세션 ID·화면·진단 기록을 남기고 중단한다. 시작 완료 후 현재 장면이 준비 자료와 맞는지 확인한다.
5. 실제 후보 문맥과 응답을 읽으며 자연스럽게 플레이한다. 현재 상황이 끝나지 않았으면 같은 상황을 이어간다. 끝났다면 먼저 같은 단계의 자연스러운 선택 상황이 있고 허용량이 남아 있는지 확인한다. 이 경우 해당 후보가 제안·선택되는지 보고, 턴 확정 뒤 완료 수가 한 번만 늘었는지 확인한다.
6. 자연스러운 선택 상황이 없거나 허용량이 소진되면 전체 필수 상황 그래프를 확인한다. 아직 사용되지 않았고 모든 명시 선행 상황이 사용된 필수 상황만 적격이다. 다른 단계의 적격 상황도 제안 가능한지 확인한다. 후보가 없고 끝 상황이 아직 완료되지 않았으면 새 상황 생성 없이 상태 변경 없는 거부가 나와야 한다.
7. 적격한 명시 결말 상황에 실제 플레이로 도달하면, 해당 상황 종료가 필요한 검증·굴림을 모두 마친 뒤 기존 턴 확정에서 상황 사용 상태와 모험 완료가 함께 저장되는지 확인한다. 다른 결말 갈래는 방문하지 않는다. 끝 표식이 없는 막다른 상황을 결말로 간주하지 않는지 확인한다.
8. 각 턴에서 확정 전에는 상황 사용·선택 상황 완료 수·결말 완료가 저장되지 않고, 확정 후에는 한 번만 반영되는지 확인한다. 화면·저장 상태·진단 로그가 일치하는지 확인한다.

## 중단 조건

턴 오류, 5xx, 연결 실패, 저장 상태 불일치 또는 예상 밖의 후보 구조가 나타나면 요청을 다시 보내지 않는다. 화면·요청 식별자·서버 증거를 남기고 중단해 사용자에게 묻는다. 원인을 고치고 사용자가 재검증을 승인한 경우에만 증거에 근거해 한 번 재시도한다. 같은 시나리오의 총 시도는 두 번을 넘기지 않는다. 기존 브라우저나 서버를 종료·재시작하지 않는다.

## 성공 조건

- 이야기 길이 선택 세 단계만 화면에 보이고 정확한 상황 개수는 숨겨지며, 선택값이 세션·모험 상태에 보존된다.
- 이야기 연결에 후보가 필요한 곳에는 구체 후보가 준비되고, 불필요한 곳의 0/1개는 실패가 아닌지 확인한다. 실제 AI 응답과 화면에서 자연스러운 선택 상황 우선, 허용량 경계, 전체 그래프 필수 상황 적격성 및 후보 부재 거부를 확인한다.
- 선택 상황 사용량은 종료된 선택 상황마다 기존 턴 확정에서 정확히 한 번 증가한다.
- 명시적 결말 상황 하나의 종료가 검증·굴림 및 기존 턴 확정을 거쳐 완료되며, 다른 끝 갈래 방문을 요구하지 않는다.
- 새 상황 생성이 그래프나 길이 허용량을 우회하지 않고, 화면·저장 상태·진단 로그가 일치한다.

실제 상황 그래프에 해당 분기나 적격 결말이 없으면 인위적으로 데이터를 바꾸거나 순서를 주입하지 않는다. 관찰한 분기만 통과로 기록하고 미검증 경로와 이유를 분리해 보고한다.

## 종료와 증거

사용자가 요청한 경우 브라우저와 모든 서버 프로세스를 계속 실행한다. 실패 시 서비스를 종료·재시작하지 말고 증거를 보존한다. 이번 실행에서 새로 만든 테스트 산출물만 정리한다.

결과에 worktree·HEAD·실행 profile·receipt·사용 자료·브라우저와 서비스 PID·선택한 길이(정확한 허용량은 제외)·실제 진행 분기·화면 및 저장 상태 증거·각 실패 이력·프로세스 유지 여부·artifact cleanup을 기록한다.
