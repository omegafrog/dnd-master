이 자료는 특정 책의 모든 페이지를 통과시키는 데 사용하지 않는다. 서로 다른 출판물에서 구조 보존과 검토 판정의 정확도를 함께 확인하고, 새 문서의 오류를 근거로 고친 경우에는 그 문서를 더 이상 독립 검증 자료로 취급하지 않는다.

첫 평가에서 Cairn의 표 셀 사이에 전처리기가 넣은 세로 막대 구분자를 원문 변형으로 세는 평가기 오탐을 발견했다. 평가기는 표 셀의 원문 조각 순서를 그대로 보존하는지 확인하고, 표를 출력할 때 추가되는 셀 구분자와 빈 셀 표시만 허용하도록 수정했다. 실제 셀 글자가 바뀌는 경우를 잡는 회귀 테스트도 추가했다. 수정한 평가기로 세 자료를 다시 평가한 결과 모두 원문 출처 추적률 100%, 원문 변형 0건이었다.

이 수치는 청크가 출처 글자를 보존했는지에 대한 결과다. 제목 연결, 열 구분, 표의 행·열 정확도, 읽기 순서가 원본과 일치하는지를 측정한 결과는 아니다. `preprocess.py`의 성공 여부나 검토 이슈 개수만으로 구조 정확도를 주장하지 않는다. 특히 Cairn 두 권은 청크 경계 경고가 많아 구조 품질을 원본과 대조해야 한다.

## 정확도를 확인하는 채택 절차

1. PDF 전체 단위로 자료 역할을 정한다. 같은 책의 일부 페이지를 개발에 쓰고 다른 페이지를 독립 검증에 쓰지 않는다.
2. 개선을 시작하기 전에 검증 페이지의 원본 구조를 사람이 확인해 정답을 기록한다. 최소한 페이지 유형, 제목과 상위 제목 관계, 본문 블록 읽기 순서, 표 영역과 행·열, 양식 여부를 표시한다. 확실하지 않은 구조는 불확실하다고 기록한다.
3. 후보 변경은 개발 자료에서만 조정한다. 제목 글꼴 크기, 문구, 페이지 번호 같은 특정 책 고정 조건을 추가하지 않는다.
4. 후보 코드를 고정한 다음 교차 검증 자료 전체를 같은 설정으로 처리한다. 페이지 통과율뿐 아니라 제목 연결 정확도, 읽기 순서 일치율, 표 영역·셀 정확도, 양식 오분류, 출처 누락·중복, 청크 경계 품질을 정답 자료와 비교한다.
5. 구조별 정답과 비교할 수 없는 지표는 “미측정”으로 남긴다. 한 구조의 개선이 다른 구조를 손상시키면 기본 전처리기에 통합하지 않는다.
6. 교차 검증 자료의 특정 오류를 보고 알고리즘을 다시 조정하면 그 자료는 개발 자료로 옮긴다. 개선을 최종 확인할 새 출판물 자료를 먼저 추가하고 원본 구조를 표시한 뒤 평가한다.

현재 저장소 평가기는 출처 추적, 청크 크기, 중복, 일부 청크 경계 문제를 측정하고, 별도 구조 채점기는 사람이 만든 페이지 정답과 구조 예측을 비교할 수 있다. 다만 문서별 개발·평가 역할을 강제하는 실행기와 실제 구조 정답은 아직 없다. 지금까지의 새 문서 실행만으로 전처리기의 범용성이나 구조 정확도가 확인됐다고 볼 수 없다.

## 구조 정답 평가

일반 전처리 실행은 페이지별 결과와 문서 제목 관계를 `document_structure.json`에 기록한다. 추출 버전에서 나온 `version.json`도 같은 평가기에 입력할 수 있다. 입력 파일의 SHA-256과 페이지 번호로 PDF 판본을 확인하며, 일반 실행의 실제 PDF 해시는 manifest의 `source_file_sha256`에 따로 기록한다. `document_structure.json`의 `source_sha256`는 전처리 문서의 해시다.

사람이 원본 PDF를 확인해 만든 페이지별 JSONL 정답은 `schemas/preprocessing_structure_gold.schema.json` 형식을 따른다. 블록은 전처리 블록 ID를 정답으로 복사하지 않고 문구와 PDF 좌표로 표시한다. 페이지 유형, 블록, 읽기 순서, 제목의 단계와 상위 제목, 본문 영역·열 경계, 표 영역과 행·열을 필요한 범위만 기록한다. 확실하지 않은 항목은 임의로 채우지 않고 해당 평가 항목을 생략한다. 표의 빈 셀은 빈 문자열로 적어 위치를 보존한다.

평가 명령은 다음과 같다.

```bash
.venv/bin/python scripts/evaluate_preprocessing_structure.py \
  --version /path/to/run/document_structure.json \
  --annotations /path/to/structure-gold.jsonl \
  --output /path/to/structure-evaluation.json
```

현재 채점 결과는 페이지 유형 정확도, 블록 정밀도·재현율, 제목 탐지·단계·상위 관계, 읽기 순서 쌍별 일치율과 주석 블록 포괄률, 열 개수와 경계 겹침, 표 탐지와 셀 내용 일치율을 각각 보고한다. 영역 상자 대응에는 교차 면적 비율 0.5 기준을 쓴다. 문서 제목 관계가 입력에 없으면 제목 상위 관계 정확도는 `null`로 남긴다. 정답을 만들지 않은 항목도 `null`이며 종합 점수나 자동 통과 기준은 없다.

세 전처리 명령은 종료 코드 0으로 끝났지만 모두 `valid=false`였으므로 게시 가능한 성공으로 해석하지 않는다. 구조 평가는 표본 페이지에 한정한다. 세 문서에서 주석한 경계의 끝점은 모두 추출 결과와 대응했지만, 계층이 미확정이거나 공통 상위 경로만 남아 있어 같은 절·다른 절을 판정한 결과는 없다. 판정 가능한 경계 비율은 0%이며, 제목 단계·상위 관계 정확도도 확정된 계층이 없어 측정되지 않았다. 미확정 표본 2개는 모두 보류 예측을 내어 보류 비율 100%였고, 이를 절 관계 정확도로 계산하지 않았다. 문단 또는 같은 표가 페이지를 넘어 이어지는 사례는 골드에 없어 내용 이어짐 정확도는 미측정이다.

Cairn 표 결과는 영역을 찾는 것과 행·열을 복원하는 것이 별개임을 보여준다. Player’s Guide의 여덟 표는 모두 위치를 찾았지만 각각 5행 중 4행만 출력했다. Warden’s Guide의 26행·8열 표는 비어 있지 않은 26행을 모두 보존했지만, 행 사이에 내용이 없는 행 25개를 추가해 51행으로 만들었다. 따라서 셀 글자 보존이 높아도 격자 구조가 맞다고 볼 수 없다. Basic Roleplaying의 표 재현율 0은 주석한 표 영역과 일치한 표가 없다는 뜻이며, 책 전체에 표가 없다는 뜻은 아니다.

이번 결과는 새 코드의 구조 기준선이다. 모든 자료의 검증 이슈가 남아 있으므로 후속 작업에서는 페이지 통과 수를 성능 점수로 사용하지 않는다. 각 구조의 정밀도·재현율, 판정률, 보류율과 원본 대조를 함께 비교한다.

페이지 경계의 관계는 선택 사항인 `section_continuations`에 기록한다. 두 끝점은 페이지 번호와 해당 페이지의 `block_id`, 또는 표본 밖 문맥을 위한 보이는 문구·좌표를 가진 `anchor`로 지정한다. 각 경계에는 `section_relation`을 `SAME_SECTION`, `DIFFERENT_SECTION`, `UNRESOLVED` 중 하나로 기록하고, 문단·표 자체가 이어지는지는 별도 `content_continuity`에 기록한다. 같은 상위 제목 아래 있다는 사실만으로 같은 세부 절이라고 판단하지 않는다. 경로가 비어 있거나, 두 경로가 공통 상위 제목까지만 확인되거나, 같은 경로 끝에 미확정 하위 제목이 있으면 예측은 `UNRESOLVED`로 둔다. 평가 결과는 끝점 대응률, 관계를 판정한 비율, 판정 가능한 사례의 정확도, 관계별 정밀도·재현율, 미확정 정답에 대한 보류 비율을 나눠 보고한다. 문단·표 이어짐은 현재 자동 예측하지 않으므로 그 정확도는 `null`이다. 관계 라벨이 없는 기존 JSONL은 관계 점수에서 성공으로 간주하지 않고 미확정으로 처리한다.

정답은 원본 PDF를 보고 독립적으로 작성해야 한다. 특히 무작위 페이지와 제목·다단·표·혼합 배치가 있는 페이지를 함께 뽑고, 문서 전체를 개발 자료 또는 평가 자료 중 한 역할로 둔다. 현재 세 자료의 실제 구조 정답은 아직 만들지 않았으므로, 코드 테스트 통과를 문서 구조 정확도로 해석하지 않는다.
