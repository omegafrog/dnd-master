## 차단 원인

정상 런처로 첫 시작 시 백엔드가 다음 오류로 종료했다.

1. `movementPlacementModelPort` 이름의 빈 정의가 `AdventureApiConfiguration`과 `AiGameMasterApiConfiguration`에 중복되어 애플리케이션 시작 실패.
2. 빈 덮어쓰기를 임시 허용해 재시작했으나, PostgreSQL 기존 볼륨의 Flyway 검사값이 현재 코드와 불일치해 다시 실패.
   - 버전 `1.3`: 저장 `-1260669017`, 현재 `831519058`
   - 버전 `2.5`: 저장 `670413886`, 현재 `2141222091`

데이터베이스 복구·초기화는 상태를 바꾸므로 실행하지 않았다. 따라서 이번 결과는 UI의 전체 기능 실패 판정이 아니라, 백엔드 기동 전제 미충족으로 인한 통합 검증 차단 판정이다.

## UI/UX 판정

Terra 중간 추론 서브에이전트가 로그인 캡처를 검토했다.

- 로그인 목적과 입력 순서는 명확하다.
- 왼쪽 소개 문구가 배경 경계와 겹쳐 첫 화면 완성도를 낮춘다.
- `테스트 계정으로 로그인`과 `회원가입`의 시각적 우선순위가 기본 로그인과 비슷하다.
- 개선: 소개 문구 폭·줄바꿈 조정, 테스트 계정은 보조 링크로 낮춤, 회원가입을 별도 안내 문구로 분리, `PLAYER ACCESS`를 한국어로 통일.

## 결론

이번 브라우저 검증은 로그인 화면 표시와 실패 상태 표시까지만 통과했다. 핵심 요청인 모험 시작, 전투, 맵 이동, 전장의 안개, AI 동료 턴, 캐릭터 시트 수정은 백엔드가 기동하지 않아 판정할 수 없다.

다음 검증 전제:

- 백엔드 health 확인 후 같은 UI 시나리오 재실행

## 모험 준비 500 원인 확인 및 수정

재현 로그에서 원인은 `ScenarioBundleApplicationService`가 소유 자료와 공유 룰북을 조회할 때 발생한 `HttpTimeoutException`이었다. 통합 실행 환경의 룰북 목록 조회가 약 2.35초 걸리는데, `CrossContextHttpKnowledgeDocumentLookupGateway` 제한 시간이 2초로 고정되어 500으로 변환되지 않은 예외가 발생했다.

수정:

- 내부 자료 조회 제한 시간을 2초에서 10초로 상향.
- 같은 UI 흐름으로 다시 제출.
- `모험을 준비하고 있습니다` 화면 진입 통과.
- 약 8초 후 `모험 자료 준비가 끝났습니다`와 `캐릭터 설정 계속` 표시 확인.

즉, 이번 실패 원인은 자료 역할이나 선택값이 아니라 내부 조회 제한 시간 부족이었다.

## 재검증: 중계기·Redis 보완 후 실제 플레이 진입

앞선 `모험 시작` 실패는 UI 맵 준비 문제가 아니라 로컬 AI 연결 중계기의 실행 조건 누락이었다.

- 중계기 요청 결과: `DELIVERY_FAILED`
- 확인된 원인: 개발 인프라에 Redis가 없어 중계기의 연결 위치 임대가 `DOWN` 상태
- 수정: `src/infra/compose.yaml`에 Redis 7.4 서비스와 상태 확인 추가
- 수정: `src/start-dev.sh`가 중계기, 사용자 PC 에이전트, 데모 로그인 토큰 연결을 자동 준비하도록 보완
- 검증: Redis 상태 `healthy`, 중계기 `/actuator/health` `UP`, 사용자 PC 에이전트 WebSocket 연결 유지

같은 브라우저 세션에서 맵 준비 완료 후 `맵 준비 완료, 모험 시작`을 다시 눌렀다.

## 최신 UI/UX 판정

Terra 중간 추론 에이전트가 최신 캡처 3장을 직접 검토했다. 다음 개선이 우선이다.

- 지도 열기 상태에서도 전장과 안개가 한 화면에서 대비되도록 본문 영역에 직접 표시할 것.
- `opening` 같은 내부 위치 표현 대신 한국어 장소명과 현재 위치 표식을 지도에 표시할 것.
- 자연어 이동 입력 위에 `계단으로 이동`, `상자 조사`처럼 상황별 선택지 2~3개를 제공할 것.
- 적 발견 시 `전투 시작`을 명확한 단일 버튼으로 제공하고, 전투 시작 뒤에 공격·이동·행동을 노출할 것.
- 행동 뒤 안개 범위와 현재 위치 변화가 시각적으로 바뀌었음을 보여줄 것.

## 현재 결론

이전의 모험 준비 실패와 모험 시작 실패는 각각 조회 시간 제한과 Redis 누락으로 확인·수정했다. 현재 브라우저는 실제 플레이 화면까지 진입하고 전장의 안개를 표시한다. 다만 이번 시나리오 경로에서는 적이 끝까지 노출되지 않아 전투·AI 동료 턴·실제 이동 커밋은 아직 판정할 수 없다.

## 이번 재검증에서 수정한 항목

- 이미 활성화된 맵의 반복 입장 요청을 멱등 처리했다.

## 남은 차단 원인

코드 수정 뒤에도 마지막 UI 행동은 AI 중계기에서 `scenario lookup failed`로 실패했다. 백엔드 로그에는 사용자 PC 에이전트 전달 실패가 확인됐다. 따라서 이번 실행에서는 전투 화면 전환, 실제 공격 판정, AI 동료 차례를 성공으로 보고할 수 없다. 함정과 적 노출까지는 UI로 검증됐고, 전투 이후 판정은 AI 중계기 재연결 상태에서 다시 실행해야 한다.

## 최신 재검증 보정

- `scenario lookup failed`는 수동 백엔드 기동 때 릴레이 주소가 빠진 문제로 재현·확정했다. `AGENT_CONNECTION_RELAY_URL=http://127.0.0.1:8081` 적용 뒤 AI 시나리오 조회와 턴 처리는 성공했다.
- 남은 전투 보류는 룰북 판본 문제였다. 당시 선택된 공개 판본은 몬스터 수치가 없는 4쪽 자료였다. 실제 거대 거미 수치가 있는 `dnd5th.pdf` 판본을 백오피스 UI에서 공개하고 새 Potent Brew 모험을 다시 준비했다.
- 백오피스가 `READY`·비공개 판본을 공개하지 못하던 조건을 수정했다. 카탈로그 응답에 공개 여부를 포함하고 비공개 `READY` 판본에 `공개` 버튼을 표시한다.
- 새 모험 UI 통과 범위: 룰북 선택, Potent Brew 메인 시나리오·지도·핸드아웃 선택, 캐릭터 생성·능력치 배정·저장, 파티 4명, 지도 자르기, 격자 정렬, AI 벽·문 초안 생성·저장, 런타임 시작, 첫 장면·저장고·돌 복도 탐색.
- 이후 브라우저 프로세스가 종료되고 실행 브라우저가 사라져 Chromium 재기동에서 막혔다. 새 판본 기준 전투 화면, 공격 굴림, AI 동료 차례는 아직 미판정이다.
