# 공간 이동 해결 Product Spec

- 범위 ID: `spatial-movement-resolution`
- 문서 상태: **READY** — 요구사항 확정 및 Product 다이어그램 완료
- 대상: 전술 지도가 활성화된 탐험·잠입·추격·전투

## 1. Problem and Context

전술 지도에서 토큰 이동은 단순한 출발지·도착지 변경이 아니다. 이동 중 통과하는 각 칸에서 시야와 탐험 영역이 달라지고, 숨겨진 공간 요소를 발견하거나 발동할 수 있으며, 새로운 적과 조우할 수 있다. 직접 드래그와 자연어 입력이라는 서로 다른 입력 방식도 동일한 확인·해결 규칙을 따라야 한다.

현재 필요한 제품 계약은 다음 문제를 함께 해결해야 한다.

- 확인 전의 이동 의도가 지도 상태를 바꾸지 않아야 한다.
- 이동 경로를 확인할 수 있어야 하지만, 숨겨진 적이나 공간 요소가 경로 계산이나 응답을 통해 드러나지 않아야 한다.
- 확정된 이동은 칸별 순서와 중단 지점을 보존해야 한다.
- 플레이어가 알 수 없는 공간 요소와 내부 판정값이 입력 해석·서술·실패 메시지를 통해 새지 않아야 한다.
- 탐험·잠입·추격·전투에서 같은 공간 규칙을 사용하되, 전투에서는 턴과 이동 가능량을 추가로 지켜야 한다.
- 모험 준비 중 공간 요소 위치를 추측하지 않고, 필수 요소를 배치하지 못한 지도를 활성화하지 않아야 한다.
- 지도 토큰이 진영과 선택·현재 턴·마지막 목격 상태를 명확히 전달해야 한다.

## 2. Goals and Desired Outcomes

- **G-01 — 단일한 확인 흐름:** 직접 드래그와 자연어 입력이 하나의 `목적지 해석 → 경로 미리보기 → 조정 → 확인 → 이동 해결` 흐름으로 수렴한다.
- **G-02 — 칸별 공간 일관성:** 확인된 이동이 통과 칸 순서대로 시야, 탐험 영역, 공간 요소, 적이 이동 중인 플레이어를 알아차리는지를 반영한다.
- **G-03 — 숨겨진 정보 보호:** 플레이어에게 공개되지 않은 공간 요소, 판정 난이도, 내부 성공·실패 결과가 입력 해석과 서술을 통해 노출되지 않는다.
- **G-04 — 안전한 중단과 복구:** 게임 규칙에 따른 중단은 이미 통과한 경로를 보존하고, 시스템·연동 실패는 관련 상태를 이동 전으로 되돌린다.
- **G-05 — 근거 있는 준비:** Adventure Story Plan에 필요한 공간 요소를 정해진 시도 안에서 근거에 따라 배치하며 좌표를 추측하지 않는다.
- **G-06 — 읽기 쉬운 토큰:** 재배포 가능한 일관된 시각 자산으로 진영과 주요 토큰 상태를 구분한다.

## 3. Users and Actors

- **A-01 Solo Player:** 토큰을 직접 드래그하거나 자연어로 이동 의도를 입력하고, 이동 제안을 확인하며, 관찰·상호작용·우회·해제를 선택한다.
- **A-02 AI Game Master:** 자연어 이동의 위치 후보와 준비 단계의 공간 요소 위치를 제안하고, 공개가 확정된 사실만으로 서술한다. 지도 상태를 직접 변경하지 않는다.
- **A-03 Combat Map:** 지형, 토큰, 공간 요소, 시야와 탐험 상태의 정본을 소유하고, 확인된 이동과 검증된 배치만 반영한다.
- **A-04 Adventure Runtime:** 룰북에 따른 판정·행동 비용과 전투·경고·대화·추격 같은 모험 진행 결과를 확정한다.
- **A-05 Scenario Preparation:** Adventure Story Plan과 근거를 사용해 초기 공간 요소 배치 및 제한된 보정 시도를 진행하고 지도 활성화 가능 여부를 결정한다.

## 4. Ubiquitous Language and Terminology

- **전술 지도(Tactical Map):** 탐험, 잠입, 추격, 전투에 사용하는 격자형 플레이 공간.
- **공간 요소:** 전술 지도의 한 칸 이상에 놓이며 이동·시야·발견·상호작용에 반응하는 지도 상태. 이 범위에서는 함정, 비밀문, 위험 지역, 상호작용 대상, 마법 범위 효과를 포함한다.
- **이동 제안:** 직접 드래그로 놓은 목적지 또는 자연어 이동 의도에서 해석한 목적지와, 플레이어에게 알려진 통행 가능 지도 정보만으로 서버가 계산한 경로를 나타내는 미확정 후보. 유령 토큰과 경로로 미리 보며 확인 전에는 정본 상태를 변경하지 않는다.
- **이동 해결:** 확인된 이동 제안을 경로의 칸 순서대로 처리하고 실제 마지막 위치와 공개 가능한 결과를 확정하는 과정.
- **전장의 안개(Fog of War):** 현재 보이는 영역, 과거 탐험 영역, 미탐험 영역을 구분하는 공개 규칙.
- **플레이어가 별도 행동을 선언하지 않아도 적용되는 지각 판정:** 다음 칸에 들어가기 전, 현재 보이고 범위 안이며 시선이 닿는 공간 요소만 대상으로 적용하는 판정.
- **플레이어가 주변을 자세히 살피는 행동:** Solo Player가 별도 행동으로 선언하며, 적용 룰북이 비용과 굴림을 정하는 관찰 행동.
- **Last Seen Token:** 공개된 몬스터가 시야에서 벗어났을 때 룰북이 정한 기간 동안 마지막 목격 칸에 축소 표시되는 기존 토큰 상태.
- **게임 진행 중단:** 공간 요소 발견·발동 또는 적이 이동 중인 플레이어를 새로 알아차린 상황처럼 플레이어 결정이나 Adventure Runtime 처리가 필요해 이동을 멈추는 정상 결과.
- **시스템·연동 실패:** 게임 세계의 결과가 아니라 처리 자체를 신뢰할 수 없게 만드는 실패로, 지도·공간 요소·전장의 안개 변경을 되돌려야 하는 경우.

## 5. Core Use Cases

### UC-01 이동 제안 만들기 및 확인

1. Solo Player가 토큰을 직접 드래그하거나 자연어로 이동 의도를 입력한다.
2. 직접 드래그이면 토큰을 놓은 목적지를 사용하고, 자연어 입력이면 플레이어가 알고 있는 지도 정보만으로 목적지를 해석한다.
3. 자연어 목적지가 모호하면 후보를 임의 선택하지 않고 이동 위치를 질문하거나 토큰 드래그를 안내한다.
4. 서버가 플레이어에게 알려진 통행 가능 지도 정보만으로 목적지까지의 경로를 계산한다. 숨겨진 적과 숨겨진 공간 요소는 경로 계산에 영향을 주지 않으며 응답에도 드러나지 않는다.
5. UI가 목적지의 유령 토큰과 계산된 경로를 표시한다. Solo Player는 목적지나 경로를 조정할 수 있으며, 조정하면 서버가 같은 공개 정보 경계 안에서 경로를 다시 계산한다.
6. 이동 제안은 계산에 사용한 기준 지도 버전을 포함한다. Solo Player가 제안을 확인하기 전에는 위치, 전장의 안개, 공간 요소 상태, 모험 진행을 바꾸지 않는다.
7. 기준 지도 버전이 오래되었으면 확인을 거부하고 현재 지도 상태를 기준으로 경로를 다시 계산해 다시 미리 본 뒤 확인하도록 안내한다.

### UC-02 확인된 이동을 칸별로 해결

1. Solo Player가 현재 기준 지도 버전의 이동 제안을 확인하면 서버가 제안된 경로를 검증하고 칸별 이동 해결을 시작한다.
2. 확인된 경로의 다음 칸에 들어가기 전에 플레이어가 별도 행동을 선언하지 않아도 적용되는 지각 판정의 대상을 평가한다.
3. 통과가 확정된 각 칸에서 토큰 위치와 시야·탐험 영역을 갱신한다.
4. 플레이어가 볼 수 있는 이동은 통과한 칸을 따라 애니메이션하고 전장의 안개를 순서대로 공개한다.
5. 발견, 공간 요소 발동 또는 적이 플레이어를 새로 알아차리는 일이 발생하면 해당 칸에서 이동을 멈추고 공개 가능한 사실을 전달한다.
6. 정상 중단이면 통과한 경로를 보존하고, 시스템·연동 실패면 지도·공간 요소·전장의 안개 상태를 이동 전으로 되돌린다.
7. 전투에서는 위 절차에 더해 현재 턴과 남은 이동 가능량을 검사한다.

### UC-03 공간 요소 발견 및 대응

- 함정 발견 시 위치를 공개하고 위험 칸 진입 전에 멈춘다. Solo Player는 우회하거나 해제를 시도할 수 있으며, 비용·굴림·결과와 중복 발동은 적용 룰북을 따른다.
- 비밀문 발견 시 위치만 공개한다. 별도 상호작용으로 연 뒤에만 이동과 시야가 달라진다. 잠금과 함정은 룰북 또는 시나리오 근거가 있을 때만 적용한다.
- 위험 지역과 상호작용 대상은 구성된 발동 조건에 따라 공개 가능한 결과를 낸다.
- 마법 범위 효과는 생성 시 고정된 점유 칸에서 진입·이탈·전투 턴 시작에 반응하며, 지속 시간이 끝나거나 제거될 때까지 유지된다. 여러 효과는 겹칠 수 있다.

### UC-04 플레이어가 주변을 자세히 살피는 행동

1. Solo Player가 주변을 자세히 살피는 행동을 선언한다.
2. 적용 룰북에 따라 행동 비용과 굴림 필요 여부를 정한다.
3. 플레이어 굴림이 필요하면 기존 Pending Roll Gate와 Player Roll Submission 흐름으로 기다린다.
4. 성공하면 조건을 충족한 공간 요소를 공개한다.
5. 실패하면 `특이한 점을 찾지 못했다`는 의미만 전달하며, 공간 요소 존재 여부·판정 난이도·내부 결과는 숨긴다.

### UC-05 적이 이동 중인 플레이어를 새로 알아차리는 상황 처리

1. 적의 위치에서 이동 중인 플레이어에게 시선이 닿는지 먼저 확인한다. 적에서 플레이어로 시선이 닿지 않으면 적의 지각 판정을 하지 않는다.
2. 은신, 어둠 등 판정 조건이 있으면 룰북에 따라 적이 플레이어를 알아차리는지를 적의 지각 규칙으로 해결한다. 판정 조건이 없으면 적에서 플레이어로 시선이 닿는 것만으로 적이 플레이어를 알아차린다.
3. 적이 플레이어를 새로 알아차린 칸에서 이동을 중단한다.
4. Adventure Runtime이 전투, 경고, 대화 또는 추격으로 이어질지를 결정한다.
5. 같은 적이 플레이어를 계속 보고 있는 동안에는 매 칸마다 다시 중단시키지 않는다. 적이 플레이어를 놓쳤다가 다시 알아차리거나 새로운 적이 플레이어를 알아차리면 다시 중단시킬 수 있다.

### UC-06 Story Plan 기반 공간 요소 준비

1. Adventure Story Plan과 근거를 사용해 숨겨진 공간 요소의 최초 위치를 제안하고 검증한다.
2. 실패하면 이유를 반영해 최대 두 번 보정하여 총 세 번까지 시도한다.
3. 세 번 모두 실패한 필수 공간 요소는 내부 준비 실패로 지도 활성화를 막는다.
4. 세 번 모두 실패한 선택 공간 요소는 생략하고 내부 경고를 남긴다.
5. 좌표를 추측하지 않으며 숨겨진 배치와 검수 화면을 Solo Player에게 노출하지 않는다.

### UC-07 플레이 중 공간 요소 추가

- 현재 사건으로 생긴 불, 붕괴, 마법 효과 등은 이미 본 칸에도 추가할 수 있고 관찰 가능한 경우 공개한다.
- 기존부터 숨겨져 있었다고 주장하는 함정이나 비밀문을 플레이어가 이미 보거나 들어간 칸에 소급하여 추가하지 않는다.
- 아직 보지 않은 칸에는 근거와 생성 시점·버전을 남길 수 있는 공간 요소만 추가한다.

### UC-08 토큰 상태 식별

- 토큰은 원형 초상과 프레임으로 표시한다.
- 플레이어·우호·적대 진영의 테두리를 구분한다.
- 선택됨, 현재 전투 턴, 마지막 목격 상태를 서로 알아볼 수 있게 표시한다.

## 6. Business Rules and Invariants

- **BR-01:** Combat Map은 지형, 토큰, 공간 요소, 시야와 탐험 상태의 유일한 정본이며, 확정 상태 변경 경로는 하나다.
- **BR-02:** AI는 위치를 제안하거나 자연어 위치를 지도에 대응시킬 수 있지만 상태를 직접 변경할 수 없다.
- **BR-03:** 전술 지도가 활성화된 탐험·잠입·추격·전투에 동일한 기본 이동 해결 규칙을 적용한다. 전투는 턴과 이동 가능량을 추가 검사한다.
- **BR-04:** 유령 토큰과 경로를 포함한 이동 제안은 확인 전까지 어떤 게임 상태도 변경하지 않는다.
- **BR-05:** 자연어 이동 해석이 모호하면 후보를 자동 선택하지 않는다.
- **BR-06:** 이동 제안은 경로 계산에 사용한 기준 지도 버전을 포함한다. 확인 시 기준 버전이 오래되었으면 확인을 거부하고, 현재 지도 상태를 기준으로 경로를 다시 계산해 다시 미리 본 뒤 확인해야 한다.
- **BR-07:** 서버는 확인 전에 플레이어에게 알려진 통행 가능 지도 정보만으로 경로를 계산하고, UI는 목적지의 유령 토큰과 경로를 표시한다. Solo Player가 목적지나 경로를 조정하면 같은 공개 정보 경계 안에서 다시 계산한다. 확인된 이동은 경로의 칸 순서대로 해결하며 각 통과 칸에서 시야와 탐험 영역을 갱신하고, 과거 탐험 영역은 기억된 상태로 남는다.
- **BR-08:** 게임 진행 중단은 통과한 경로를 보존한다. 시스템·연동 실패는 해당 이동에서 바뀐 지도·공간 요소·전장의 안개 상태 전부를 되돌린다.
- **BR-09:** 같은 이동 명령을 다시 처리해도 효과가 중복되지 않는다.
- **BR-10:** 플레이어가 별도 행동을 선언하지 않아도 적용되는 지각 판정은 다음 칸 진입 전에 수행하며 현재 보이고, 범위 안이며, 시선이 닿는 공간 요소만 고려한다. 전장의 안개로 가려졌거나 미탐험인 칸은 제외한다.
- **BR-11:** 플레이어가 별도 행동을 선언하지 않아도 적용되는 지각 판정에 성공하면 공간 요소를 공개하고 위험 칸 진입 전에 멈춘다. 실패는 완전히 조용하며 이후 진입으로 공간 요소가 발동할 수 있다.
- **BR-12:** 플레이어가 주변을 자세히 살피는 행동은 이동과 별도 행동이며 비용·굴림은 적용 룰북이 정한다. 실패 응답은 숨겨진 존재나 내부 판정을 암시하지 않는다.
- **BR-13:** 공간 요소 발동 조건은 칸 진입, 칸 이탈, 시야에 들어옴, 관찰, 상호작용, 전투 턴 시작으로 제한한다.
- **BR-14:** 일반 전투·행동 사건은 Adventure Runtime의 책임이며 공간 요소의 범용 발동 체계로 확장하지 않는다.
- **BR-15:** 함정·비밀문·마법 범위 효과의 발견·작동·지속 규칙은 UC-03을 지키고 상태를 다음 행동까지 보존한다.
- **BR-16:** 적이 이동 중인 플레이어를 알아차리는지는 적에서 플레이어로 시선이 닿는지 먼저 확인한 뒤 결정한다. 은신·어둠 등 판정 조건이 있으면 룰북의 적 지각 규칙을 따르고, 판정 조건이 없으면 시선이 닿는 것만으로 적이 플레이어를 알아차린다. 공개되지 않은 내부 수치는 플레이어에게 전달하지 않는다.
- **BR-17:** 플레이 중 추가되는 공간 요소는 UC-07의 시간적 정합성과 근거·시점·버전 규칙을 지킨다.
- **BR-18:** 계획·배치 과정은 숨겨진 정보를 사용할 수 있다. 자연어 목적지 해석과 경로 미리보기 계산은 플레이어가 알고 있는 통행 가능 지도 정보만 사용한다. 숨겨진 적과 숨겨진 공간 요소는 미리보기 경로에 영향을 주거나 응답에 드러나서는 안 되며, 서술은 공개가 확정된 사실만 받는다.
- **BR-19:** Story Plan의 숨겨진 공간 요소는 백엔드 전용이며 Solo Player 검수 대상이 아니다.
- **BR-20:** 토큰 자산은 재배포 가능한 CC0 무료 이미지를 우선 사용하고, 부족한 자산은 일관된 형태로 생성한다. 번들에 포함하는 모든 자산은 출처와 라이선스를 기록해야 한다.

## 7. States and State Transitions

### 이동 제안과 이동 해결

- **제안 없음 → 경로 미리보기:** 직접 드래그로 놓은 목적지 또는 모호하지 않은 자연어 목적지에 대해 서버가 플레이어에게 알려진 통행 가능 지도 정보만으로 경로를 계산하고, UI가 유령 토큰과 경로를 표시한다.
- **경로 미리보기 → 경로 미리보기:** Solo Player가 목적지나 경로를 조정하면 같은 공개 정보 경계 안에서 다시 계산하고 표시한다.
- **경로 미리보기 → 현재 상태에서 재계산 필요:** 확인 시 제안의 기준 지도 버전이 오래되면 확인을 거부하고 현재 지도 상태를 기준으로 경로를 다시 계산해 다시 미리 보게 한다.
- **경로 미리보기 → 칸별 해결 중:** Solo Player가 현재 기준 지도 버전의 이동 제안을 확인하면 검증된 경로를 첫 칸부터 순서대로 해결한다.
- **칸별 해결 중 → 완료:** 목적 칸까지 중단 없이 해결한다.
- **칸별 해결 중 → 정상 중단:** 발견·발동 또는 적이 플레이어를 새로 알아차린 일로 멈추며 통과 상태를 보존한다.
- **칸별 해결 중 → 이동 전 상태:** 시스템·연동 실패로 관련 변경 전체를 되돌린다.

### 공간 요소의 업무 상태

공간 요소는 하나의 동일한 생명주기를 강제하지 않는다. 공통적으로 플레이어에게 `숨김` 또는 `공개됨`일 수 있지만 이후 상태는 종류별로 다르다.

- **함정:** 숨김 → 발견됨 → 해제됨 또는 발동됨. 룰북이 허용하면 발동 후에도 활성 상태가 지속되어 다시 발동할 수 있다.
- **비밀문:** 숨김 → 발견됨 → 열림. 발견만으로 통행·시야가 바뀌지 않는다.
- **위험 지역:** 숨김 또는 공개됨 → 활성 → 해결됨. 시나리오와 룰북에 따라 활성 상태가 지속될 수 있다.
- **상호작용 대상:** 숨김 또는 공개됨 → 상호작용 가능 → 상호작용 결과가 반영된 상태.
- **마법 범위 효과:** 생성됨/활성 → 지속 → 만료 또는 제거. 생성 시 점유 칸은 고정되고 다른 효과와 겹칠 수 있다.

## 8. Failures, Exceptions, and Boundary Conditions

- **EX-01 모호한 자연어 위치:** 이동하지 않고 목적지를 질문하거나 직접 드래그를 안내한다.
- **EX-02 오래된 이동 제안:** 확인을 거부하고 현재 지도 상태를 기준으로 경로를 다시 계산해 다시 미리 본 뒤 확인하도록 안내한다.
- **EX-03 별도 행동 선언 없이 적용되는 지각 판정 실패:** 아무 메시지도 표시하지 않으며 다음 칸 진입과 발동 가능성을 유지한다.
- **EX-04 주변을 자세히 살피는 행동 실패:** 특이한 점을 찾지 못했다는 결과만 표시한다.
- **EX-05 시스템·연동 실패:** 해당 이동에서 발생한 지도·공간 요소·전장의 안개 변경을 전부 되돌리고 이동을 완료로 표시하지 않는다.
- **EX-06 게임 규칙에 따른 중단:** 이미 통과한 경로와 그에 따른 공개 상태를 보존한다.
- **EX-07 중복 명령:** 이미 처리된 같은 명령의 효과를 다시 적용하지 않는다.
- **EX-08 적에서 플레이어로 시선이 닿지 않음:** 적의 지각 판정을 만들지 않으며, 적이 플레이어를 새로 알아차린 상황으로 취급하거나 이동을 중단하지 않는다.
- **EX-09 필수 배치 실패:** 총 세 번의 검증된 시도 후에도 배치하지 못하면 내부 준비 실패로 지도 활성화를 막는다.
- **EX-10 선택 배치 실패:** 총 세 번 실패하면 요소를 생략하고 내부 경고를 남긴다.
- **EX-11 근거 없는 좌표:** 필수 여부와 관계없이 좌표를 추측하지 않는다.
- **EX-12 비공개 정보 경계:** 플레이어가 공간 요소를 알아차리지 못한 결과, 적이 플레이어를 알아차리는 내부 판정, 자연어 이동 해석, AI 서술에서 숨겨진 공간 요소의 존재나 공개되지 않은 내부 수치를 암시하지 않는다.

## 9. Inputs and Outputs

### Inputs

- 직접 드래그로 선택한 토큰과 놓은 목적지 또는 자연어 이동 의도
- 플레이어에게 알려진 통행 가능 지도 정보
- 이동 제안의 기준 지도 버전과 Solo Player가 조정한 목적지 또는 경로
- 확인 시점의 지도·토큰·공간 요소·시야·탐험 상태
- 전투일 때 현재 턴과 남은 이동 가능량
- 적용 룰북의 공간 요소 지각 규칙, 적이 플레이어를 알아차릴 때 사용하는 지각 규칙, 행동 비용, 굴림, 해제, 중복 발동 규칙
- Adventure Story Plan, 시나리오·룰북 근거, 배치 실패 이유
- 플레이 중 사건의 근거와 생성 시점·버전
- 토큰 시각 자산의 출처와 재배포 라이선스

### Outputs

- 직접 드래그로 놓거나 자연어에서 해석한 목적지의 유령 토큰, 플레이어에게 알려진 통행 가능 지도 정보로 계산한 경로, 모호성 해소 안내
- 오래된 기준 지도 버전으로 확인했을 때 현재 상태에서 경로를 다시 계산하고 다시 미리 보도록 하는 안내
- 칸별 애니메이션과 순차적으로 공개되는 전장의 안개
- 최종 도달 칸 또는 중단 칸, 기억된 탐험 영역, 공개가 확정된 공간적 사실
- 발견·상호작용·발동 및 적이 플레이어를 새로 알아차린 상황에 대해 플레이어에게 공개 가능한 결과
- 필요할 때 기존 플레이어 굴림 대기 상태
- 필수 배치 실패에 따른 지도 활성화 차단 또는 선택 배치 생략 내부 경고
- 출처·라이선스가 기록된 원형 토큰 초상 및 진영·선택·현재 턴·마지막 목격 표시

## 10. Scope and Non-goals

### In scope

- 전술 지도가 활성화된 탐험·잠입·추격·전투의 칸별 이동 해결
- 직접 드래그와 자연어 이동 목적지 해석, 유령 토큰·경로 미리보기, 목적지·경로 조정, 확인, 오래된 기준 지도 버전에서의 재계산·재미리보기
- 칸별 시야·탐험 갱신과 플레이어용 이동·전장의 안개 표현
- 플레이어가 별도 행동을 선언하지 않아도 적용되는 지각 판정, 플레이어가 주변을 자세히 살피는 행동, 함정·비밀문·위험 지역·상호작용 대상·마법 범위 효과
- 적이 이동 중인 플레이어를 새로 알아차리는 상황과 이동 중단, Adventure Runtime으로 전달할 공개 가능한 공간적 사실
- Adventure Story Plan 기반 숨겨진 공간 요소 배치와 제한된 보정
- 플레이 중 인과관계가 있는 공간 요소 추가
- 토큰 초상·프레임·진영 및 선택/현재 턴/마지막 목격 시각 상태 새로고침
- 번들 토큰 자산의 출처 표시와 라이선스 준수. 후보 출처로 KePixelArt의 CC0 판타지 캐릭터와 Screaming Brain Studios의 CC0 팩을 검토할 수 있으나, 현재 통합된 것으로 간주하지 않는다.

### Non-goals

- 별도의 지도 사건 체계
- AI의 지도 상태 직접 변경
- 숨겨진 공간 요소에 대한 Solo Player 검수
- 이동하거나 확장되는 마법 범위 효과
- 일반 목적의 범용 발동 체계
- 제품 요구사항을 넘어서는 코드, 저장 방식, 서비스 또는 모듈 구조 결정

## 11. Priorities and Trade-offs

1. **P-01:** 숨겨진 정보 보호와 정본 상태의 일관성을 가장 우선한다.
2. **P-02:** 올바른 중단 지점과 시야·탐험 영역 갱신을 그다음으로 우선한다.
3. **P-03:** 자연어 이동의 지도 대응과 AI 공간 요소 배치를 그다음으로 우선한다.
4. **P-04:** 토큰 시각 완성도는 기능적 정확성이 확보된 뒤 개선한다.

모호한 입력을 자동 완성하는 편의성보다 숨겨진 정보 보호와 잘못된 이동 방지를 우선한다. 시스템 실패 때 부분 진행을 남기는 것보다 정본 일관성을 우선하되, 게임 규칙상 정상 중단에서는 플레이어가 이미 통과하고 관찰한 결과를 보존한다.

## 12. Success Conditions and Acceptance Criteria

- **AC-01 (G-01, BR-04):** 직접 드래그와 자연어 입력 모두 유령 토큰과 경로를 표시하고 조정할 수 있지만, 확인 전에는 위치, 전장의 안개, 공간 요소, 모험 진행을 변경하지 않는다.
- **AC-02 (G-01, BR-05, BR-06):** 직접 드래그로 놓거나 자연어에서 해석한 목적지에 대해 서버가 경로를 계산하고 UI가 유령 토큰과 경로를 표시하며, Solo Player가 목적지나 경로를 조정할 수 있다. 모호한 자연어 입력은 질문 또는 드래그 안내로 끝나며 후보를 자동 선택하지 않는다. 기준 지도 버전이 오래된 제안은 확인을 거부하고 현재 상태에서 경로를 다시 계산해 다시 미리 본 뒤 확인하게 한다.
- **AC-03 (G-02, BR-03, BR-07, BR-18):** 경로 미리보기는 플레이어에게 알려진 통행 가능 지도 정보만 사용하며 숨겨진 적과 숨겨진 공간 요소의 영향을 받거나 이를 응답에 노출하지 않는다. 탐험·잠입·추격·전투에서 현재 기준 지도 버전의 제안을 확인하면 검증된 경로를 칸 순서대로 해결하고, 각 통과 칸마다 시야를 갱신하며 탐험한 영역을 기억한다.
- **AC-04 (G-02):** 플레이어가 볼 수 있는 이동이 통과 칸 순서로 표시되고 전장의 안개가 같은 순서로 공개된다.
- **AC-05 (G-04, BR-08):** 정상 중단은 통과 경로를 보존하고 시스템·연동 실패는 해당 이동의 지도·공간 요소·전장의 안개 변경 전체를 되돌린다.
- **AC-06 (G-04, BR-09):** 같은 명령을 재처리해도 위치 변경, 발견, 발동 또는 공개 효과가 중복되지 않는다.
- **AC-07 (G-03, BR-10, BR-11):** 플레이어가 별도 행동을 선언하지 않아도 적용되는 지각 판정은 다음 칸 진입 전에 현재 보이고 범위 안이며 시선이 닿는 대상만 고려하고, 성공 시 위험 칸 전에 멈추며 실패 시 아무 단서도 표시하지 않는다.
- **AC-08 (G-03, BR-12):** 플레이어가 주변을 자세히 살피는 행동은 룰북의 비용·굴림과 기존 플레이어 굴림 대기를 따르고, 실패 시 판정 난이도·존재·내부 결과를 공개하지 않는다.
- **AC-09 (G-02, BR-13, BR-15):** 각 공간 요소가 지원되는 발동 조건과 종류별 상태 규칙에 맞게 반응하며, 비밀문은 별도 상호작용으로 열리기 전까지 이동과 시야를 바꾸지 않는다.
- **AC-10 (G-02, BR-16):** 적에서 이동 중인 플레이어로 시선이 닿지 않으면 적의 지각 판정과 이동 중단이 없다. 시선이 닿고 판정 조건이 없거나 룰북의 적 지각 판정 결과 적이 플레이어를 새로 알아차리면 해당 칸에서 중단한다. 같은 적이 플레이어를 계속 보고 있는 동안에는 매 칸 다시 중단하지 않고, 놓쳤다가 다시 알아차리거나 새로운 적이 알아차리면 다시 중단할 수 있다.
- **AC-11 (G-03, BR-17, BR-18):** 이미 보거나 들어간 칸에 기존 숨은 함정·비밀문을 소급 추가하지 않고, 자연어 이동 해석과 서술에는 각각 플레이어 공개 정보와 확정된 공개 사실만 사용한다.
- **AC-12 (G-05, BR-19):** Story Plan 공간 요소 배치는 최초 한 번과 이유를 반영한 두 번의 보정까지만 수행하며, 필수 실패는 지도 활성화를 막고 선택 실패는 생략과 내부 경고로 끝난다.
- **AC-13 (G-05):** 배치 좌표를 추측하지 않고 숨겨진 공간 요소나 검수 흐름을 Solo Player에게 노출하지 않는다.
- **AC-14 (G-06, BR-20):** 토큰이 원형 초상·프레임, 진영별 테두리, 선택·현재 턴·마지막 목격 상태를 구분해 표시하며, 번들 자산마다 출처와 재배포 라이선스가 기록된다.
- **AC-15 (BR-03):** 전투 중 이동은 공통 칸별 해결 규칙과 함께 현재 턴 및 남은 이동 가능량 제한을 지킨다.
- **AC-16:** 마법 범위 효과는 생성 시 고정된 칸에서 지속·제거되고 진입·이탈·전투 턴 시작에 반응하며, 겹치는 효과를 허용한다.
