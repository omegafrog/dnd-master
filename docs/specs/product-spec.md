# Product Spec: 자료 준비와 모험 시작 흐름 개선

## 1. Problem and Context

현재 사용자는 룰북 선택, 스토리북 업로드, 자료 처리, 모험 자료 저장, 게임 준비, 모험 시작을 여러 화면과 서로 다른 용어로 경험한다. 룰북과 스토리북의 선택 상태가 분리되어 있고, UUID·revision·내부 처리 상태가 노출되며, 자료 준비와 게임 준비의 경계도 명확하지 않다.

그 결과 사용자는 다음을 알기 어렵다.

- 어떤 자료가 실제 모험에 포함되는가
- 업로드와 추출·인덱싱이 끝났는가
- 저장된 자료와 진행 중인 모험의 차이는 무엇인가
- 게임 준비는 어디에서 시작하는가
- 삭제가 기존 모험에 어떤 영향을 주는가

이 명세는 로그인 이후 자료 준비부터 모험 재개까지의 전체 사용자 흐름과 UI/UX를 일관된 상태 기반 흐름으로 정리한다.

## 2. Goals and Desired Outcomes

- 사용자가 `자료 선택 → 자료 준비 → 모험 자료 저장 → 게임 준비 → 모험 시작`을 한 흐름으로 이해한다.
- 룰북은 고정된 게임 시스템 선택값으로 별도 관리하고, 모험 자료에는 정확히 하나만 연결한다.
- 스토리북은 사용자가 파일별로 선택하고 역할을 지정한다.
- 업로드·추출·인덱싱의 비동기 진행 상황을 shadcn Progress로 확인할 수 있다.
- 모든 선택 자료가 사용 준비 완료되기 전에는 모험 자료 저장을 할 수 없다.
- 저장된 모험 자료를 이름으로 식별할 수 있다.
- 게임 준비는 각 모험 자료의 팝업에서 실행한다.
- 연결된 진행 중 모험이 있는 모험 자료는 삭제할 수 없다.
- AI 엔드포인트 설정은 자료 준비와 분리하고, 게임 준비 시점에만 연결 상태를 확인한다.

## 3. Users and Actors

- **Solo Player**: 자료를 업로드·선택하고 모험을 준비·시작·재개·삭제하는 유일한 인간 사용자.
- **AI Game Master**: 게임 준비가 완료된 뒤 모험 진행을 담당하는 AI 역할.
- **AI Endpoint**: Ollama, OpenAI 호환 연결, Codex OAuth 등 AI Game Master가 사용할 연결 대상.
- **Document Processing**: 업로드 자료를 추출하고 청킹·임베딩·인덱싱하는 비동기 처리 주체.

## 4. Ubiquitous Language and Terminology

- **룰북**: 게임 규칙을 정의하는 고정 선택 자료. 초기 선택지는 `D&D 5판`, `D&D 5.5판`이다.
- **스토리북**: 시나리오·지도·핸드아웃 등 모험 원본 자료.
- **자료 준비**: 업로드, 추출, 청킹, 임베딩, 인덱싱이 완료되어 사용할 수 있는 상태.
- **모험 자료**: 룰북 1개와 사용자가 선택한 스토리북 파일들의 이름 있는 묶음.
- **자료 역할**: 각 스토리북 파일의 의미. `메인 시나리오`, `지도`, `핸드아웃`, `부록`, `참고 자료` 등을 사용한다.
- **게임 준비**: 저장된 모험 자료를 실제 플레이 가능한 패키지로 분석·검증·발행하는 단계.
- **진행 중인 모험**: 게임 준비 결과로 생성된 실제 플레이 세션.
- **사용 준비 완료**: 자료 준비가 끝나 모험 자료에 선택할 수 있는 상태.

## 5. Core Use Cases

### UC-01 자료 업로드와 기존 자료 확인

1. 사용자가 자료 설정 화면에 진입한다.
2. 기존에 업로드한 스토리북 목록을 확인한다.
3. 새 파일을 여러 개 선택해 업로드한다.
4. 파일별 처리 상태와 shadcn Progress를 확인한다.
5. 실패한 파일은 개별적으로 다시 처리한다.
6. 사용자는 기존 자료를 삭제할 수 있다.

### UC-02 룰북 선택

1. 사용자가 `D&D 5판` 또는 `D&D 5.5판`을 선택한다.
2. 룰북은 스토리북 파일 목록 및 역할 선택과 별도의 선택 영역에 표시된다.
3. 모험 자료를 저장할 때 룰북이 정확히 하나 선택되어야 한다.

### UC-03 스토리북 파일별 선택과 역할 지정

1. 사용자가 준비 완료된 스토리북을 파일별로 선택한다.
2. 각 선택 파일에 역할을 지정한다.
3. 메인 시나리오는 최대 하나만 선택한다.
4. 처리 중이거나 실패한 파일은 선택할 수 없다.
5. 선택하지 않은 파일은 모험 자료에 포함하지 않는다.

### UC-04 모험 자료 저장

1. 사용자가 모험 자료 이름을 입력한다.
2. 선택한 룰북과 스토리북 파일·역할을 확인한다.
3. 모든 선택 자료가 사용 준비 완료인지 확인한다.
4. 조건을 만족하면 모험 자료를 저장한다.
5. 저장 목록에는 이름, 룰북, 자료 수, 버전, 준비 상태를 표시한다.

### UC-05 모험 자료 게임 준비

1. 사용자가 모험 자료 카드의 `게임 준비`를 누른다.
2. 팝업에서 준비 대상과 현재 상태를 확인한다.
3. 시스템은 AI 엔드포인트 연결 상태를 확인한다.
4. 연결되어 있으면 분석·컴파일·발행을 시작한다.
5. 준비 중에는 단계별 상태와 진행 상황을 표시한다.
6. 완료되면 `모험 시작` 또는 `캐릭터 생성`을 제공한다.

### UC-06 진행 중인 모험 재개

1. 사용자가 모험 목록에서 진행 중인 모험을 선택한다.
2. 모험 이름과 마지막 진행 상태를 확인한다.
3. `재개`를 누르면 해당 모험 화면으로 이동한다.
4. 세션에 사용할 자료 목록을 변경할 수 있는 경우, 변경 대상과 영향을 명확히 안내한다.

### UC-07 모험 자료 삭제

1. 사용자가 모험 자료 삭제를 요청한다.
2. 연결된 진행 중인 모험이 있으면 삭제를 거부한다.
3. 삭제 불가 사유와 연결된 모험 목록 또는 개수를 안내한다.
4. 연결된 진행 중인 모험이 없을 때만 삭제를 완료한다.

### UC-08 AI 엔드포인트 설정

1. 사용자는 내 설정에서 AI 엔드포인트를 등록한다.
2. 자료 업로드와 모험 자료 저장은 엔드포인트 없이 가능하다.
3. 게임 준비 시작 시 엔드포인트 연결 상태를 확인한다.
4. Codex OAuth는 `로그인 필요`, `연결됨`, `만료됨`, `연결 실패` 상태를 표시한다.
5. 연결되지 않은 경우 게임 준비를 중단하고 설정 화면으로 안내한다.

## 6. Business Rules and Invariants

- BR-01: 하나의 모험 자료에는 룰북이 정확히 하나 포함된다.
- BR-02: 룰북 선택은 스토리북 역할 선택과 별도 UI 영역에서 수행한다.
- BR-03: 스토리북 파일은 파일 단위로 선택·삭제·역할 지정한다.
- BR-04: 메인 시나리오 역할은 하나의 모험 자료에서 최대 하나만 허용한다.
- BR-05: 처리 중·실패·사용 불가 자료는 모험 자료에 선택할 수 없다.
- BR-06: 선택한 모든 자료가 `사용 준비 완료`여야 모험 자료 저장이 가능하다.
- BR-07: 모험 자료 저장에는 사용자에게 표시할 이름이 필요하다.
- BR-08: 게임 준비는 저장된 모험 자료에서만 시작할 수 있다.
- BR-09: AI 엔드포인트 연결은 자료 준비의 선행 조건이 아니며 게임 준비의 선행 조건이다.
- BR-10: 진행 중인 모험이 연결된 모험 자료는 삭제할 수 없다.
- BR-11: 삭제 실패는 조용히 무시하지 않고 사용자가 이해할 수 있는 사유를 제공한다.
- BR-12: 사용자 화면에는 UUID·내부 enum·raw compilation error를 기본 정보로 노출하지 않는다.

## 7. States and State Transitions

### 자료 상태

`업로드 대기 → 자료 준비 중 → 사용 준비 완료`

실패 경로:

`자료 준비 중 → 준비 실패 → 다시 처리 → 자료 준비 중`

### 모험 자료 상태

`작성 중 → 저장됨 → 게임 준비 중 → 준비 완료`

실패 경로:

`게임 준비 중 → 준비 실패 → 다시 준비`

### 모험 상태

`생성됨 → 진행 중 → 완료`

삭제 제약:

`저장됨` 또는 `준비 완료` 상태의 모험 자료라도 연결된 `진행 중` 모험이 있으면 삭제 불가.

## 8. Failures, Exceptions, and Boundary Conditions

- 파일 일부만 실패한 경우 성공한 파일의 처리는 유지하고 실패 파일만 다시 처리한다.
- 사용자가 페이지를 새로 열어도 `대기 중`·`자료 준비 중` 상태는 자동으로 갱신되어야 한다.
- 네트워크 오류로 상태를 불러오지 못하면 마지막 상태와 새로고침 안내를 표시한다.
- 룰북을 선택하지 않으면 저장 버튼을 비활성화한다.
- 스토리북을 하나도 선택하지 않으면 저장 버튼을 비활성화한다.
- 메인 시나리오를 두 개 지정하려 하면 기존 선택을 해제하거나 명확한 오류를 표시한다.
- 게임 준비 중 팝업을 닫아도 준비 작업은 중단하지 않으며, 다시 열면 최신 상태를 표시한다.
- AI 엔드포인트가 없거나 만료된 경우 게임 준비를 시작하지 않는다.
- 연결된 진행 중 모험이 있는 자료는 삭제할 수 없다.
- 자료 삭제 시 해당 자료를 참조하는 저장된 모험 자료가 있으면 의존성 상태를 확인하고 삭제를 거부한다.

## 9. Inputs and Outputs

### 입력

- 룰북 선택: `D&D 5판 | D&D 5.5판`
- 스토리북 파일 목록
- 파일별 포함 여부
- 파일별 역할
- 모험 자료 이름
- AI 엔드포인트 연결 설정
- 게임 준비·재시도·삭제·재개 명령

### 출력

- 파일별 처리 상태
- shadcn Progress 진행률
- 모험 자료 요약 카드
- 게임 준비 단계와 완료·실패 상태
- 삭제 불가 사유
- AI 엔드포인트 연결 상태
- 모험 목록과 마지막 진행 상태

## 10. Scope and Non-goals

### Scope

- 자료 설정 화면의 정보 구조와 용어 개선
- 비동기 자료 처리 상태 및 진행률 표시
- 룰북·스토리북 선택 모델 정리
- 이름 있는 모험 자료 저장
- 모험 자료별 게임 준비 팝업
- 삭제 의존성 보호
- AI 엔드포인트 연결 상태 표시

### Non-goals

- 룰북 편집기 제작
- 여러 룰북 병합
- AI Game Master의 서술 품질 자체 개선
- 게임 규칙 엔진의 새로운 기능 추가
- 보관 기능 구현
- 모바일 전용 레이아웃 재설계

## 11. Priorities and Trade-offs

### P0

- 룰북을 별도 필드로 유지하면서 모험 자료 저장에 정확히 연결
- 파일별 선택·역할 지정
- 자료 처리 완료 전 저장 차단
- shadcn Progress 기반 비동기 상태 표시
- 삭제 시 진행 중 모험 보호

### P1

- 모험 자료 이름
- 게임 준비 팝업의 단계별 상태
- 사용자용 상태·오류 문구
- 새로고침 후 처리 상태 복구
- AI 엔드포인트 상태 표시

### P2

- 미리보기와 상세 경고 개선
- 모험 목록의 필터·정렬
- 자료 보관 기능

Trade-off: 룰북을 별도 선택으로 유지하면 사용자가 시나리오 파일과 게임 시스템을 명확히 이해할 수 있지만, 저장 시 두 선택 영역을 함께 검증해야 한다. 파일별 역할 선택은 자동 분류보다 입력 부담이 크지만, 잘못된 역할 지정으로 인한 시나리오 분석 오류를 줄인다.

## 12. Success Conditions and Acceptance Criteria

- AC-01: 사용자는 자료 설정 화면에서 룰북을 `D&D 5판` 또는 `D&D 5.5판` 중 하나만 선택할 수 있다.
- AC-02: 사용자는 준비 완료된 스토리북 파일을 파일별로 선택하고 역할을 지정할 수 있다.
- AC-03: 처리 중 파일은 선택 및 저장 대상이 될 수 없다.
- AC-04: 업로드 직후 shadcn Progress와 파일별 상태가 표시된다.
- AC-05: 페이지를 새로 열어도 처리 중 상태가 자동 갱신된다.
- AC-06: 룰북 미선택, 스토리북 미선택, 처리 미완료 상태에서는 저장 버튼이 비활성화된다.
- AC-07: 저장된 자료는 UUID가 아닌 사용자가 입력한 이름을 우선 표시한다.
- AC-08: 게임 준비는 모험 자료 카드의 팝업에서 실행된다.
- AC-09: AI 엔드포인트가 연결되지 않으면 게임 준비가 시작되지 않고 설정 안내가 표시된다.
- AC-10: 진행 중인 모험이 연결된 자료는 삭제할 수 없고, 사유가 표시된다.
- AC-11: 게임 준비 중 팝업을 닫았다가 다시 열면 최신 상태를 확인할 수 있다.
