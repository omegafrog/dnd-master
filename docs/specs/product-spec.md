# Product Spec: GM 모험 진행 품질 개선

## 1. Problem and Context

실제 Playwright로 자산 업로드·인덱싱·번들 생성·캐릭터/파티 생성·모험 시작까지 수행한 뒤 GM 대화를 진행했을 때, 첫 플레이어 입력부터 턴 처리가 중단되었다. 구조화 응답을 요구하는 모델이 유효한 결과를 만들지 못했고, 재시도 후에도 실패했다. 시작 장면에는 플레이어가 알 수 없어야 할 DC와 내부 결말 식별자가 노출되었다. 주사위 굴림과 룰 안내도 실패 시 원인과 복구 경로를 제공하지 못했다.

이 문제는 Solo Player가 자료 준비부터 실제 플레이까지의 핵심 여정을 완료할 수 없게 하며, 룰북 근거·스토리 진행·전투·비밀 정보 보호에 대한 신뢰를 훼손한다.

## 2. Goals and Desired Outcomes

- **G-001**: 인덱싱된 Rulebook과 Storybook을 사용해 모험을 시작하고 GM 대화 5턴을 연속 완료한다.
- **G-002**: GM이 Story Plan의 현재 단계와 전환 조건을 유지하며 플레이어 행동에 맞춰 장면을 전개한다.
- **G-003**: 전투 진입 시 룰북 근거에 따른 판정, 내성, 공격/피해 주사위와 상태 변화를 일관되게 진행한다.
- **G-004**: 플레이어에게 DC, 숨은 분기·결말, GM 전용 사실, 내부 식별자와 같은 비공개 정보를 노출하지 않는다.
- **G-005**: 모델·검색·룰 엔진 오류가 발생해도 턴을 부분 반영하지 않고, 이해 가능한 실패 상태와 재시도 경로를 제공한다.
- **G-006**: 위 여정을 실제 프런트엔드 UI만으로 반복 검증할 수 있는 수용 시나리오와 품질 증거를 남긴다.

## 3. Users and Actors

- **Solo Player**: 파일을 준비하고 캐릭터/파티를 구성하며 모험을 플레이한다.
- **AI Game Master**: 근거와 런타임 상태를 바탕으로 장면, 판정, NPC, 전투 진행을 제안한다.
- **Rule Knowledge**: 업로드된 Rulebook/Storybook의 인덱싱 및 근거를 제공한다.
- **Dice/Rule Runtime**: 주사위 결과와 규칙에 따른 상태 전이를 확정한다.
- **Character/Combat Map**: 캐릭터와 전투 상태를 소유하고 명령을 반영한다.

## 4. Ubiquitous Language and Terminology

- **GM Turn**: 플레이어 행동 하나를 해석하고 판정·서술·상태 변화·다음 상황을 확정하는 원자적 진행 단위.
- **Player Projection**: 플레이어에게 공개해도 되는 정보만으로 구성된 응답과 화면 상태.
- **Hidden Fact**: 아직 공개 조건을 만족하지 않은 DC, 분기, 결말, NPC 의도, 위치·트랩 정보 및 내부 식별자.
- **Authoritative Roll**: 룰 런타임이 멱등 명령으로 실행하고 결과를 정본으로 보존하는 주사위 결과.
- **Combat Turn**: 전투 규칙에 따라 순서·행동·명중·피해·상태를 처리하는 런타임 단위.
- **Quality Scenario**: 자산 준비부터 모험 5턴 및 전투까지 UI로 실행하는 고정 수용 시나리오.

## 5. Core Use Cases

### UC-001 자료에서 모험 시작

Solo Player가 Rulebook과 Storybook을 업로드하고 UI에서 인덱싱 완료를 확인한다. 번들을 생성하고 캐릭터와 파티를 만든 뒤 모험을 시작한다. 시스템은 세션에 선택된 자료와 버전을 고정하고 플레이 가능한 시작 상태를 보여준다.

### UC-002 GM과 5턴 진행

Solo Player가 자연어 행동을 입력한다. AI Game Master는 공개된 근거와 현재 런타임 상태 안에서 장면과 판정 결과를 제안한다. 시스템은 유효성 검사를 통과한 결과만 한 턴으로 커밋하고 다음 입력을 받는다. 동일 흐름을 5회 완료한다.

### UC-003 룰 판정과 주사위 수행

플레이어 행동 또는 GM 판정이 룰북에 정의된 판정·내성·공격·피해를 요구한다. 시스템은 필요한 주사위를 authoritative roll로 실행하고, 결과를 룰에 적용한 뒤 플레이어가 이해할 수 있는 판정 결과를 표시한다.

### UC-004 전투 진행

스토리 또는 플레이어 행동으로 전투에 진입한다. 시스템은 전투 상태와 순서를 표시하고, 각 행동의 유효성을 검증하며, 명중·피해·자원·상태를 룰북대로 반영한다. 전투 종료 조건을 만족하면 탐험/서사 흐름으로 복귀한다.

### UC-005 실패 복구

모델 응답이 malformed이거나 검색·룰·외부 서비스가 실패하면 시스템은 해당 턴을 커밋하지 않는다. UI는 실패 원인 범주, 현재 상태 보존 여부, 재시도 가능 여부를 표시한다. 재시도는 중복 상태 변화를 만들지 않는다.

## 6. Business Rules and Invariants

- **BR-001**: 플레이어 투영에는 공개된 사실과 허용된 근거만 포함한다. Hidden Fact와 내부 식별자는 기본적으로 차단한다.
- **BR-002**: DC·난이도·비공개 판정 기준은 공개 조건이 충족된 경우에만 공개한다. 판정 전에는 자연어 목표와 결과만 제공할 수 있다.
- **BR-003**: AI 응답은 구조·인용·사실·도구 호출·비밀정보 검사를 모두 통과해야 턴에 반영된다.
- **BR-004**: AI는 권위 있는 상태 변경을 직접 확정하지 않는다. 주사위·캐릭터·전투 명령은 해당 상태 소유자가 검증하고 반영한다.
- **BR-005**: 하나의 GM Turn은 성공적으로 커밋되거나 아무것도 반영되지 않는 원자적 결과다.
- **BR-006**: authoritative roll은 멱등 키로 중복 실행을 방지하고 결과를 재현 가능하게 조회할 수 있어야 한다.
- **BR-007**: 세션은 선택된 Rulebook/Storybook과 버전을 고정하며, 다른 문서나 미인덱스 자료를 근거로 사용하지 않는다.
- **BR-008**: 전투 행동은 현재 전투 상태·차례·캐릭터 권한·룰북 지원 범위를 만족해야 한다.
- **BR-009**: malformed 응답에 대한 자동 복구는 제한된 횟수로 수행하며, 복구 실패 시 안전하게 중단한다.
- **BR-010**: UI 수용 검증은 파일·DB를 직접 변경하지 않고 사용자-visible 조작만으로 수행한다.

## 7. States and State Transitions

### Session

`PREPARING → STARTING → STARTED → COMPLETED`

`STARTING → START_FAILED` 또는 `STARTED → TURN_RETRYABLE_FAILURE` 전환은 사용자에게 원인과 복구 경로를 남긴다. 실패한 턴은 이전 커밋 버전을 유지한다.

### GM Turn

`RECEIVED → CONTEXT_READY → PROVIDER_REQUESTED → VALIDATED → COMMITTED`

구조 오류·안전 오류·외부 오류는 `TURN_FAILED`로 종료하며 `COMMITTED`로 진행하지 않는다.

### Combat

`EXPLORATION → COMBAT_ENTERED → ACTOR_TURN → RESOLUTION → COMBAT_END → EXPLORATION`

## 8. Failures, Exceptions, and Boundary Conditions

- 모델이 JSON 스키마를 지키지 않거나 repair도 실패함: 턴 미커밋, 재시도 버튼과 안정적인 오류 표시.
- 모델이 숨은 사실, DC, 내부 ID, 존재하지 않는 상태를 제안함: 응답 폐기, 보호 정보는 오류 메시지에도 포함하지 않음.
- 룰북 근거가 없거나 지원되지 않는 규칙임: 판정을 확정하지 않고 플레이어에게 선택 가능한 다음 행동을 안내.
- 주사위/캐릭터/전투 서비스가 지연·실패함: 부분 서술·부분 상태 변경 없이 재시도 가능 상태.
- 세션의 자료가 미인덱스이거나 버전이 불일치함: 시작을 막고 필요한 준비 상태를 표시.
- 5턴 중간에 새로고침하거나 재시도함: 마지막 커밋 턴 이후로만 복구하며 중복 턴을 생성하지 않음.

## 9. Inputs and Outputs

입력은 UI에서 선택한 업로드 파일, 번들·캐릭터·파티 선택, 플레이어 자연어 행동, 전투 행동, 선택적 판정 대상이다. 출력은 공개 장면 서술, 공개된 NPC 상태, 룰 근거와 판정 결과, 전투 상태, 현재 턴 상태, 실패·복구 안내다.

플레이어 출력에는 모델 원문, 프롬프트, 검색 결과 전체, 내부 상태 델타, 비공개 계획·결말·DC·식별자를 포함하지 않는다.

## 10. Scope and Non-goals

포함: 구조화 GM 응답의 안정성, 비밀정보 투영 차단, authoritative dice/rules/combat 연계, 시작 프리플라이트·실패 복구, UI 기반 5턴/전투 수용 시나리오와 관측 증거.

제외: 새 게임 시스템 설계, 임의 입력 파일 편집, DB 직접 조작을 통한 테스트, 인간 GM 관리 기능, 모델 파인튜닝 자체, 전체 RAG 랭킹 재설계.

## 11. Priorities and Trade-offs

1. P0: 비밀정보 차단과 원자적 턴 안전성.
2. P0: 모델 응답 실패를 줄이고 실패 시 복구 가능하게 함.
3. P0: 룰·주사위·전투의 권위 있는 처리.
4. P1: 시작 프리플라이트와 버전/인덱싱 상태 가시화.
5. P1: 5턴 및 전투를 반복 실행하는 UI 수용 자동화와 품질 지표.

품질과 진행성 충돌 시 안전한 중단을 우선한다. 모델의 자유로운 서술보다 룰북 근거·현재 상태·비밀정보 보호를 우선한다.

## 12. Success Conditions and Acceptance Criteria

- **AC-001**: 고정된 UI 시나리오가 인덱싱 완료된 Rulebook/Storybook으로 세션 시작과 GM 5턴을 완료한다.
- **AC-002**: 시나리오 실행 중 플레이어 화면·브라우저 네트워크·실패 메시지에 Hidden Fact, DC, 내부 ID가 나타나지 않는다.
- **AC-003**: malformed/unsafe 응답은 턴·이벤트·상태 버전을 변경하지 않고 재시도 가능한 오류로 표시된다.
- **AC-004**: 최소 한 번의 내성, 복수 주사위 굴림, 공격/피해, 전투 진입·종료가 룰북 근거와 함께 성공한다.
- **AC-005**: authoritative roll과 상태 명령은 재시도·새로고침에도 중복 반영되지 않는다.
- **AC-006**: 자료 미인덱스·버전 불일치·지원되지 않는 규칙은 시작/판정을 조용히 진행시키지 않고 명시적 상태로 안내한다.
- **AC-007**: 각 티켓은 정책 단위 테스트와 `UI ~ entity` E2E 테스트를 포함하며, 수용 시나리오 결과와 로그/스크린샷을 보관한다.
