# Product Spec: 캐릭터 생성 설정 검토 UX 개선

## 1. Problem and Context

캐릭터 생성 설정 검토 화면은 룰북 선택, 설정 생성, 필드 검토, 저장, 게시, 세션 생성을 한 화면에 혼합한다. 사용자는 현재 무엇을 해야 하는지, 설정이 생성되었는지, 어떤 항목이 미완료인지, 저장과 게시의 차이가 무엇인지 즉시 이해하기 어렵다.

현재 화면에는 모험 결과 UUID와 `CharacterCreationBlueprint` 같은 내부 용어가 노출되고, 설정 생성 실패 상태에서도 입력 트리가 함께 표시되는 상태 모순이 있다. 긴 중첩 입력 구조와 설명 패널은 탐색 비용을 높이며, 선택 항목의 완료 여부와 저장 상태도 분명하지 않다.

## 2. Goals and Desired Outcomes

- 사용자가 `룰북 선택 → 설정 검토 → 게시 및 캐릭터 생성`의 3단계를 이해한다.
- 내부 ID, enum, 영문 오류를 사용자 친화적인 표현으로 대체한다.
- 설정 생성 전·진행 중·실패·검토 필요·게시 완료 상태를 모순 없이 표현한다.
- 룰북 기본 내용과 스토리북 추가 제안을 서로 다른 검토 영역으로 보여준다.
- 스토리북 제안마다 적용 또는 제외를 선택하고, 적용한 항목만 최종 설정에 포함한다.
- 섹션별 미완료 필드와 전체 완료율을 확인할 수 있다.
- 필드 입력, 저장, 게시의 차이를 명확하게 전달한다.
- 룰북이 하나뿐이면 자동 선택해 불필요한 조작을 줄인다.
- 데스크톱과 좁은 화면 모두에서 입력 흐름을 유지한다.

## 3. Users and Actors

- **Solo Player**: 생성 설정을 검토하고 값을 보완한 뒤 캐릭터 생성을 시작하는 사용자.
- **Scenario Preparation**: 모험 자료를 분석하고 캐릭터 생성 설정을 제공하는 시스템.
- **Rulebook Catalog**: 기본 시트 구조와 선택지를 제공하는 룰북 카탈로그.

## 4. Ubiquitous Language and Terminology

- **캐릭터 생성 설정**: 룰북과 시나리오 자료를 바탕으로 생성된 캐릭터 입력 항목 묶음.
- **기본 설정 생성**: 선택한 룰북으로 캐릭터 생성에 필요한 기본 항목과 선택지를 만드는 작업.
- **설정 검토**: 시스템이 제안한 항목을 사용자가 확인·수정하는 작업.
- **검토값 저장**: 특정 입력 항목의 사용자 선택을 저장하는 작업.
- **게시**: 검토가 끝난 설정을 캐릭터 생성에 사용할 수 있도록 확정하는 작업.
- **필수 항목**: 게시 전에 값이 반드시 있어야 하는 항목.
- **시나리오 전용 항목**: 스토리북 분석으로 추가된 선택적 캐릭터 입력 항목.
- **스토리북 제안**: 스토리북에서 발견되어 캐릭터 생성 설정에 추가할 수 있지만, 사용자가 적용하기 전에는 최종 설정에 포함되지 않는 항목.
- **적용된 설정**: 룰북 기본 항목과 사용자가 적용한 스토리북 제안으로 구성된 게시 대상 설정.

## 5. Core Use Cases

### UC-01 룰북 선택과 기본 설정 생성

사용자는 준비된 룰북을 확인하고 하나를 선택해 기본 설정 생성을 시작한다. 준비된 룰북이 하나뿐이면 시스템이 자동 선택한다.

### UC-02 설정 상태 확인

사용자는 설정 생성 중, 실패, 검토 필요, 게시 완료 상태와 다음 행동을 확인한다.

### UC-03 섹션별 설정 검토

사용자는 기본 정보, 능력치, 배경 및 특징 등 섹션을 열고 항목을 입력·선택한다. 각 섹션의 완료 수와 전체 완료율을 확인한다.

### UC-03a 룰북 기본 내용 검토

사용자는 선택한 룰북에서 제공된 기본 항목과 선택지를 별도 영역에서 확인하고 값을 입력한다. 룰북 기본 항목은 스토리북 제안과 섞이지 않는다.

### UC-03b 스토리북 추가 제안 검토

사용자는 스토리북별로 추출된 추가 항목을 목록으로 확인한다. 각 제안에는 출처 파일, 제안 설명, 원문 근거와 입력 방식이 표시되며, 사용자는 항목별로 `적용` 또는 `제외`를 선택한다. 적용 전 제안은 최종 캐릭터 생성 설정에 반영되지 않는다.

### UC-04 선택지 탐색

사용자는 종족·배경·직업 등 설명이 필요한 선택지를 이름, 요약, 주요 특징과 함께 비교하고 선택한다.

### UC-05 검토값 저장

사용자는 변경된 항목의 저장 상태를 확인한다. 저장 성공·실패는 해당 항목과 전체 상태에 반영된다.

### UC-06 설정 게시

사용자는 필수 항목을 모두 해결한 뒤 설정을 게시한다. 미완료 항목이 있으면 게시할 수 없고 남은 항목을 확인할 수 있다.

### UC-07 캐릭터 생성 시작

게시된 설정에서 캐릭터 생성으로 이동한다. 게시 전에는 이 행동을 제공하지 않는다.

## 6. Business Rules and Invariants

- BR-01: 기본 설정 생성에는 준비 완료 상태의 룰북이 필요하다.
- BR-02: 준비된 룰북이 하나면 자동 선택하고, 여러 개면 사용자가 하나를 선택한다.
- BR-03: 설정 생성 실패 상태에서는 입력 트리를 표시하지 않고 실패 원인과 재시도만 표시한다.
- BR-04: 설정 검토 화면에는 내부 UUID, enum 이름, `Blueprint` 같은 내부 구현 용어를 노출하지 않는다.
- BR-05: 게시에는 모든 필수 항목이 해결되어야 한다.
- BR-06: 저장 중인 항목은 중복 저장할 수 없고, 실패한 항목은 재시도할 수 있다.
- BR-07: 시나리오 전용 항목은 기본 룰북 항목과 시각적으로 구분한다.
- BR-08: 게시 완료 전에는 캐릭터 생성 시작을 허용하지 않는다.
- BR-09: 룰북 기본 항목, 스토리북 제안, 적용된 설정은 화면과 데이터 모델에서 구분한다.
- BR-10: 스토리북 제안은 사용자가 `적용`한 경우에만 적용된 설정과 게시 대상에 포함한다.
- BR-11: 사용자가 `제외`한 스토리북 제안은 적용된 설정과 게시 대상에서 제외하며, 기본 룰북 항목에는 영향을 주지 않는다.
- BR-12: 각 스토리북 제안에는 출처 문서, 추출 요약 또는 제안 설명, 원문 근거를 표시한다. 근거가 없으면 적용을 허용하지 않고 확인 필요 상태로 표시한다.

## 7. States and State Transitions

### 7.1 설정 생성 상태

`NOT_STARTED → GENERATING → NEEDS_REVIEW → PUBLISHED`

실패 시 `GENERATING → GENERATION_FAILED → GENERATING`으로 재시도한다.

### 7.2 입력 항목 상태

`UNRESOLVED → DIRTY → SAVING → SAVED`

저장 실패 시 `SAVING → SAVE_ERROR → DIRTY`로 되돌려 재시도한다.

### 7.3 화면 상태 규칙

- `NOT_STARTED`: 룰북 선택과 기본 설정 생성만 표시한다.
- `GENERATING`: 진행 표시와 취소 또는 대기 안내만 표시한다.
- `GENERATION_FAILED`: 오류 원인과 재시도만 표시한다.
- `NEEDS_REVIEW`: 섹션별 입력과 검토 진행률을 표시하고, 룰북 기본 내용·스토리북 제안·적용된 설정 요약을 별도 영역으로 표시한다.
- `PUBLISHED`: 게시 완료 요약과 캐릭터 생성 버튼을 표시한다.

## 8. Failures, Exceptions, and Boundary Conditions

- 룰북이 없거나 사용할 수 없으면 기본 설정 생성 버튼을 비활성화하고 이유를 표시한다.
- 설정 생성 실패 시 원시 예외 문자열 대신 사용자 메시지와 재시도 방법을 표시한다.
- 일부 항목 저장 실패 시 전체 화면을 오류 상태로 만들지 않고 해당 항목에 오류를 표시한다.
- 동시 수정으로 revision이 맞지 않으면 최신 설정을 다시 불러오고 사용자의 미저장 값을 보존할지 안내한다.
- 게시 조건이 충족되지 않으면 필수 항목 목록으로 이동할 수 있게 한다.
- 스토리북 분석 결과가 없으면 “추가 제안 없음”과 분석 대상 문서를 표시한다.
- 스토리북 분석에 실패하거나 근거가 부족하면 제안 목록 대신 실패·확인 필요 상태와 재시도 방법을 표시한다.
- 스토리북 제안을 적용하거나 제외하지 않은 채 게시할 수 없으며, 미결정 제안 수를 표시한다.
- 긴 선택지 설명과 깊은 중첩은 카드 내부 접기와 페이지 내 탐색으로 제한한다.
- 모바일 화면에서는 좌우 분할을 단일 열로 바꾸고 섹션 탐색을 가로 스크롤 또는 상단 탭으로 제공한다.

## 9. Inputs and Outputs

### Inputs

- 선택한 룰북 카탈로그 ID와 추출 버전
- 캐릭터 입력 필드 값
- 시나리오 전용 필드 추가 요청
- 게시 요청

### Outputs

- 설정 상태와 사용자 메시지
- 섹션별 완료 수와 전체 완료율
- 항목별 저장 상태
- 스토리북 제안 목록과 제안별 출처·근거·결정 상태
- 사용자가 적용한 스토리북 항목 목록
- 게시된 설정과 캐릭터 생성 진입

## 10. Scope and Non-goals

### Scope

- 캐릭터 생성 설정 검토 화면의 정보 구조, 상태 표현, 용어, 입력·저장·게시 흐름 개선
- 룰북 기본 내용과 스토리북 제안의 분리·검토·적용/제외 흐름
- 룰북 자동 선택과 선택지 카드형 표현
- 반응형 레이아웃과 접근 가능한 상태 안내

### Non-goals

- 룰북 원문 또는 시나리오 추출 알고리즘 변경
- 캐릭터 시트 계산 규칙 변경
- 새로운 AI 제공자 추가
- 기존 캐릭터 플레이 화면 재설계

## 11. Priorities and Trade-offs

1. P0: 상태 모순 제거, 내부 용어 제거, 3단계 흐름 정리
2. P0: 룰북 기본 내용과 스토리북 제안 분리, 제안별 적용/제외, 근거 표시
3. P0: 게시 전 필수 항목 검증과 미완료 항목 안내
4. P1: 섹션별 완료율과 항목별 저장 상태
5. P1: 룰북 자동 선택과 선택지 카드
6. P2: 고급 필드 검색, 단축 탐색, 세부 애니메이션

정확한 서버 진행률보다 사용자가 다음 행동을 이해하는 것이 우선이다. 초기 버전은 서버가 제공하는 상태와 필드 상태로 완료율을 계산하고, 세부 작업 진행률은 별도 계약이 필요할 때 확장한다.

## 12. Success Conditions and Acceptance Criteria

- AC-01: 사용자는 화면 진입 후 현재 단계와 다음 행동을 5초 안에 이해할 수 있다.
- AC-02: 내부 UUID와 `CharacterCreationBlueprint`가 일반 사용자 화면에 표시되지 않는다.
- AC-03: 설정 생성 실패 시 입력 트리가 표시되지 않고 재시도 방법이 표시된다.
- AC-04: 준비된 룰북이 하나면 기본 룰북이 자동 선택된다.
- AC-05: 각 섹션에 완료 항목 수와 미완료 항목 수가 표시된다.
- AC-06: 필수 항목이 남아 있으면 게시 버튼이 비활성화되고 남은 항목을 확인할 수 있다.
- AC-07: 저장 중·저장 완료·저장 실패가 항목 단위로 구분된다.
- AC-08: 게시 완료 후에만 캐릭터 생성 시작 버튼이 표시된다.
- AC-09: 390px 폭에서도 입력 항목과 주요 버튼을 사용할 수 있다.
- AC-10: 사용자는 룰북 기본 내용과 스토리북 추가 제안을 서로 다른 영역에서 확인할 수 있다.
- AC-11: 각 스토리북 제안에 출처 파일, 설명, 원문 근거와 `적용`·`제외` 조작이 표시된다.
- AC-12: 적용하지 않은 스토리북 제안은 적용된 설정 요약과 게시 결과에 포함되지 않는다.
- AC-13: 스토리북 제안이 없거나 추출에 실패하면 빈 상태 또는 실패 상태와 대상 문서가 표시된다.
- AC-14: 근거가 없는 제안은 적용할 수 없고, 사용자는 확인 필요 사유를 볼 수 있다.
