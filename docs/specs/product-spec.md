# Product Spec — 근거 기반 자동 판정 GM과 장기 세션 메모리

## 1. Problem and Context

현재 GM은 근거 기반 장면 서술과 대화 저장을 수행하지만, 플레이어 행동을 캐릭터의 실제 상태와 룰에 맞게 판정하고 주사위 결과를 확정하는 완전한 게임 마스터 흐름은 제공하지 않는다. 또한 전체 대화는 보존되더라도, 긴 세션에서 중요한 사실을 안정적으로 GM 입력에 유지·복구하는 정책이 필요하다.

## 2. Goals and Desired Outcomes

- 플레이어 행동마다 GM이 판정 필요 여부와 적용 규칙을 결정한다.
- 시스템이 주사위와 수치를 정본으로 계산하고, GM은 결과를 서술한다.
- 모든 판정 근거와 계산 과정을 플레이어에게 투명하게 보여 준다.
- 장기 세션의 게임 사실은 손실 없이 보존하고, 모델 입력은 예산 안에서 압축한다.
- GM은 분위기 묘사만 제한적으로 창작하며, 게임 효과가 있는 사실은 근거나 확정 상태에 묶는다.

## 3. Users and Actors

| Actor | Goal |
| --- | --- |
| 플레이어 | 자연어로 행동을 선언하고, 공개된 판정 결과와 다음 장면을 받는다. |
| GM | 행동을 해석하고, 판정을 요청하며, 확정 결과를 근거 기반으로 서술한다. |
| 게임 규칙 시스템 | 주사위, 수정치, 이점/불리, DC 비교, 피해와 상태 변경을 확정한다. |

## 4. Ubiquitous Language and Terminology

- **행동 선언(Action Declaration)**: 플레이어가 현재 차례에 하고자 하는 일을 자연어로 입력한 것.
- **판정 요청(Adjudication Request)**: GM이 행동에 대해 제안하는 판정 종류, 적용 능력치·기술, DC, 이점/불리 및 근거.
- **확정 판정(Resolved Check)**: 규칙 시스템이 난수와 캐릭터 수치를 적용해 만든 변경 불가 결과.
- **게임 상태(Game State)**: 캐릭터 자원, 인벤토리, 조건, 퀘스트, NPC 관계, 장면, 지도 등 게임 결과에 영향을 주는 확정 사실.
- **세션 요약(Session Summary)**: 오래된 대화에서 이후 서술에 필요한 사건만 압축한 기록. 게임 상태의 정본이 아니다.
- **컨텍스트 압축(Context Compaction)**: 모델 입력이 예산을 넘을 때 과거 대화를 세션 요약으로 바꾸는 과정.
- **근거(Evidence)**: 선택된 스토리북, 룰북, 시나리오 또는 확정 게임 상태의 추적 가능한 출처.

## 5. Core Use Cases

### UC-01 플레이어 행동 판정

1. 플레이어가 행동을 선언한다.
2. GM은 현재 상태와 근거를 보고 판정 불필요, 판정 필요, 또는 정보 부족을 결정한다.
3. 판정 필요 시 GM은 공개 판정 요청을 반환한다.
4. 시스템은 캐릭터 수치와 룰을 이용해 판정을 확정한다.
5. GM은 확정 결과와 근거만으로 결과를 서술하고, 다음 선택지를 제시한다.

### UC-02 판정 정보 공개

플레이어는 판정 전에 판정 종류, 능력치·기술, 수정치, 숙련, 이점/불리, DC, 룰 근거를 보고, 판정 뒤 d20 값과 최종값 및 성공·실패를 본다.

### UC-03 장기 세션 유지

시스템은 모든 원문 턴과 확정 게임 상태를 보존한다. GM 입력이 6,000 tokens를 넘으면 최근 6턴 원문은 남기고 더 오래된 대화를 세션 요약으로 압축한다. 현재 행동과 관련된 과거 사실은 상태와 검색 결과로 복구한다.

### UC-04 근거 부족 행동 처리

행동의 대상, 방법, 규칙 또는 효과가 불명확하면 GM은 가능한 범위의 낮은 위험 진행만 수행한다. 게임 효과가 있는 추정이나 임의 수치는 만들지 않는다. 보수적으로 진행할 수 없으면 필요한 정보를 질문한다.

## 6. Business Rules and Invariants

- BR-01: 주사위 난수, 보정치 계산, 성공 여부, 피해·회복·자원·조건 변경의 정본은 시스템이다. GM은 이를 확정하거나 변경하지 않는다.
- BR-02: 판정 정보는 플레이어에게 모두 공개한다. 비공개 DC는 사용하지 않는다.
- BR-03: 판정 요청은 적용 룰과 근거를 포함해야 한다.
- BR-04: 캐릭터 능력치, 숙련, HP, AC, 주문·자원, 인벤토리와 상태이상은 판정 시 최신 확정 상태를 사용한다.
- BR-05: GM은 감각·분위기·무해한 배경 묘사만 창작할 수 있다. 새 NPC, 적, 보상, 함정, 퀘스트, 전투 수치, 지도 사실은 근거 또는 확정 상태 없이는 만들 수 없다.
- BR-06: 게임 상태는 요약문으로만 보존하면 안 된다. 별도 정본 상태로 저장한다.
- BR-07: 원문 대화는 압축 뒤에도 보존·조회 가능해야 한다.
- BR-08: 세션 요약은 게임 상태를 덮어쓰지 않으며, 정본 상태와 충돌하면 정본 상태가 우선한다.
- BR-09: 압축은 모델 입력 예산이 6,000 tokens를 넘을 때만 실행한다. 최근 6턴 원문은 유지한다.

## 7. States and State Transitions

| Current State | Trigger | Next State |
| --- | --- | --- |
| 행동 대기 | 플레이어 행동 선언 | 행동 분석 |
| 행동 분석 | 판정 불필요 | 결과 서술 |
| 행동 분석 | 판정 필요 | 공개 판정 대기 |
| 행동 분석 | 보수 진행 불가 | 정보 요청 |
| 공개 판정 대기 | 시스템 굴림 확정 | 결과 서술 |
| 결과 서술 | 유효한 상태 변경 | 행동 대기 |
| 어느 상태 | 입력 예산 6,000 tokens 초과 | 컨텍스트 압축 후 기존 상태 복귀 |

## 8. Failures, Exceptions, and Boundary Conditions

- 캐릭터 상태 또는 룰 근거를 읽지 못하면 판정을 확정하지 않는다.
- GM이 근거 없는 게임 효과를 제안하면 거절하고 상태를 변경하지 않는다.
- 동일 행동 요청이 재시도되면 같은 판정·상태 변경이 중복 적용되지 않아야 한다.
- 압축 결과가 불완전하거나 충돌하면 원문과 정본 게임 상태를 기준으로 재구성한다.
- 모델 또는 검색 실패 시 시스템은 임의 결과를 만들지 않고 재시도 가능 오류를 돌려준다.

## 9. Inputs and Outputs

| Flow | Input | Output |
| --- | --- | --- |
| 행동 판정 | 행동 선언, 최신 캐릭터·게임 상태, 관련 근거 | 판정 불필요 서술 또는 공개 판정 요청 |
| 굴림 확정 | 판정 요청, 룰 수식, 캐릭터 수치 | d20, 수정치, 최종값, DC, 성공·실패, 상태 변경 |
| 결과 서술 | 확정 판정, 최신 상태, 근거 | 근거 기반 결과 서술과 다음 선택지 |
| 압축 | 오래된 원문 턴, 정본 게임 상태 | 세션 요약, 보존된 원문, 최근 6턴 |

## 10. Scope and Non-goals

포함: 단일 또는 파티 모험의 행동 판정, 자동 시스템 굴림, 투명한 판정 표시, 근거 기반 GM 서술, 상태 보존, 예산 기반 컨텍스트 압축.

제외: GM의 자유로운 캠페인 생성, 근거 없는 적·보상 생성, 실제 물리 주사위 인식, 인간 GM 협업 기능.

## 11. Priorities and Trade-offs

1. 규칙 정확성·상태 일관성
2. 근거 추적 가능성
3. 장기 세션 기억
4. 서술의 풍부함

근거 부족 상황에서는 끊김이나 질문을 허용한다. 자연스러운 서술을 위해 게임 사실을 추측하지 않는다.

## 12. Success Conditions and Acceptance Criteria

- AC-01: 판정이 필요한 행동은 시스템이 자동 굴림하고, GM 응답에 전체 계산과 룰 근거가 표시된다.
- AC-02: GM 응답이 판정·HP·인벤토리·조건을 임의 확정해도 시스템이 검증 전에는 상태가 바뀌지 않는다.
- AC-03: 긴 세션에서 입력 예산이 6,000 tokens를 넘으면 최근 6턴과 세션 요약으로 요청이 구성된다.
- AC-04: 압축 뒤에도 완료·진행 중 퀘스트, 자원, 인벤토리, 조건, NPC 관계 같은 확정 사실이 보존된다.
- AC-05: 근거 없는 새 게임 사실은 응답·상태 변경에서 차단된다.
