# 모험 진행 컨텍스트 개선 — Architecture Spec

> 설계 계약 정리 — 구현 및 성능 검증 전
>
> 계약 검토에서 남은 설계 반대 의견은 없다. 구현 동작과 전체 턴 5초 목표는 아직 검증되지 않았다. 별도의 Principle/Evidence 승인 자료는 생성하지 않았다. `D-01` 등은 문서 안의 추적 ID이지 공식 승인 기록이 아니다.

## 2. 도메인 흐름

### 2.1 도메인 흐름

Solo Player 요청 → 모험 실행 영역이 버전이 있는 현재 상태를 읽음 → 다섯 프롬프트 구역 구성 → Codex 실행 → 필요 시 읽기 전용 조회 → 실제 반환 근거로 인용 검증 → 기존 판정·굴림·저장 → `RevealFilter`(공개 정보 필터)가 허용 정보로 `PlayerVisibleTurn`(플레이어 공개 결과) 생성 → `TurnWriterPort`(서술 전용 연결)가 서술 생성 → 응답 → 확정된 오래된 대화의 비동기 압축.

### 2.2 명령

| 명령 | 요청자 | 입력 | 전제 | 결과 |
|---|---|---|---|---|
| GM 턴 진행 | Solo Player | 행동, 기존 요청 식별자 | 사용자·모험·턴 권한 유효 | 기존 진행·대기·확정 결과 |
| 추가 정보 조회 | Codex | 대상, 범주, 질문 | 활성 요청 및 서버가 확인한 버전 | 출처가 있는 조회 결과; 상태 변경 없음 |
| 시츄에이션 변경 제안 | Codex | 제안 식별자·버전·기존 항목 ID·허용 동작 | 기존 StoryRuntime 규칙 및 턴 검증 | 같은 턴 저장에 포함되거나 대기 상태로 보존 |

### 2.3–2.6 결과, 정책, 조회 자료, 외부 연동

새 도메인 이벤트나 저장소를 추가하지 않는다. 개념상 결과는 `턴 확정` 및 `시츄에이션 제안 적용`이며 별도 이벤트 타입을 뜻하지 않는다. 모험 실행 영역은 상태·턴을 소유한다. 기억과 대화 압축도 기존 모험 실행 영역의 기능과 저장소를 사용하며 별도 독립된 도메인 경계가 아니다. 자료 검색 영역 소유자는 기존 문서·검색·출처를 제공한다. Codex 이외 제공자는 변경하지 않는다.

선택 정보의 `NOT_FOUND`(찾을 수 없음)와 `UNAVAILABLE`(조회 불가)는 확인된 사실의 부재로 뭉뚱그리지 않고 선택 근거만 생략한다. 판정·비밀 공개에 필수인 근거의 실패·부재·버전 불일치는 기존 보류·재시도 경로로 보낸다. 압축은 응답 뒤 확정된 오래된 대화만 처리한다.

### 2.7 주요 설계 쟁점

| 쟁점 | 정리 |
|---|---|
| 조회 경계 | 모험 실행 영역 내부 기능으로 둔다. 새 서비스·모듈·장기 기억 DB를 만들지 않는다. (D-01) |
| 정보 선택 | 별도 언어 모델 사전 판단 없이 Codex가 같은 실행에서 직접 결정한다. (D-02) |
| 인용 검증 | 모델이 적은 출처를 신뢰하지 않고, 서버가 실제 반환한 자료만 기존 검증에 합친다. (D-03) |
| 시츄에이션 | 기존 규칙을 같은 턴의 검증·저장 흐름에 잇는다. 조회는 상태를 바꾸지 않는다. (D-04) |

## 3. 도메인 구조

### 3.1 도메인 경계와 경계 결정

| 기존 경계 | 소유 책임 | 이번 변경 |
|---|---|---|
| 모험 실행 영역 | 모험 상태·턴·NarrativeState(서사 상태)·기존 기억/압축 흐름 및 공개 검증 | 컨텍스트 구성, 읽기 전용 조회, 같은 턴 제안 적용 연결 |
| Codex 실행·요청 중계기 | 사용자 PC 실행, 활성 연결·요청 중계 | 도구 추가 및 실행 중 조회 근거 전달 |
| 자료 검색 영역 | 고정 자료·룰북 검색 및 출처 | 기존 검색 경로 재사용 |

새 독립된 도메인 경계나 배포 서비스를 만들 이유가 없다. 조회는 Adventure가 소유한 정본 상태와 같은 턴의 버전을 사용해야 하므로 약한 경계인 기존 내부 기능이면 충분하다. 요청 중계기 조회 근거는 활성 요청 안에서만 임시 보관한다.

### 3.2 경계 간 관계

모험 실행 영역은 Codex 실행 어댑터에 요청을 보내고, 요청 중계기가 사용자·연결·요청 범위를 확인한다. 요청 중계기는 서버 내부 조회 서버 경로를 호출한다. 검색은 자료 검색 영역의 기존 경로를 쓴다. 기억과 압축은 모험 실행 영역의 기존 경로를 쓴다. 새 소유 경계나 별도 번역 저장소는 두지 않는다.

### 3.3 기존 저장 경계

| 기존 저장 경계 | 책임 | 이번 변경의 제약 |
|---|---|---|
| Adventure | 기존 모험 상태와 검증된 변경 | StoryRuntime 규칙 적용은 기존 Adventure 저장 흐름에서 수행 |
| RuntimeTurn | 진행·굴림 대기·확정 계획 | 대기 중에는 제안을 보존하되 적용하지 않음 |
| NarrativeState(서사 상태) 저장소 | 세계 사실, 공개 사실, 인물 지식 등 기존 서사 상태 | GM 내부 조회 결과를 플레이어 응답에 직접 복사하지 않음 |

`StoryRuntimeState`(시츄에이션 실행 상태)는 Adventure 안의 기존 상태이며 독립 저장 경계의 기준 객체가 아니다.

### 3.4 자료형과 값 객체

| 자료형 | 책임 및 검증 |
|---|---|
| `SituationDefinition`(시츄에이션 정의) | 고정 시나리오 리비전의 목표·조건·사건·위협 참조. 시나리오 묶음/줄거리/단계/판본이 일치해야 함 |
| `ContextQuery` (추가 정보 조회 요청) | `target?`(대상), `kinds?`(종류), `question`(질문); 질문 1–1000자, 대상 최대 256자, 허용 범주 최대 8개 |
| `ContextEvidenceItem` (조회 근거 항목) | 종류·대상 ID·내용·`sourceRef`(출처 참조)·`sourceVersion`(출처 판본)·`playerVisible`(플레이어 공개 여부)·`citationKey`(인용 키, 선택) |
| 시츄에이션 제안 | 서버가 만든 제안 ID·버전, 허용 동작, 기존 항목 ID만 허용 |

관련 기억은 기존 LongTermAdventureFact(모험 장기 기록)과 RuntimeAddedFact(턴에서 추가된 확정 사실)를 사실 식별자 및 확정 턴 식별자로 연결한다. 현재 저장소가 제공하는 대상·장면·알려진 ID·명시적 텍스트를 활용해 정확히 일치하는 식별자를 먼저 고르고, 대상/주제 텍스트 일치 후 최근성으로 순서를 정한다. 사실 본문과 출처가 확인된 기록만 쓴다. 근거 없는 구조화 관계나 시츄에이션 외래 키를 있다고 가정하지 않는다.

### 3.5 규칙 소유권

| 기능/규칙 | 소유·적용 위치 |
|---|---|
| 최신 현재 상황·선택 시츄에이션 구성 | 기존 모험 실행 영역 애플리케이션 서비스 및 `StageArtifactRepository.findDetailedStage`(정확한 단계 자료 조회) |
| 활성화·종료·무효화 검증 | 기존 `StoryRuntimeRules`(시츄에이션 규칙) |
| 조회 읽기 전용 보장 | 내부 조회 기능; 쓰기 명령 미제공 |
| 공개 정보 판정 | 기존 `RevealFilter`와 `NarrativeState`가 공개 허용 사실을 판정하고 `PlayerVisibleTurn`을 만듦 |
| 플레이어 서술 | 기존 `TurnWriterPort`는 `PlayerVisibleTurn`만 받아 `WriterProse`를 생성 |
| 기억·요약 선택과 압축 | 모험 실행 영역의 기존 기억·압축 기능 |

### 3.6 상태 전이와 저장소 경계

| 현재 → 다음 | 보호 조건 및 저장 |
|---|---|
| 실행 중 → 굴림 대기 | 제안·버전을 기존 `PendingRuntimeState`(대기 턴 상태) 저장 형식에 저장; 시츄에이션은 아직 적용하지 않음 |
| 실행 중 → 확정 | 기존 Adventure 턴 저장 흐름에서 규칙 검증과 상태 변경 수행 |
| 굴림 대기 → 재개 | 기존 소유권·턴 ID·버전 확인 뒤 한 번만 적용 |
| 실행 중 → 실패/오래된 버전 | 혼합 버전 사용 금지; 기존 오류·재시도 |

`AdventureRepository`, `RuntimeTurnRepository`, `StageArtifactRepository`, `NarrativeState` 저장소와 기존 사실 조회 경계를 재사용한다. 실제 코드의 저장/복구는 기존 턴 저장 조정자 규칙을 따른다. 분산 저장의 전역 원자성을 주장하지 않는다.

## 4. 프로그램 설계

### 4.1 구성요소와 책임

| 기존 구성요소 | 변경 책임 | 금지 사항 |
|---|---|---|
| `RuntimeTurnApplicationService`(턴 애플리케이션 서비스), `GmAgentRuntimePlanningAdapter`(GM 계획 어댑터) | 상태 버전 고정, 컨텍스트·조회·제안 연결 | 모델 호출 중 데이터베이스 저장 트랜잭션 유지 |
| `GmContextEnvelope`(GM 컨텍스트 묶음), `RuntimeGmPromptComposer`(GM 프롬프트 구성기) | 기존 다섯 구역을 같은 순서로 구성 | 요약을 최신 상태 정본으로 사용 |
| `HttpTypedRuntimeGmAgentPort`(형식 검증 GM 연결) | 기본 근거와 서버 반환 근거를 합쳐 기존 인용 검증 | 출처 문자열이나 인용 검증 생략 신뢰 |
| `RevealFilter` / `DeterministicRevealFilter`(공개 정보 필터) | 확정 상태와 기존 공개 규칙으로 허용 정보만 `PlayerVisibleTurn`에 담음 | 언어 모델·검색 호출, 직접 응답 전송 |
| `TurnWriterPort` / `ScenarioRuntimeWriterAdapter`(플레이어 서술 연결) | 공개용 `PlayerVisibleTurn`만 서술로 바꿈 | 내부 계획·검색·비공개 대화 접근 |
| `McpStdioServer`(도구 통신 서버), `LocalCodexAiExecutionPort`(로컬 Codex 실행 연결), `CodexWebSocketAgent`(Codex 연결 어댑터) | 사용자 PC의 Codex 도구 계약·응답 중계 | 권한 범위 우회 |
| `AgentWebSocketHandler`(에이전트 연결 처리기), `LocalConnectionManager`(로컬 연결 관리자) | 활성 소유자·연결·요청 확인, 임시 근거 수집·정리 | 실행 범위의 장기 저장 |
| `GmCompletionRouter`(GM 완료 라우터), `RemoteAiExecutionPort`(원격 AI 실행 연결), `AiExecutionResult`(실행 결과) / `AiExecutionSuccess`(성공 응답), `TypedAgentContractController`(형식화된 에이전트 계약 제어기) | 신뢰 가능한 서버 조회 근거 전달 | 모델 텍스트와 서버 근거 정보 혼합 |
| 내부 조회 제어기/보조 기능 | 필요한 경우에만 제한된 읽기 기능 제공 | 게임 상태 변경 |

### 4.2 애플리케이션 흐름과 호출 계약

1. 턴 서비스가 서버 측 사용자/모험/세션/턴 및 `adventureVersion`·`bindingVersion`·`storyVersion` 및 시나리오 판본을 정한다.
2. `StoryRuntimeState.activeSituationId`가 있으면 `findDetailedStage`로 `scenarioPackageId`/`backboneRevision`/`stageId`/`detailedStageRevision`이 일치하는 고정 자료를 찾는다. 없으면 일반 현재 상황으로 진행한다. ID가 있으나 자료가 없거나 판본 불일치면 기존 오류/재시도 경로로 보내며 새 상황을 만들지 않는다.
3. 다섯 프롬프트 구역은 기존 순서로 유지한다: ① 지침·잠긴 자료 범위의 장면 개요, ② 현재 시츄에이션 관련 장기 기록, ③ 압축된 이전 대화, ④ 압축하지 않은 최근 대화, ⑤ 최신 캐릭터/현재 상황/턴 근거/플레이어 입력. 선택 시츄에이션과 목표·도전·조건·진행은 ⑤의 최신 정보에 포함한다. 필수 항목을 조용히 자르지 않는다.
4. Codex가 `query_context`(추가 정보 조회) 또는 기존 `search_rules`(룰북 검색 도구)를 같은 실행에서 호출한다. 두 도구의 반환 근거 모두 기존 인용 근거 대조에 전달한다.
5. 요청 중계기는 실제 서버 조회 결과를 활성 요청 안에 보관한다. 완료 시 모델 본문과 분리된 서버 간 결과 필드로 형식 검증 어댑터에 넘기고, 전달이 끝난 뒤 요청 자료를 정리한다. 텍스트 결과를 추리는 `requireFinalText`도 포함해 `AiExecutionResult`(실행 결과)/`AiExecutionSuccess`(성공 응답) 경로에서 부가 근거 정보가 유지되어야 한다.
6. 모험 실행 영역은 기본 근거와 서버가 실제 반환한 근거를 메모리에서 합쳐 인용을 검증한다. 검증된 계획과 서버 출처 근거를 포함한 묶음만 기존 `RuntimeTurn`(실행 턴)에 저장하며, 잘못된 계획은 저장하지 않는다. 사람이 굴림을 제출해야 하면 제안과 버전을 대기 자료에 보존하되 적용하지 않는다.
7. 기존 판정·굴림·공개·저장 절차를 따른다. 제안은 같은 저장 조정 흐름 안에서 검증한다.
8. 기존 `RevealFilter`는 확정된 관찰 결과, 엔진이 허가한 공개 사실, 인물에게 이미 알려진 맥락으로 `PlayerVisibleTurn`을 만든다.
9. 기존 `TurnWriterPort`는 `PlayerVisibleTurn`만 입력받아 플레이어 서술을 만든다. 내부 GM 계획, `narrationSeed`, `NarrativeContext`, 현재 장면의 비공개 맥락, 도구 대화·검색 자료를 입력으로 주지 않는다.
10. 관찰 결과가 없는 대화 응답도 공개 필터를 거친다. 서사 상태의 공개 규칙이 허용한 인물 정보만 제공하며, 필요한 공개 사실이 없으면 추측·창작으로 메우지 않고 기존 보류·재시도 규칙을 따른다. 굴림 대기 재개와 전투 서술도 같은 공개 필터를 통과한다.
11. 플레이어에게 엔진 허가와 서술 경계를 통과한 결과만 반환한다. 확정 뒤 오래된 대화 압축은 비동기 처리한다.

### 4.3 추가 조회 계약

도구 입력은 `{target?: string, kinds?: string[], question: string}`이며 각 필드는 대상·범주·질문을 뜻한다. 질문은 공백만일 수 없다. 결과는 기존 입력 예산 안에서 최대 30개 항목으로 제한하고, 예산 초과 선택 항목은 추가 결과가 있음을 알린다. 초과를 결과 없음으로 표현하지 않는다. 범주는 제품 명세의 장소공간·인물관계·사건진행·단서비밀·규칙판정·조우전투·아이템자원·과거기억을 허용한다. 범주가 없으면 알려진 식별자/용어를 정본에서 먼저 찾고, 이어 현재 세션에서 허용된 자료를 검색한다. 중간 언어 모델로 대상을 고르지 않는다. 모호하면 후보를 같은 GM에게 돌려주며 다른 모험의 임의 결과를 선택하지 않는다.

| 내부 응답 | 의미 |
|---|---|
| `FOUND`(발견) | 출처가 확인된 항목 반환 |
| `NOT_FOUND`(미발견) | 허용 범위에서 결과 없음 |
| `UNAVAILABLE`(조회 불가) | 조회 원천을 사용할 수 없음 |
| `STALE`(버전 불일치) | 실행 당시와 현재 판본 불일치 |

```json
{
  "scope": {
    "ownerId": "00000000-0000-0000-0000-000000000001",
    "adventureId": "00000000-0000-0000-0000-000000000002",
    "sessionId": "00000000-0000-0000-0000-000000000003",
    "turnId": "00000000-0000-0000-0000-000000000004",
    "executionId": "00000000-0000-0000-0000-000000000005",
    "scenarioPackageId": "00000000-0000-0000-0000-000000000006",
    "bindingVersion": 3, "adventureVersion": 8, "storyVersion": 2,
    "stageId": "00000000-0000-0000-0000-000000000007",
    "backboneRevision": 4, "detailedStageRevision": 6
  },
  "query": { "target": "선택 항목", "kinds": ["단서비밀"], "question": "확인할 내용" }
}
```

예시 JSON의 ID·판본 값은 형식 예시다. `StoryRuntimeState` 자체가 없는 기존 모험에서만 국면 참조를 생략한다. 활성 시츄에이션이 없어도 국면 상태가 있으면 `stageId`, `backboneRevision`, `detailedStageRevision`을 보낸다. 모든 `scope`(요청 권한 범위) 값은 요청 중계기와 서버가 정하고 Codex는 `query`(도구 조회 인자)만 제출한다. 내부 경로는 `POST /internal/runtime/context/query`이며 기존 내부 인증·권한 확인을 따른다. 응답은 `status`(조회 상태)와 `{kind,targetId,content,sourceRef,sourceVersion,playerVisible,citationKey?}` 목록이다. 읽기 전용이며 동일 실행의 반복 질의는 기존 실행 안에서 재사용할 수 있다.

### 4.4 오류 전달과 의존성

잘못된 질문·권한·범위는 거부한다. 선택 근거의 부재/장애는 선택적으로 생략한다. 필수 근거 실패는 판정·공개·확정을 보류한다. 같은 인용 키에 다른 출처/판본이 들어오면 덮어쓰지 않고 오류로 처리한다. 기존 AI 실행 및 복구 한도를 유지하며 새 무한 재시도나 5초 강제 중단을 만들지 않는다. 구형 사용자 PC 실행 프로그램이 새 조회 도구를 지원하지 않으면 명시적으로 실패시키는 것이 구현 제안이다. 기존의 큰 컨텍스트 전송 경로로 조용히 돌아가는 동작은 허용하지 않으며, 최종 아키텍처 검토가 남아 있다.

의존 방향은 모험 실행 영역 → 기존 저장소/AI 실행 연결, 요청 중계기 → 내부 조회 서버 경로 및 기존 자료 검색 영역의 검색, Codex 실행 프로그램 → 요청 중계기 도구 계약이다. 공개 필터만 `PlayerVisibleTurn`을 만들고 서술 어댑터는 이 형식만 받는다. 조회 기능은 저장/공개 명령에 의존하지 않는다. Codex 이외 AI 제공자의 요청·근거·응답 계약은 변경하지 않는다.

## 5. 기술 구조

### 5.1 경계와 통신

새 서비스·모듈 없이 기존 `adventure-service`, 사용자 PC Codex, 요청 중계기, AI 실행 어댑터를 사용한다. 요청 중계기에서 모험 실행 내부 서버 경로로 동기 웹 요청 조회를 추가한다. 그 호출은 전체 5초 목표를 측정하지만 새 5초 timeout을 뜻하지 않는다. `search_rules`는 호환 유지한다.

### 5.2 데이터와 저장 형식

| 데이터 | 소유자·저장 | 변경 |
|---|---|---|
| Adventure, `CurrentSituation`(현재 상황), story 상태 | 모험 실행 영역 기존 저장 | 새 정본 없음 |
| NarrativeState | 기존 전용 저장소 | 기존 공개/지식 규칙 재사용 |
| 장기 기록·대화 요약 | 모험 실행 영역의 기존 기억·압축 기능 | 저장소 통합 없음 |
| 실행 중 조회 근거 | 요청 중계기 활성 요청 메모리; 신뢰 전달 뒤 요청 종료 시 정리 | 영속 저장소 없음 |
| pending 제안 | 기존 RuntimeTurn의 `PendingRuntimeState`(대기 턴 상태) 저장 형식 | 선택적 proposal/version 필드 추가, 구 행은 없음으로 해석 |

조회 결과의 출처·버전은 요청 중계기에서 형식 검증 결과까지 신뢰 부가 근거 정보로 유지한다. 모험 실행 영역은 판정/확정 전에 완전한 선택 근거 묶음을 기존 RuntimeTurn에 보존한다. 직렬화 방식으로 처리 가능하면 데이터베이스 migration은 추가하지 않는다.

### 5.3 일관성과 기반 구성

상태·자료 판본·연결 설정 버전을 조회와 저장 확정에서 확인한다. 불일치 시 혼합 버전으로 진행하지 않고 기존 재시도/충돌 처리를 따른다. 데이터베이스 저장 트랜잭션은 저장 경계에서만 열고 모델·네트워크 대기 동안 유지하지 않는다. 한 턴의 상태와 제안은 기존 Adventure 저장·기존 단계별 복구 흐름에서 함께 처리하며 분산 전역 원자성을 가정하지 않는다.

### 5.4 파일 변경 범위

| 기존 경로/구성요소 | 변경 목적 |
|---|---|
| `RuntimeTurnApplicationService`(턴 애플리케이션 서비스), `GmAgentRuntimePlanningAdapter`(GM 계획 어댑터), `RuntimeGmPromptComposer`(GM 프롬프트 구성기) | 최신 시츄에이션·다섯 구역 구성, `narration` 직접 반환 우회 제거 |
| `RuntimePlanningRequest`(계획 요청), `GmContextEnvelope`(GM 컨텍스트 묶음), `RuntimePlanningResult`(계획 결과), `HttpTypedRuntimeGmAgentPort`(형식 검증 GM 연결) | 실행 입력, 결과 및 출처 검증 연결 |
| `PendingRuntimeState`(대기 턴 상태), Adventure, `PostgresRuntimeTurnRepository`(턴 저장소) | 대기 제안과 동일 턴 저장 연결 |
| `RevealFilter`, `DeterministicRevealFilter`, `PlayerVisibleTurn`, `TurnWriterPort`, `ScenarioRuntimeWriterAdapter` | 공개 필터에서 서술 전용 어댑터로 이어지는 기존 경계를 재사용하고 내부 서술 경로를 차단 |
| `McpStdioServer`(도구 통신 서버), `LocalCodexAiExecutionPort`(로컬 Codex 실행 연결), `CodexWebSocketAgent`(Codex 연결 어댑터) | 새 조회 도구와 결과 전달 |
| `AgentWebSocketHandler`(에이전트 연결 처리기), `LocalConnectionManager`(로컬 연결 관리자), `HttpRagToolSearch`(HTTP 자료 검색 어댑터), `RelayExecutionResult`(중계 실행 결과) | 활성 요청 권한, 임시 근거 수집·전달·정리 |
| `GmCompletionRouter`(GM 완료 라우터), `RemoteAiExecutionPort`(원격 AI 실행 연결), `AiExecutionResult`(실행 결과)/`AiExecutionSuccess`(성공 응답), `TypedAgentContractController`(형식화된 에이전트 계약 제어기) | 텍스트 최종화 과정에서도 서버 부가 근거 정보를 보존 |
| 내부 조회 제어기/보조 기능 | 기존 클래스에서 분리 필요할 때만 제한적으로 추가 |

표의 package 경로 생략은 새 식별자 제안이 아니다. 기존 런타임 사실 조회는 재사용하되 모든 기존 호출의 의미를 전역 변경하지 않는다.

## 6. 실행 설계

요청 접수부터 응답까지 상태 준비, 모델 실행, 도구 왕복, 검증, 저장을 같은 턴으로 추적한다. 사람의 굴림 대기는 제품 측정 범위에서 제외한다. 동시 턴·순서·요청 중복은 기존 모험·turn ID 및 버전 규칙에 맡긴다. 요청 중계기 근거는 한 활성 실행에만 귀속하고 전달 후, 취소·연결 종료 시 정리한다. 재시작 뒤 저장되지 않은 계획을 이어 쓰지 않고 최신 상태로 재시도한다.

## 7. 오류 처리와 복구

선택 조회가 실패하면 확인된 정보만으로 진행한다. 필수 근거, 불일치 상태, 인용 충돌은 판정·공개·확정을 막고 기존 최종 오류/재시도를 따른다. 굴림 대기 상태의 제안은 기존 pending 저장 형식에서 재개 시 버전과 소유권을 재검증한다. 압축 실패는 유효한 요약과 원문 대화를 보존하며 응답을 막지 않는다. 별도 선행 시츄에이션 저장이나 새 보상 흐름을 추가하지 않는다.

## 8. 보안

### 8.1 인증·권한·입력 검증

기존 내부 서비스 인증을 쓴다. 요청 중계기 및 서버는 활성 사용자·연결·요청과 adventure/session/turn/package/연결 설정/state 버전을 확인한다. 도구 인자에서 사용자·모험·문서·세션·버전을 지정하거나 권한 범위를 바꿀 수 없다. 질문은 1–1000자, 대상은 256자 이하, 허용된 종류는 최대 8개다.

### 8.2 민감 정보

GM 전용 도구 대화와 내부 출처 부가 정보는 플레이어 서버 응답·기록·진단 로그에 보내지 않는다. 읽기 권한이 있는 GM은 비공개 자료를 가시성·출처 표시와 함께 받을 수 있다. 플레이어 서술은 기존 공개 필터가 만든 `PlayerVisibleTurn`(플레이어 공개 결과)만 입력으로 받는다. 공개 필터는 확정된 관찰 결과·허가된 사실·인물에게 알려진 맥락만 담는다. 서술 연결과 `NarrativeContext`에는 내부 GM 계획·대화·도구 권한을 주지 않는다. 실패한 공개와 아직 공개되지 않은 사실의 바꿔 말하기를 허용하지 않는다.

기존 아키텍처에는 [공개 정보 필터 아키텍처](../runtime-reveal-filter/architecture-spec.md)에 정의된 공개 전용 서술 경계가 있다. 다만 현재 확인된 구현은 `ScenarioRuntimeWriterAdapter`가 `visibleFacts`가 비었을 때 `narrationSeed`를 그대로 전달하고, `RuntimeTurnApplicationService`가 계획의 `narration`을 seed로 넘긴다. 일부 로컬 presentation 경로(응답 표시 경로)는 서술 어댑터 대신 계획의 `narration`을 직접 반환한다. 이 우회와 seed 전달을 기존 공개 필터 및 `TurnWriterPort`로 연결한다.

이 변경은 별도 서술 언어 모델을 새로 결정하는 것이 아니다. 기존 `TurnWriterPort` 경계를 재사용하며, 그 어댑터의 기존 구현이 언어 모델을 호출하는지는 구현 세부로 둔다. 언어 모델을 호출하더라도 계획 실행의 대화·도구 권한·비공개 근거를 이어받지 않고, 공개 자료만 새 입력으로 제공한다. 전체 5초 목표 측정에는 계획·조회·검증·저장·서술을 모두 포함한다. 공개 결과가 비어 있으면 `narrationSeed`나 내부 GM 문장을 대체 입력으로 넘기지 않는다. 단순 문자열 포함 검사는 바꿔 말하기 방지의 증거가 아니므로, 엔진 공개 결과와 대화 상대 반응·굴림 대기·전투 응답 경로를 검증한다. 별도 안전 판정 언어 모델은 추가하지 않는다.

## 9. 관측

로그·추적 기록에는 요청/턴 ID, 단계 시간, 버전 불일치, 재시도와 오류 종류를 남기되 비밀 본문·전체 도구 대화·비밀 값은 남기지 않는다. 성공한 전체 턴의 지연, 준비·모델·도구 왕복·검증·저장 시간, 입력 바이트 수, 조회 호출 회수와 재시도 수를 측정한다. 5초 초과 성공도 포함하고 대화 압축은 별도로 잰다. 동시 요청 수나 새 성능 보증은 추정하지 않는다.

## 10. 변경 경계

허용: Codex의 기본 정보 구성·추가 조회·근거 전달, 모험 실행 영역의 읽기 기능, 기존 턴 저장에 제안 연결, 비공개 공개용 결과 검증 및 단계별 측정.

금지: 별도 조회 언어 모델, 서비스/모듈/기억 DB 신설, 전체 시나리오 제공, 도구 조회에 의한 상태 변경, 모델 출처만 신뢰, 인용/공개 검증 완화, Codex 외 AI 제공자 변경, 5초 초과 즉시 종료 또는 느린 성공의 측정 제외.

조건부: 내부 제어기/보조 기능는 기존 클래스에 제한 책임을 둘 수 없을 때만 추가. 저장 형식 확장이 불가능한 경우에만 저장소 변경을 재검토. 문서 검색 대체 경로은 기존 권한 및 고정된 세션 자료 범위일 때만 허용.

## 11. 검증 요구사항

### 11.1 도메인과 프로그램

선택 시츄에이션 있음/없음/불일치, 정확한 단계 판본, 현재 상황과 시츄에이션 구분, 관련 오래된 기억과 최근 무관 기억, 목표·조건 포함 여부, 조회의 읽기 전용, 조회 결과의 실제 출처만 인용 가능 여부를 확인한다.

### 11.2 기술 계약·실행·복구

조회 인자 제한·내부 인증·교차 사용자/모험 차단·권한 범위 변조 거부·`NOT_FOUND`와 `UNAVAILABLE` 구분·오래된 Codex 도구 지원 실패를 확인한다. 필수 조회 실패, 연결 종료, 버전 변경, 인용 충돌, 굴림 대기/재개, 중복 저장 확정, 압축 실패도 확인한다. 실제 Codex가 있는 동일 작업 사본에서 단순 대화, 오래된 기억, 룰북 검색, 장면 단서, 전투 서술을 실행하고 전체 및 단계 시간을 기록한다. 테스트는 구현 후 수행한다.

### 11.3 독립 검토 기준

플레이어 공개 결과에는 엔진이 허가한 정보만 포함한다. 동적 비밀의 바꿔 말하기·NPC 대사 누출을 확인한다. 다른 AI 제공자는 기존 입력·근거·응답 동작과 비교한다. 전체 5초 목표는 실측 전 달성으로 표시하지 않으며 시험 환경·모델·자료·동시 요청 수를 함께 기록한다.

## 12. 대안과 절충

| 대안 | 선택 | 이유/비용 |
|---|---|---|
| 별도 서비스·모듈·장기 기억 DB | 사용 안 함 | 같은 상태 소유와 턴 일관성이 필요하며 독립 수명 주기의 근거가 없음. 기존 경로 통합 비용은 남음 |
| 매 턴 전체 시나리오 | 사용 안 함 | 입력과 미래 비밀 노출을 줄이고 현재 필요 자료만 제공 |
| 사전 언어 모델 사전 선택기 | 사용 안 함 | 별도 호출 없이 GM이 같은 실행에서 조회 결정 |
| 모델이 쓴 출처를 신뢰하거나 인용 검증 제거 | 사용 안 함 | 실제 서버 조회 결과를 전달하는 연결을 추가해야 함 |
| 시츄에이션 별도 선행 저장 | 사용 안 함 | 굴림 대기와 턴 저장에서 부분 적용을 막기 위해 같은 저장 흐름에 연결 |
| Codex 이외 제공자까지 변경 | 사용 안 함 | 제품 범위에서 제외; 기존 경로의 동작 회귀만 확인 |

## 13. 위험과 미해결 항목

### 13.1 위험

| 위험 | 대응/상태 |
|---|---|
| 5초 전체 턴 목표 미실측 | 구현 후 전체 실행 측정; 측정 전 달성 주장 금지 |
| 오래된 기억의 구조화 관련성 부족 | 현재 제공하는 ID·대상·장면·텍스트·최근성만 사용; 관련성 선택 품질 검증 필요 |
| 요청 중계기 결과가 `requireFinalText` 또는 성공 응답 변환에서 유실 | `AiExecutionResult`(실행 결과)/`AiExecutionSuccess`(성공 응답) 전 경로 부가 근거 정보 보존 검토 필요 |
| 내부 계획이 서술 연결을 우회하거나 `narrationSeed`로 전달됨 | 기존 공개 전용 서술 경계를 재사용하고 두 우회를 제거; 바꿔 말하기 누출 검증은 아직 실행 전 |
| 오래된 Codex 도구 계약 | 새 도구 미지원 시 명시적 실패; 구현 동작 검증 필요 |

### 13.2 검증 대기 항목

추가로 결정해야 할 설계 쟁점은 남아 있지 않다. 구현 시 `requireFinalText`를 지나 부가 근거 정보가 형식 검증 어댑터까지 유지되는지, relay가 신뢰 자료 전달 전에 조회 근거를 지우지 않는지 확인한다. 동적 비공개 정보의 바꿔 말하기 누출과 전체 턴 5초 목표도 구현 후 실측·검증한다. 시험 환경과 동시 요청 수는 아직 정해지지 않았다. 기존 장애 재시도·종료 정책을 보존하며 새 무한 재시도는 도입하지 않는다.
