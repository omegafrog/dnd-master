# Product Spec: hybrid-rag-evidence-selection

## 1. **Problem and Context**

현재 근거 검색은 Dense 검색만 사용하므로 단어가 정확히 일치하는 근거를 놓칠 수 있다. 그 결과 AI Game Master가 실제 모험 준비·진행 중 필요한 룰북·시나리오 사실을 충분히 확보하지 못할 수 있다.

이 변경은 실제 모험 준비·진행의 모든 근거 검색에 Dense 검색과 BM25 검색을 함께 적용하고, Dense 단독 기준선보다 검색·선택 품질을 개선한다. RULEBOOK과 STORYBOOK을 모두 대상으로 하며, 문서 등록·추출·관리자 목록 조회는 대상이 아니다.

## 2. **Goals and Desired Outcomes**

- Dense와 BM25의 후보를 함께 활용해 의미 유사도와 단어 일치에 강한 근거를 모두 확보한다. (G-HR-001)
- 충분한 근거를 가능한 한 작은 조합으로 선택해 AI Game Master가 새 룰북·시나리오 사실을 만들지 않고 다음 결과를 결정하게 한다. (G-HR-002)
- 검색·판정 실패를 일관되게 처리하고, 근거 부족 시 추가 검색과 제한된 임시 판정을 명확히 구분한다. (G-HR-003)
- 기존 평가 데이터와 지표로 Dense 단독 기준선 대비 주요 검색 품질 지표 개선을 확인한다. (G-HR-004)
- 실제 모험 준비·진행의 모든 관련 상황에서 같은 검색·판단 흐름을 적용하되, 상황별 충분함과 최종 부족 결과를 구분한다. (G-HR-005)

## 3. **Users and Actors**

- **Solo Player**: 최종 판정 결과와 근거 부족 시 임시 판정임을 확인한다.
- **AI Game Master**: 현재 게임 상태와 검색 근거를 사용해 다음 결과를 결정한다.
- **Document Knowledge 검색 시스템**: 세션에 고정된 문서를 검색하고 후보를 통합·재정렬하며 근거 충분성을 판단하도록 지원한다.
- **근거 소비 흐름**: 플레이어 행동 판정, 시나리오 준비, 시작 장면 구성, 규칙 안내가 선택된 근거와 정책별 결과를 소비한다. 모두 AI Game Master 또는 시스템의 기존 흐름이며 별도 인간 역할은 아니다.

## 4. **Ubiquitous Language and Terminology**

- **복합 검색**: Dense 검색과 BM25 검색에서 각각 최대 30개 후보를 얻고, 같은 청크를 합친 뒤 RRF로 통합 순위를 만드는 절차.
- **관련도 재정렬**: 복합 검색 후보를 판정 질문과의 관련도 순서로 다시 정렬하는 단계. 점수로 제거하지 않는다.
- **근거 충분성 판단**: 선택된 정책의 작업 맥락과 목표를 후보 근거만으로 충족할 수 있는지 판단하고, 가능한 한 작은 근거 조합을 선택하는 단계.
- **최소 충분 근거 묶음**: 근거 충분성 판단이 선택한, 판정에 필요한 가장 작은 근거 조합. 고정 개수나 순위 앞부분으로 제한하지 않는다.
- **임시 판정**: 플레이어 행동 판정 정책에서 추가 검색을 모두 수행해도 근거가 부족할 때, 확보한 근거와 현재 게임 상태만으로 제한해 내리는 판정. 룰북·시나리오 사실을 새로 만들지 않는다.
- **세션에 고정된 문서**: 해당 세션의 Session Knowledge Set에 속한 문서. 검색은 이 범위를 벗어나지 않는다.

## 5. **Core Use Cases**

### UC-HR-001 근거 검색 및 충분성 판단

**주요 행위자**: AI Game Master, Document Knowledge 검색 시스템

**시작**: AI Game Master가 현재 게임 상태와 질의로 근거 검색을 요청한다.

**기본 흐름**

1. 선택된 상황별 정책이 세션에 고정된 문서 중 검색 대상 문서 유형을 정한다. 시나리오 전용 작업은 STORYBOOK, 규칙 전용 작업은 RULEBOOK, 둘 다 필요한 플레이어 행동 등은 두 유형을 검색한다. 시나리오 검색에서는 활성 원문 위치 우선 규칙을 유지한다.
2. Dense에서 최대 30개, BM25에서 최대 30개 후보를 검색한다.
3. 같은 청크를 하나로 병합하고 RRF로 통합 순위를 만든다. 고유 후보는 최대 60개이며, 후보가 부족하면 추가 채움 검색 없이 있는 만큼 진행한다.
4. 최초 RRF 결과 전체를 관련도 재정렬에 전달한다. Dense·BM25·RRF·관련도 재정렬에는 문서 유형 가중치나 고정 할당을 추가하지 않으며, 재정렬은 점수 threshold로 제거하지 않고 순위만 정해 상위 30개를 근거 충분성 판단에 전달한다.
5. 근거 충분성 판단은 선택된 정책의 작업 맥락과 목표를 후보 근거만으로 충족할 수 있는지 판단한다. 충분하면 유효한 최소 충분 근거 묶음과 `sufficient`를 반환한다.
6. 부족하면 이미 유효한 `selectedEvidenceIds`를 유지하고 `missing`을 반환한다. missing으로 추가 복합 검색을 수행하고, 이전 전체 후보와 새 후보를 중복 제거해 합친 뒤 전체를 다시 관련도 재정렬한다.
7. 재정렬 상위 결과로 남은 자리를 채워 총 최대 30개를 다시 판단한다. 추가 검색은 최대 2회 수행한다.
8. 그래도 부족하면 선택된 정책의 최종 부족 결과를 반환한다. 플레이어 행동 판정 정책인 경우에만 확보한 근거와 현재 게임 상태로 제한된 임시 판정을 내리고, 플레이어에게 근거 부족과 임시 판정임을 표시한다.

**종료**: 충분한 근거에 따른 결과, 정상 빈 결과, 전체 요청 오류, 또는 선택된 정책의 최종 부족 결과가 반환된다.

### UC-HR-002 검색 실패 및 재시도 처리

Dense, BM25, 관련도 재정렬 실행 오류는 해당 단계에서 1회 재시도한다. 재시도도 실패하면 전체 검색 오류를 반환하며 한 검색 방식만으로 부분 진행하지 않는다. 근거 충분성 판단 실행 오류 또는 잘못된 출력 형식도 1회 재시도 후 전체 요청 오류로 종료하며 자율 판정으로 우회하지 않는다.

### UC-HR-003 상황별 근거 충분성 판단 정책

**공통 흐름**: 모든 실제 모험 준비·진행 검색은 Dense와 BM25 후보를 RRF로 통합하고 관련도 재정렬한 뒤, 1회 Judge 호출에서 근거 선택과 불필요성 판단을 함께 수행한다. 선택 결과를 신뢰하며 가능한 부분집합마다 운영 재호출하지 않는다. 출력은 `sufficient`, `selectedEvidenceIds`, `selectionReasons`, `missing`이다. `selectionReasons`는 선택된 각 근거에 필수이며, `necessity`와 `useThroughRank`는 사용하지 않는다.

**정책별 충분함과 최종 부족 결과**

1. **플레이어 행동 판정**: 현재 게임 상태와 근거로 다음 결과를 판정할 수 있으면 충분하다. 추가 검색 최대 2회 후에도 부족하면 제한된 임시 판정을 내린다.
2. **시나리오 준비**: 원문을 추측하지 않고 구조화 후보를 생성할 수 있으면 충분하다. 부족하면 기존 `PARTIAL` 또는 `INVALID` 후보와 누락 정보를 반환하며 자율 보완하지 않는다.
3. **시작 장면**: 고정 모험 계획과 근거로 시작 상황을 생성할 수 있으면 충분하다. 시나리오 자료 기반 모험은 최종 부족 시 시작 준비 실패다. Rulebook-Only Bundle은 기존 Adventure Brief와 Adventure Story Plan에 따른 AI 생성을 허용한다.
4. **규칙 안내**: 선택 근거와 인용만으로 답변할 수 있으면 충분하다. 부족하면 근거 부족 응답을 반환하며 자율 규칙을 생성하지 않는다.

네 정책 모두 추가 검색, 후보 병합, 선택 근거 고정, 추가 검색 최대 2회 규칙을 적용한다.

## 6. **Business Rules and Invariants**

- BR-HR-001: Dense용 색인과 BM25용 색인이 모두 완료된 문서만 검색 가능하다. 하나라도 실패한 문서는 기존 문서 처리 실패 규칙을 따르며 불완전 색인은 검색에서 제외한다.
- BR-HR-002: 최초 검색은 Dense 최대 30개와 BM25 최대 30개를 사용하고, RRF 통합 뒤 고유 후보는 최대 60개다.
- BR-HR-003: 후보 부족은 정상 결과이며 추가 채움 검색을 하지 않는다.
- BR-HR-004: 최초 RRF 결과 전체를 관련도 재정렬에 전달하고, 재정렬은 점수 threshold로 후보를 제거하지 않는다.
- BR-HR-005: 근거 충분성 판단의 관련도 순위는 읽기 우선순위일 뿐 선택 계약이 아니다. 임의 부분집합 중 가능한 한 작은 충분한 조합을 선택한다.
- BR-HR-006: `sufficient`, `selectedEvidenceIds`, `selectionReasons`, `missing`을 사용한다. `insufficient`에서도 유효한 선택 근거·선택 이유와 missing을 반환하며 `necessity`와 `useThroughRank`는 사용하지 않는다.
- BR-HR-007: 추가 검색 시 이전 판단에서 선택된 유효 근거는 반드시 유지하고, 새 전체 후보에서 중복을 제거한 뒤 최대 30개를 다시 판단한다.
- BR-HR-008: 최종 후보가 0개여도 정상 빈 결과다. 1~29개면 있는 만큼 반환·진행한다. 후보 없음·부족은 추적 기록한다.
- BR-HR-009: 상황별 정책이 세션에 고정된 문서 중 검색 대상 문서 유형을 선택한다. 시나리오 전용 작업은 STORYBOOK, 규칙 전용 작업은 RULEBOOK, 둘 다 필요한 플레이어 행동 등은 두 유형을 검색한다. 검색 단계에는 문서 유형 가중치·고정 할당을 적용하지 않으며, 시나리오 검색의 활성 원문 위치 우선 규칙은 유지한다. 최종 필요 조합은 상황별 근거 충분성 정책이 선택하고, 최종 근거에는 원문 위치와 문서 유형을 유지한다.
- BR-HR-010: 원문 질의와 청크 본문은 추적 로그에 기록하지 않는다.
- BR-HR-011: 모든 실제 모험 준비·진행 검색은 Dense+BM25→RRF→관련도 재정렬을 공통 적용한다.
- BR-HR-012: 근거 충분성 판단은 모든 관련 상황에 전략 패턴으로 적용하며, 1회 Judge 호출에서 선택과 불필요성 판단을 함께 수행한다. 선택된 각 근거에는 `selectionReasons`가 있어야 한다.
- BR-HR-013: 공통 판단 출력은 `sufficient`, `selectedEvidenceIds`, `selectionReasons`, `missing`이며 `necessity`와 `useThroughRank`는 없다.
- BR-HR-014: 네 상황별 정책은 각자의 충분함 기준과 최종 부족 결과를 사용한다. 추가 검색·후보 병합·선택 근거 고정·최대 2회 규칙은 공통이다.
- BR-HR-015: `selectionReasons` 원문은 운영 로그에 기록하지 않는다. 선택 이유의 존재 여부와 선택 ID만 기록한다.
- BR-HR-016: 오프라인 평가에서는 선택 근거를 하나씩 제거해 최소성과 중복을 검증한다. 운영에서는 선택과 불필요성 판단을 위해 부분집합별 재호출을 하지 않는다.

## 7. **States and State Transitions**

독립적인 장기 업무 상태 lifecycle은 없다. 검색 요청 내부에 다음 순차 흐름과 실패·재시도만 존재한다.

`검색 요청 → Dense/BM25 검색 → 후보 병합·RRF → 관련도 재정렬 → 근거 충분성 판단 → (충분: 결과 반환 / 부족: 추가 검색 최대 2회 후 재판단 / 최종 부족: 선택 정책별 결과)`. 각 단계 오류는 정의된 1회 재시도 후 전체 요청 오류로 전환된다.

업무 상태 다이어그램: 해당 없음 — 독립적인 장기 업무 상태가 없고 요청 내부 처리 흐름만 변경된다.

## 8. **Failures, Exceptions, and Boundary Conditions**

- 색인 하나라도 실패하거나 불완전하면 문서를 검색하지 않고 기존 문서 처리 실패 규칙을 적용한다.
- Dense, BM25, 관련도 재정렬은 단계별 1회 재시도한다. 재실패 시 부분 검색 없이 전체 검색 오류다.
- 후보 0개, 후보 부족, 추가 검색 후에도 부족한 경우는 오류가 아니다. 각각 정상 빈 결과·있는 만큼 진행·선택 정책별 최종 부족 결과로 처리한다.
- 근거 충분성 판단 오류나 출력 형식 오류는 1회 재시도 후 전체 요청 오류이며 임시 판정으로 우회하지 않는다.
- 추가 검색은 최대 2회다. 이후 최종 부족 결과는 선택 정책에 따른다. 플레이어 행동 판정의 임시 판정은 확보된 근거와 현재 게임 상태에 한정하고 새 룰북·시나리오 사실을 만들지 않는다.
- 시나리오 준비 부족 시 기존 `PARTIAL` 또는 `INVALID` 후보와 누락 정보를 반환하고 자율 보완하지 않는다. 시나리오 자료 기반 시작 장면 부족은 시작 준비 실패이며, Rulebook-Only Bundle의 기존 Adventure Brief·Adventure Story Plan에 따른 AI 생성은 허용한다.
- 규칙 안내 부족은 근거 부족 응답으로 종료하며 자율 규칙 생성을 하지 않는다.

## 9. **Inputs and Outputs**

**입력**

- 검색 요청 식별자, 세션 식별자, 대상 문서 식별자
- 원문 질의와 정책별 작업 맥락(플레이어 행동 판정은 현재 게임 상태, 그 외에는 시나리오 준비·시작 장면·규칙 안내에 필요한 입력)
- Query Intent(`RULE`, `STORY`, `MIXED`, `UNKNOWN`)와 상황별 정책이 정한 검색 대상 문서 유형
- 세션에 고정된 문서 범위와 문서 유형 메타데이터

**출력**

- 충분성 결과(`sufficient` 또는 `insufficient`)
- `selectedEvidenceIds`, `missing`
- 최종 선택 청크의 본문, 원문 위치, 문서 유형
- 임시 판정 여부와 플레이어에게 표시할 근거 부족 안내
- 상황별 최종 부족 결과(제한된 임시 판정, 기존 `PARTIAL`/`INVALID` 후보, 시작 준비 실패, 근거 부족 응답)

**추적 정보**

검색 요청·세션·대상 문서 식별자, Dense/BM25 후보 수, 중복 제거 수, 관련도 재정렬 입력·출력 수, 단계별 시간, 재시도·오류 원인, 최종 선택 청크 ID, 충분성 결과, missing, 추가 검색 횟수·질의·후보 수, 임시 판정 근거를 기록한다. `selectionReasons`는 존재 여부와 선택 ID만 기록하고 원문은 기록하지 않는다. 원문 질의와 청크 본문도 기록하지 않는다.

## 10. **Scope and Non-goals**

**범위**

- 실제 모험 준비·진행의 RULEBOOK/STORYBOOK 근거 검색
- Dense와 BM25 복합 검색, RRF 통합, 관련도 재정렬, 근거 충분성 판단, 추가 검색, 임시 판정 표시와 추적
- 기존 평가 데이터·지표를 사용한 Dense 단독 기준선 비교
- 플레이어 행동 판정·시나리오 준비·시작 장면·규칙 안내의 상황별 근거 충분성 판단

**비목표**

- 문서 등록·추출·관리자 목록 조회
- 고정 근거 슬롯 수
- 관련도 재정렬 점수 threshold
- FACT/RULE/PROCEDURE 같은 고정 역할 enum
- Resolution 사전 컴파일·저장
- 이전 미선택 후보의 무조건 보존

## 11. **Priorities and Trade-offs**

1. 세션 문서 범위, 정책별 검색 대상 문서 유형, 원문 위치·문서 유형 보존, 그리고 룰북·시나리오 사실을 만들지 않는 근거 충실성을 최우선으로 한다.
2. Dense와 BM25 모두의 정상 결과를 활용하되, 한 방식의 오류를 숨긴 부분 진행은 허용하지 않는다.
3. 충분성 판단에서는 관련도 순위보다 판정에 유효한 최소 충분 근거 묶음을 우선한다.
4. 후보 부족은 있는 만큼 처리해 정상 응답성을 유지하고, 추가 검색은 최대 2회로 제한한다.
5. 품질 합격은 기존 평가 데이터·지표로 Dense 단독 기준선 대비 주요 검색 품질 지표가 개선되고 다른 품질 지표가 허용 오차 밖으로 하락하지 않는 것이다. 응답 시간은 기록하지만 이번 합격 차단 기준은 아니다. 정확한 지표와 허용 오차는 Architecture에서 현재 평가 코드로 구체화한다.
6. Recall@5는 Dense 기준선보다 반드시 개선한다. MRR·근거 회수율·NDCG@5는 기준선 대비 1%p를 초과해 하락하지 않는다. Evidence Sufficiency Accuracy, Evidence Redundancy Rate, Average Evidence Pack Size, Missing Evidence Rate는 첫 구현에서 측정·보고만 하며, 구현 후 고정 평가와 실제 모험 E2E 결과를 사용해 구체 차단값을 사용자와 별도 확정한다. 응답 시간의 구체값도 이번 범위에서 정하지 않고 구현 후 실측으로 결정한다.

## 12. **Success Conditions and Acceptance Criteria**

- AC-HR-001 (BR-HR-001): Dense와 BM25 색인이 모두 완료된 문서만 검색되고, 하나라도 실패·불완전하면 검색에서 제외된다.
- AC-HR-002 (UC-HR-001): Dense 최대 30개와 BM25 최대 30개를 받아 같은 청크를 합치고 RRF로 통합하며, 고유 후보 최대 60개를 초과하지 않는다.
- AC-HR-003 (UC-HR-001): 후보가 부족할 때 추가 채움 검색 없이 있는 후보만 관련도 재정렬과 판단에 사용한다.
- AC-HR-004 (BR-HR-004): 최초 RRF 결과 전체가 관련도 재정렬에 전달되고, 점수 threshold 제거 없이 상위 30개가 근거 충분성 판단에 전달된다.
- AC-HR-005 (BR-HR-006): 충분성 판단은 `sufficient`, `selectedEvidenceIds`, `selectionReasons`, `missing`을 반환하고, 선택된 각 근거 ID에 `selectionReasons`가 필수이며 `insufficient`에서도 유효한 선택 근거·선택 이유와 missing을 반환한다.
- AC-HR-006 (BR-HR-007): insufficient이면 이전 유효 선택 근거를 유지한 채 이전·새 후보를 중복 제거하고 재정렬해 최대 30개로 다시 판단한다. 추가 검색은 최대 2회다.
- AC-HR-007 (UC-HR-002): Dense/BM25/관련도 재정렬과 충분성 판단의 오류·형식 오류는 각 1회 재시도하며, 재실패 시 부분 진행 또는 자율 판정 없이 전체 요청 오류다.
- AC-HR-008 (BR-HR-008): 후보 0개는 정상 빈 결과, 1~29개는 있는 만큼 진행하며 후보 없음·부족은 추적 로그에 남긴다. 추가 검색을 최대 2회 수행한 뒤에도 부족하면 선택 정책의 최종 부족 결과를 반환하고, 플레이어 행동 판정 정책에서 제한된 임시 판정을 내리는 경우에만 플레이어에게 근거 부족과 임시 판정임을 표시한다.
- AC-HR-009 (BR-HR-009): 상황별 정책이 검색 대상 문서 유형을 선택한다(STORYBOOK 전용, RULEBOOK 전용, 또는 둘 다). Dense/BM25/RRF/관련도 재정렬에는 문서 유형 가중치·고정 할당을 적용하지 않고, 시나리오 검색의 활성 원문 위치 우선 규칙과 최종 근거의 원문 위치·문서 유형을 보존한다. 최종 필요 조합은 상황별 근거 충분성 정책이 선택한다.
- AC-HR-010 (BR-HR-010): 추적 정보에 합의된 식별자·수량·시간·재시도·판단·임시 판정 정보를 남기되 원문 질의와 청크 본문은 남기지 않는다.
- AC-HR-011 (G-HR-004): 기존 평가 데이터·지표 비교에서 Dense 단독 기준선 대비 주요 검색 품질 지표가 개선되고 다른 품질 지표가 허용 오차 밖으로 하락하지 않는다. 응답 시간은 기록한다.
- AC-HR-012 (UC-HR-003, BR-HR-011): 모든 실제 모험 준비·진행 검색이 Dense+BM25→RRF→관련도 재정렬을 공통 적용한다.
- AC-HR-013 (UC-HR-003, BR-HR-012~014): 한 번의 Judge 호출이 선택과 불필요성 판단을 함께 수행하고, `sufficient`, `selectedEvidenceIds`, 선택된 각 근거의 `selectionReasons`, `missing`을 반환한다. 부분집합별 운영 재호출과 `necessity`·`useThroughRank`는 없다.
- AC-HR-014 (UC-HR-003, BR-HR-014): 네 정책이 각각 합의된 충분함 기준과 최종 부족 결과를 사용하고, 추가 검색·후보 병합·선택 근거 고정·최대 2회를 공통 적용한다.
- AC-HR-015 (BR-HR-015): 운영 로그에는 `selectionReasons` 원문이 없고 존재 여부와 선택 ID만 남는다.
- AC-HR-016 (BR-HR-016): 오프라인 평가가 선택 근거를 하나씩 제거해 최소성과 중복을 검증하고, 운영 Judge를 부분집합별로 재호출하지 않는다.
- AC-HR-017 (G-HR-005): Recall@5는 Dense 기준선보다 개선되고 MRR·근거 회수율·NDCG@5는 기준선 대비 1%p 초과 하락하지 않는다. 새 근거선택 지표는 첫 구현에서 측정·보고하며 차단값은 별도 확정한다.
