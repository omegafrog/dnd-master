# 전투 이동·주문 사거리 Product Spec

- 범위 ID: `combat-movement-spell-range`
- 문서 상태: **READY** — 제품 요구사항 확정, Product 다이어그램 검토 완료
- 대상: 전술 지도에서 진행하는 D&D 5판(2014) 전투의 이동, 행동, 주문 시전 및 범위 확인
- 결정 출처: 본 작업의 사용자 인터뷰. 사용자는 수정한 규칙이 현재 준비 중인 모험에만 적용된다고 확정했다: “해당 모험에만 적용. 모험 시작전에 유저의 판단이 들어가 검증을 돌리니까”.

## 1. Problem and Context

전술 지도에서 이동과 주문을 처리할 때, 플레이어는 이동 가능량, 지형, 벽과 문, 점유, 행동 시점, 주문 사거리, 시야와 효과 범위를 함께 판단해야 한다. 규칙에 근거한 전투 행동 미리보기와 실행 전 검증이 없으면 이동·시전 가능 여부를 잘못 판단하거나, 대상 지정과 범위 효과가 주문별 규칙을 따르지 않을 수 있다.

현재 범위는 D&D 5판(2014) 기본 룰북의 모든 주문을 포함하는 이동·행동·주문 지원이다. 파티가 현재 보유한 주문만을 대상으로 삼지 않는다. 주문 및 행동은 기본 룰북과 선택된 추가 룰북·시나리오 자료에서 출처와 함께 구조화한다. 준비 과정에서는 항목의 구조적 완전성과 지원 가능한 규칙 요소를 확인한다. 추출된 의미·수치·조건·출처의 최종 의미 검토, 직접 수정 및 승인은 사용자가 수행한다.

`combat-01`의 기본 룰북 주문 목록은 사용자가 제공한 `DnD_BasicRules_2018.pdf`와 동반 `DnD_BasicRules_2018.nodes.json`만을 권위 원문으로 사용한다. 다른 웹 자료나 선택 추가 자료의 항목을 이 목록에 합치지 않는다. 추가 자료는 별도 합의 전까지 이 목록에서 비활성으로 둔다.

## 2. Goals and Desired Outcomes

- **G-01 — 기본 룰북 전체 주문 범위:** D&D 5판(2014) 기본 룰북의 모든 주문을 범위로 포함하고, 주문별 규칙 차이를 보존한다.
- **G-02 — 근거 있는 규칙 준비:** 기본 룰북과 선택된 추가 룰북·시나리오 자료에서 주문과 행동을 구조화하고 출처를 유지한다. 모험 준비에서 구조와 출처, 지원 가능한 규칙 요소를 확인한다. 추출된 의미·수치·조건·출처의 최종 검토·직접 수정·승인은 사용자가 수행한다.
- **G-03 — 규칙에 맞는 이동:** 이동 시점, 속도와 남은 이동량, 경로 비용, 지형·점유·상태 조건을 반영한다.
- **G-04 — 안전한 미리보기와 실행:** 전투 행동 미리보기는 읽기 전용이며 숨겨진 정보를 노출하지 않는다. 확정 시 최신 상태를 다시 확인하고, 오래된 요청은 비용 없이 거부한다.
- **G-05 — 주문 규칙을 충실히 표현:** 시전 시간, 자원, 구성요소, 집중, 지속시간, 발동 조건, 공격·내성·자동 효과와 주문별 예외 및 더 높은 등급의 주문 슬롯 사용에 따른 변화를 출처 규칙대로 처리한다.
- **G-06 — 위치 표현 확장:** 평면 지도와 수치 지면으로부터의 높이를 사용해 비행, 거리, 장애물, 효과 포함 여부를 다룬다. 3차원 지도 편집은 포함하지 않는다.
- **G-07 — 입력 방식 일관성:** 지도 조작과 자연어 선언은 같은 규칙 검증과 숨김 정보 경계를 따른다.

## 3. Users and Actors

- **A-01 Solo Player:** 유일한 인간 사용자. 자신의 플레이어 캐릭터를 이동시키고 행동·주문을 선택하거나 자연어로 선언한다.
- **A-02 AI Game Master:** 장면을 서술하고 자연어 행동을 해석하며, 룰북 근거를 활용한다. 확정 규칙 검증을 우회하지 않는다.
- **A-03 AI 아군·적:** Solo Player가 직접 조작하지 않는 전투 참가자. 동일한 런타임 규칙을 따른다. 적의 내부 수치는 공개 필터를 따른다.
- **A-04 모험 준비 절차:** 선택된 자료에서 규칙을 추출·구조화하고 구조와 지원 가능한 규칙 요소를 확인해 사용자가 최종 검토할 수 있게 제시한다.

## 4. Ubiquitous Language and Terminology

- **기본 룰북:** `CONTEXT.md`의 `RULEBOOK`. 이번 범위에서는 D&D 5판(2014) Basic Rules다.
- **추가 룰북:** `CONTEXT.md`의 `STORYBOOK` 등 기본 룰북 외에 선택된 규칙·시나리오 자료.
- **구조화된 주문·행동 정의:** 선택한 룰북과 추가 자료의 주문·행동을 사용 조건, 비용, 대상 선택, 사거리, 효과 범위, 판정·효과, 지속·발동 조건, 예외 및 원문 출처와 함께 저장한 규칙 자료. 준비 과정은 구조적 완전성과 지원 가능한 규칙 요소를 확인하며, 추출된 의미의 최종 검토·직접 수정·승인은 사용자가 한다.
- **규칙 근거:** 구조화된 주문·행동 정의 또는 판정이 유래한 자료의 출처 참조.
- **주문 효과 범위:** 주문의 규칙이 지정한 대상 또는 공간에 적용되는 범위. 주문의 모양이나 투사체 외형만으로 결정하지 않는다.
- **시전 거리:** 시전자가 주문 대상을 지정할 수 있는 거리에 관한 규칙.
- **대상 가시성:** 주문이 요구하는 시야 조건.
- **명확한 경로와 엄폐:** 시전자와 대상 또는 효과 사이에 적용되는 경로·엄폐 규칙.
- **지면으로부터의 높이:** 평면 전술 지도의 위치와 함께 기록하는 수치 높이. 비행 이동, 대상까지의 거리, 장애물 차단, 주문 효과 범위에 포함되는지 판정하는 데 사용한다.
- **전투 행동 미리보기:** 이동 또는 주문·행동을 선택한 뒤 마우스 위치에 따라 경로·비용·사거리·효과 범위와 공개된 대상을 보여주는 읽기 전용 표시. 위치·자원·전투 상태를 바꾸지 않으며 미공개 정보를 드러내지 않는다.

## 5. Core Use Cases

### UC-001 규칙 자료를 준비하고 검증한다

1. 준비 절차는 기본 룰북과 선택된 추가 룰북·시나리오 자료에서 주문과 행동을 추출·구조화한다.
2. 각 항목에 원문 출처를 연결하고 구조적 완전성과 지원 가능한 규칙 요소를 확인한다. 추출된 의미·수치·조건·출처를 Solo Player에게 제시한다.
3. Solo Player가 모험 시작 전에 내용을 직접 검토·수정·승인한다. 원문 출처와 사용자가 수정한 내용의 출처·변경 이력을 보존한다. 승인한 편집본은 현재 준비 중인 모험에만 적용하고, 공개된 기본 룰북 정의나 다른 모험의 규칙 자료는 변경하지 않는다. 모험 시작 전에 검증과 사용자 판단을 마친 뒤 기존 Bundle Lock 및 Adventure Start Lock에 따라 고정한다.
4. 실행할 수 없는 추가 자료 항목은 비활성 상태로 저장하고 경고한다. Solo Player는 경고를 확인하고 모험을 시작할 수 있지만, 비활성 항목이 선택 캐릭터나 시나리오 진행에 필수이면 시작을 차단한다.
5. 기본 룰북의 모든 주문을 지원한다고 표시하려면 전체 주문을 실행할 수 있어야 한다. 기본 룰북 주문을 미지원으로 표시하는 것만으로 전체 범위 충족을 주장할 수 없다.

### UC-002 이동·행동·주문을 미리 보고 실행한다

1. Solo Player는 이동, 주문 또는 행동을 선택한다. 자연어 선언도 같은 규칙 검증으로 처리한다.
2. 이동은 이동을 선택한 뒤 도달 가능한 영역을 가리켜 미리 보고, 목적지를 클릭해 실행한다. 이동 가능량은 행동 전·사이·후에 이어 쓸 수 있다.
3. 주문·행동은 선택 후 사거리와 효과 범위를 가리켜 미리 본다. 대상이 하나이고 선택만으로 충분하면 클릭으로 시전한다.
4. 방향이 규칙상 필요한 원뿔·선 효과는 시전자에서 커서 쪽 방향으로 표시한다. 투사체나 생성 형태만으로 임의의 방향성 범위를 만들지 않는다.
5. 마법 화살 같은 대상 지정 주문은 유효한 대상을 보여준다. 여러 대상이나 투사체 배분이 필요한 경우 대상·배분을 선택한 뒤 명시적으로 시전한다.
6. 주문 효과 범위의 전투 행동 미리보기는 아군이 영향을 받을 수 있음을 알리지만 별도 확인 단계를 추가하지 않는다. 실제 영향 대상은 주문별 대상 지정 규칙으로 정한다.
7. 실행 시점에 최신 상태를 다시 확인한다. 상태가 바뀌어 실행할 수 없으면 비용 없이 실패 처리하고 화면을 갱신한다.
8. 실제 실행 도중 반응, 함정 또는 기타 기존 이동 해결 흐름에 따른 중단이 발생하면 실제 위치와 이미 소비한 이동량을 보존한다. 플레이어는 명시적으로 턴을 종료한다.

### UC-004 주문 효과를 환경에 응용한다

1. Solo Player는 주문을 선언할 때 주문 효과를 주변 환경에 응용하려는 뜻을 함께 말할 수 있다. 별도의 시전 후 입력 단계는 요구하지 않는다.
2. 추가 응용을 계획하기 전에 AI Game Master는 현재 사용 가능한 환경 작업, 각 작업의 입력 형식과 제약을 받는다.
3. AI Game Master는 제공된 목록에 있는 작업만 골라 조합한다. 목록에 없는 작업은 호출하지 않으며, 임의 코드를 만들어 실행하지 않는다. 예를 들어 물을 만들어 함정을 무력화하려는 시도를 검토할 수 있지만, 모든 함정이 물에 취약하다고 가정하지 않는다.
4. 환경 작업의 호출이 실패하면 오류 내용이 AI Game Master에 전달된다. AI Game Master는 오류를 참고해 입력이나 작업 선택을 고쳐 재시도할 수 있다. 재시도 횟수의 고정 한도는 정하지 않는다.
5. 판정이 필요하면 AI Game Master는 기존 플레이어 굴림 제출 흐름으로 굴림을 요청한다.
6. 추가 환경 응용이 실패해도 이미 적용된 주문 기본 효과와 소비된 자원은 유지하고, 실패한 응용만 실패로 처리한다. 재시도는 기본 주문 효과를 다시 실행하거나 기본 비용을 다시 소비하지 않는다.
7. 제안·호출·판정은 플레이어가 알지 못하는 함정·상태 등 숨겨진 정보를 공개하지 않는다.
8. 추가 환경 응용이 실패하고 플레이어가 관찰할 추가 변화가 없으면 그 실패나 숨겨진 내부 상태를 서술하지 않고 넘어갈 수 있다. 이미 적용된 주문 기본 효과와 소비한 자원은 기존 UI 규칙에 따라 플레이어에게 보인다. 숨겨진 함정 상태나 내부 실패 사유는 공개하지 않는다.

### UC-003 지도를 확대하고 위치 관계를 확인한다

1. Solo Player는 모험 시작 후 지도를 확대하거나 축소한다.
2. 포인터, 범위 겹침과 화면 오버레이는 확대 배율에 맞춰 지도 위치와 일치한다.
3. 비행 위치는 평면 위치와 수치 지면으로부터의 높이로 표현하고 거리, 장애물 및 주문 효과 포함 여부를 판단한다.

## 6. Business Rules and Invariants

- **BR-01:** 대상 범위는 D&D 5판(2014) 기본 룰북의 모든 주문이다. 현재 파티가 가진 주문만을 추출 대상으로 삼지 않는다.
- **BR-02:** 주문·행동 구조화 결과는 근거 출처와 연결한다. 준비 과정에서는 구조·출처·지원 가능한 규칙 요소를 확인하고, 추출된 의미·수치·조건의 최종 검토와 직접 수정·승인은 사용자가 수행한다.
- **BR-03:** 규칙 자료는 확장 가능해야 하며, 새로 확인된 예외는 명시적으로 추가한다. 추가 기능 묶음의 설치, 플러그인 설치 및 SDK 통합은 범위 밖이다. 추가 자료의 비활성 항목은 경고와 필수 여부 규칙을 따른다. 비활성 항목의 실행 요청은 주문 슬롯이나 행동 자원을 소비하지 않고 거부한다.
- **BR-04:** 기본 룰북 전체 주문 범위의 완료를 주장하려면 전체 주문을 지원해야 한다. 미지원 표시만으로 충족 처리하지 않는다.
- **BR-05:** 턴 중 이동은 행동 전·사이·후 어느 시점에도 이어 쓸 수 있다. 현재 속도, 사용량과 남은 이동량을 표시한다.
- **BR-06:** 도달 가능한 영역과 실제 경로 비용은 벽, 문, 모서리, 어려운 지형, 점유, 상태 조건을 반영한다. 질주, 이탈 및 기회 공격 반응을 적용 룰북에 따른다.
- **BR-07:** 지도는 평면이며 비행체의 지면으로부터의 높이를 수치로 표현한다. 지면으로부터의 높이는 거리·장애물·효과 포함 여부에 반영한다. 3차원 편집은 제공하지 않는다.
- **BR-08:** 이동 조작은 `이동 선택 → 가리켜 전투 행동 미리보기 → 클릭 실행` 순서다.
- **BR-09:** 주문·행동 조작은 `선택 → 가리켜 사거리·효과 전투 행동 미리보기 → 필요한 선택 완료 → 명시적 시전` 순서다. 단일 선택만으로 충분한 경우 클릭이 시전을 확정한다.
- **BR-10:** 방향 지정은 규칙이 요구할 때만 커서 방향으로 결정한다. 대상 지정형 주문을 임의의 방향형 효과로 취급하지 않는다.
- **BR-11:** 주문의 시전 행동 유형, 주문 슬롯, 구성요소, 집중, 지속시간, 발동 조건, 공격·내성·자동 해결 방식 및 더 높은 등급의 주문 슬롯 사용에 따른 변화는 출처 규칙을 따른다. 외형, 투사체 또는 생성 분류로 규칙을 추론하지 않는다.
- **BR-12:** 시전 거리, 대상 가시성, 명확한 경로·엄폐, 효과 확산과 각 주문 예외를 서로 구분해 적용한다.
- **BR-13:** 전투 행동 미리보기는 아군 피해 가능성을 알리며 별도 확인을 요구하지 않는다. 영향을 받는 아군은 해당 주문의 대상 규칙으로 결정한다.
- **BR-14:** 전투 행동 미리보기는 읽기 전용이고 자원을 쓰지 않으며 숨겨진 정보를 누설하지 않는다. 최종 실행은 최신 상태 기준으로 다시 검증한다.
- **BR-15:** 오래된 상태에서 실행 요청이 들어오면 비용을 소비하지 않고 실패 처리한 뒤 최신 상태를 표시한다.
- **BR-16:** 실제 실행 중 중단은 기존 이동 해결 흐름을 따른다. 이미 이동한 위치와 소비한 이동량은 유지한다.
- **BR-17:** Solo Player의 인간 조작 캐릭터는 하나다. AI 아군·적도 동일한 런타임 규칙을 따르며, 적 내부 수치는 공개 필터로 감춘다.
- **BR-18:** 자연어 행동 선언에도 지도 조작과 같은 규칙 검증과 정보 공개 경계가 적용된다.
- **BR-19:** 플레이어가 턴 종료를 명시적으로 선택하기 전까지 자신의 턴은 종료되지 않는다.
- **BR-20:** 지도 확대 후 포인터와 오버레이는 지도 좌표와 계속 정렬된다.
- **BR-21:** 전장의 안개 아래 있는 벽도 기존 가시성·탐험 정책을 따라 표시 여부를 정한다. 숨겨진 벽 형상은 공개하지 않는다.
- **BR-22:** 준비 과정에서 추출된 주문·행동의 항목 구조와 지원 가능한 규칙 요소를 확인한다. 전체 의미·수치·조건·출처가 원문에 맞는지의 최종 검토와 직접 수정·승인은 사용자가 수행하며, 시스템이 모든 의미상 조건과 충돌을 결정론적으로 검증할 것을 요구하지 않는다. 원문 출처와 사용자가 수정한 내용의 출처·변경 이력은 함께 보존한다.
- **BR-23:** AI Game Master는 플레이어가 주문 선언과 함께 전달하거나 별도로 제안한 환경 응용 의도를 상황에 맞게 판단하고, 필요하면 기존 플레이어 굴림 제출 흐름을 통해 굴림을 요청할 수 있다. 예시는 보편 규칙이나 자동 성공을 만들지 않으며 숨겨진 정보를 드러내지 않는다.
- **BR-24:** 추가 환경 응용이 실패해도 이미 적용된 주문 기본 효과와 소비된 자원은 유지한다. 실패하는 것은 추가 환경 응용뿐이다.
- **BR-25:** 추가 환경 응용이 실패하고 플레이어가 관찰할 추가 변화가 없으면 AI Game Master는 해당 실패를 서술하지 않고 넘어갈 수 있다. 이 생략은 추가 응용의 실패와 숨겨진 내부 상태에 한정한다. 주문 기본 효과와 소비한 자원은 기존 UI 규칙에 따라 표시하며, 숨겨진 함정 상태나 내부 실패 사유를 공개하지 않는다.
- **BR-26:** 추가 환경 응용을 계획하기 전에 AI Game Master에게 현재 지원되는 환경 작업의 목록, 각 작업의 입력 형식과 제약을 제공한다. AI Game Master는 제공된 작업만 사용하며, 목록에 없는 작업이나 임의 코드는 실행 요청하지 않는다.
- **BR-27:** 환경 작업 호출 실패 시 오류 내용을 AI Game Master에 전달해 입력이나 작업 선택을 수정할 수 있게 한다. AI Game Master는 수정 후 재시도할 수 있으며, 고정된 재시도 횟수는 요구하지 않는다.
- **BR-28:** 환경 작업 재시도는 이미 확정된 주문 기본 효과나 소비 자원을 다시 적용하지 않는다. 실행은 기존 런타임의 권한 및 지원 여부 확인을 따른다.
- **BR-29:** 사용자가 검토·수정·승인한 주문·행동 정의는 현재 준비 중인 모험에만 적용한다. 승인은 모험 시작 전에 마치며, 공개된 기본 룰북 정의나 다른 모험의 규칙 자료는 변경하지 않는다. 시작 전 검증·판단 이후에는 기존 Bundle Lock 및 Adventure Start Lock에 따라 편집본을 고정한다. 근거: 사용자 결정 “해당 모험에만 적용. 모험 시작전에 유저의 판단이 들어가 검증을 돌리니까”.

## 7. States and State Transitions

### 준비 상태

- **검증 중 → 사용자 검토:** 추출된 의미·수치·조건·출처와 구조·지원 요소 확인 결과를 제시한다.
- **사용자 검토 → 현재 모험용 승인 규칙:** Solo Player가 모험 시작 전에 항목을 직접 수정하거나 검토 후 승인한다. 원문 출처와 수정 이력을 보존한다.
- **현재 모험용 승인 규칙 → 모험 시작:** 승인본은 현재 준비 중인 모험에만 적용하며 공개된 기본 룰북과 다른 모험은 변경하지 않는다. 기존 버전 고정 규칙에 따라 모험 시작 이후 변경되지 않는다.
- **검증 중 → 사용 가능:** 구조적 완전성과 지원 가능한 규칙 요소를 확인하고 사용자가 의미 검토를 승인한다.
- **검증 중 → 경고와 함께 사용 가능:** 추가 자료의 선택 항목이 비활성 상태이며, 필수 항목은 아니다. Solo Player가 경고를 확인하면 시작할 수 있다.
- **검증 중 → 시작 차단:** 필수 비활성 항목이 선택 캐릭터 또는 핵심 시나리오에 필요하다.

### 지도 상호작용 상태

- **선택 전 → 전투 행동 미리보기:** 이동, 주문 또는 행동을 선택하고 포인터를 지도 위로 옮긴다.
- **미리보기 → 실행:** 가능한 목적지 이동을 클릭하거나, 충분히 지정된 단일 주문·행동을 클릭한다.
- **미리보기 → 추가 선택 필요:** 복수 대상 또는 배분을 요구하는 주문·행동을 선택한다. 선택 후 명시적으로 시전한다.
- **실행 요청 → 최신 상태 검증 실패:** 기준 상태가 바뀌었다. 비용 없이 거부하고 새 상태로 전투 행동 미리보기를 갱신한다.
- **실행 중 → 규칙상 중단:** 실제 위치와 사용한 이동량을 보존하고 기존 반응·함정 처리를 이어간다.
- **플레이어 턴 → 다음 턴:** Solo Player가 명시적으로 턴 종료를 선택한다.

### 주문 효과의 환경 응용

- **응용 계획 전 → 허용 작업 확인:** AI Game Master가 현재 지원되는 환경 작업 목록, 입력 형식과 제약을 받는다.
- **허용 작업 확인 → 호출:** 목록에 포함된 작업만 골라 요청한다. 적절한 작업이 없으면 호출하지 않는다.
- **호출 → 오류 조정:** 호출 실패 시 오류 내용을 AI Game Master에 전달한다. 입력 또는 작업을 수정해 재시도할 수 있다.
- **오류 조정 → 재시도 또는 추가 응용 실패:** 수정된 요청을 다시 시도하거나 추가 응용을 실패로 마친다. 어느 경우에도 이미 적용된 주문 기본 효과와 소비 자원을 다시 적용하지 않는다.

## 8. Failures, Exceptions, and Boundary Conditions

- **EX-01 추가 자료의 비필수 미지원 항목:** 비활성으로 저장하고 경고한다. 경고 확인 후 모험 시작을 허용한다.
- **EX-02 선택 캐릭터 또는 필수 시나리오가 비활성 항목에 의존:** 경고 확인만으로 우회하지 못하며 시작을 차단한다.
- **EX-12 추가 환경 응용 실패로 관찰 가능한 변화가 없음:** 추가 응용 실패나 숨겨진 내부 상태는 서술하지 않고 넘어갈 수 있다. 주문 기본 효과와 소비 자원은 계속 표시하고, 숨겨진 함정 상태와 내부 실패 사유는 공개하지 않는다.
- **EX-13 허용 환경 작업 없음:** 사용할 수 있는 작업이 목록에 없으면 지원되지 않는 동작을 요청하거나 임의 코드를 실행하지 않는다.
- **EX-14 환경 작업 호출 실패:** 오류 내용을 AI Game Master에 전달해 수정·재시도할 수 있게 한다. 재시도 횟수의 고정 한도는 정하지 않으며 주문 기본 효과와 소비 자원을 중복 적용하지 않는다.
- **EX-03 기본 룰북 주문 일부 미지원:** 전체 주문 지원 완료로 표시하지 않는다.
- **EX-04 비활성 주문 실행 요청:** 주문 슬롯이나 행동 자원을 소비하지 않고 거부한다.
- **EX-05 대상 지정 주문에 복수 대상·배분 필요:** 전투 행동 미리보기만으로 시전하지 않고 필요한 선택 뒤 명시적으로 시전한다.
- **EX-06 주문이 요구하지 않는 방향 지정:** 커서 방향이나 효과 외형에서 방향을 추론하지 않는다.
- **EX-07 실행 전 상태 변경:** 이전 전투 행동 미리보기는 실행 근거로 쓰지 않고, 비용 없이 거부한 뒤 최신 상태로 갱신한다.
- **EX-08 실행 중 반응·함정 등으로 이동 중단:** 실제로 도달한 위치와 소비한 이동량을 보존한다.
- **EX-09 숨겨진 벽:** 기존 공개 정책이 허용하지 않는 벽 형상은 지도 확대나 오버레이를 통해서도 드러나지 않는다.
- **EX-10 자연어 입력:** 정형 지도 입력과 동일한 규칙 검증을 적용한다.
- **EX-11 3차원 지도 편집 요구:** 지원 범위가 아니다. 비행 위치와 규칙 계산은 평면 지도 위 수치 지면으로부터의 높이로 처리한다.

## 9. Inputs and Outputs

### 입력

- 기본 룰북과 선택된 추가 룰북·시나리오 자료, 해당 원문 출처
- 구조화된 주문·행동과 구조·출처·지원 가능한 규칙 요소의 확인 결과 및 사용자의 의미·수치·조건 검토·수정
- 캐릭터의 속도, 이동 사용량, 상태, 자원, 주문 및 턴 행동 상태
- 지도 타일, 벽·문·모서리, 어려운 지형, 점유, 가시성·탐험 상태와 위치별 지면으로부터의 높이
- 선택한 이동·주문·행동, 주문과 함께 전달할 수 있는 환경 응용 의도, 커서 위치, 대상과 대상·투사체 배분
- 현재 지원되는 환경 작업 목록, 각 작업의 입력 형식과 제약, 호출 오류 내용
- 실행 시점의 현재 게임 상태

### 출력

- 준비된 주문·행동 항목과 근거 참조, 추출 의미·수치·조건을 검토·수정·승인하는 화면, 수정 이력, 비활성 항목 경고 및 시작 허용·차단 결과
- 현재 속도와 사용·잔여 이동량, 도달 가능 영역과 경로 비용
- 주문·행동의 사거리·효과 범위·유효 대상 표시, 아군 영향 경고
- 선택·시전·이동 실행 결과, 환경 응용 판정 요청·관찰 가능한 결과, 규칙에 따른 반응·함정 중단 결과
- AI Game Master가 수정·재시도에 사용할 수 있는 환경 작업 호출 오류 내용
- 최신 상태 불일치 시 비용 없는 실패와 새 상태 기준 미리보기
- 확대 배율과 정렬된 지도 포인터·범위 오버레이

## 10. Scope and Non-goals

### 포함

- D&D 5판(2014) 기본 룰북의 모든 주문
- 선택된 추가 룰북·시나리오 자료의 주문과 행동 및 명시적 예외
- 모험 준비 중 구조·출처·지원 가능한 규칙 요소 확인과 사용자의 최종 의미·수치·조건 검토·수정·승인
- 전술 지도에서 이동, 주문·행동의 전투 행동 미리보기와 규칙 검증
- 평면 지도에서 수치 지면으로부터의 높이를 쓰는 비행·거리·장애물·효과 판정
- 모험 시작 후 확대·축소와 오버레이 정렬
- 자연어 선언에 동일한 판정 적용

### 제외

- 3차원 지도 편집기
- 기본 룰북 주문 전체를 충족하지 못한 상태에서 전체 지원으로 표시하는 것
- 주문 모양·투사체·생성 분류만으로 규칙을 자동 추론하는 것
- 범위 경고 후 추가 확인 단계

### 추후

- 기본 및 선택 자료 이외의 자료 묶음은 별도 추가 결정에 따른다.

## 11. Priorities and Trade-offs

1. 기본 룰북 전체 주문 범위와 출처에 충실한 개별 예외 처리를 우선한다.
2. 전투 행동 미리보기의 편리함보다 최신 상태 재검증, 자원 무소비, 정보 비공개를 우선한다.
3. 이동·주문·행동 조작은 짧은 선택·가리키기·클릭 흐름을 사용하되, 복수 대상·배분 주문에는 필요한 명시적 선택을 유지한다.
4. 전투 행동 미리보기는 아군 영향 위험을 알리되 확인 단계를 늘리지 않는다.
5. 기본 룰북과 선택된 추가 자료의 실제 지원 여부를 구분한다. 추가 자료의 비필수 미지원은 경고 후 허용하지만, 필수 미지원은 시작을 막는다.

## 12. Success Conditions and Acceptance Criteria

### 적용 범위와 출처

- **AC-01:** D&D 5판(2014) 기본 룰북 원판의 권위 있는 주문 목록을 기준으로 모든 주문을 고유 식별자와 출처에 연결하고, 각 주문을 원문 규칙에 따라 실행할 수 있다. 주문 목록의 항목 누락을 허용하지 않는다. 단순히 대상 후보로 표시하는 것으로 지원을 인정하지 않으며, 보유 주문만 대상으로 축소하지 않는다. (G-01, BR-01)
- **AC-02:** 기본 룰북 원판의 주문 목록에서 하나라도 실행을 지원하지 않으면 전체 주문 지원 완료를 표시하지 않는다. 추가 자료의 미지원 항목은 이 기준을 대신할 수 없다. (G-01, BR-04)
- **AC-03:** 추가 자료의 구조화 항목에 원문 근거, 구조적 완전성, 지원 가능한 규칙 요소의 확인 결과가 연결되고, 추출 의미·수치·조건·출처는 사용자 검토 대상으로 제시된다. (G-02, BR-02, BR-22)
- **AC-04:** 비필수 추가 항목의 미지원은 비활성·경고로 표시되며 확인 후 시작할 수 있다. 선택 캐릭터 또는 필수 시나리오 항목의 미지원은 시작을 막는다. 비활성 주문을 클릭해 실행하려 하면 주문 슬롯이나 행동 자원을 쓰지 않고 거부한다. (BR-03)

### 이동

- **AC-05:** 행동 전·사이·후에 이동을 이어 쓸 수 있고 현재 속도·사용량·잔여량을 확인할 수 있다. (G-03, BR-05)
- **AC-06:** 전투 행동 미리보기와 경로 비용에 벽·문·모서리·어려운 지형·점유·상태가 반영되고, 질주·이탈·기회 공격 반응이 룰북에 따라 처리된다. (BR-06)
- **AC-07:** 이동 선택 후 커서를 옮기면 도달 가능 영역을 미리 보고, 클릭으로 이동을 실행한다. (BR-08)
- **AC-08:** 실제 실행 중 규칙상 중단되면 도달한 위치와 이미 소비한 이동량을 유지한다. (BR-16)

### 주문과 행동

- **AC-09:** 선택 후 커서 위치에 따라 사거리와 효과 범위를 미리 볼 수 있다. 한 대상 선택으로 충분하면 클릭 시전하고, 복수 선택·배분이 필요하면 선택 완료 후 명시적으로 시전한다. (BR-09)
- **AC-10:** 방향이 필요한 원뿔·선은 시전자에서 커서 방향으로 향하며, 방향이 불필요한 대상 지정 주문은 유효 대상을 표시한다. 마법 화살은 복수 대상·투사체 배분 뒤 명시적으로 시전할 수 있다. (BR-10)
- **AC-11:** 주문 실행이 시전 행동 유형, 슬롯, 구성요소, 집중, 지속시간, 발동 조건, 공격·내성·자동 해결과 더 높은 등급의 주문 슬롯 사용에 따른 변화를 출처 규칙대로 적용한다. (BR-11)
- **AC-12:** 시전 거리, 가시성, 명확한 경로·엄폐 및 효과 확산은 서로 구분하여 판정되고 주문별 예외가 유지된다. (BR-12)
- **AC-13:** 범위 안에 들어오는 아군이 있으면 전투 행동 미리보기에서 경고하고, 추가 확인 없이 주문별 대상 규칙대로 영향을 판정한다. (BR-13)

### 상태·공개·지도

- **AC-14:** 전투 행동 미리보기만으로 위치, 자원 또는 전투 상태가 변하지 않고 숨겨진 정보를 알아낼 수 없다. (G-04, BR-14)
- **AC-15:** 전투 행동 미리보기 후 상태가 바뀌면 실행은 자원 소모 없이 거부되고 현재 상태에 맞게 새로고침된다. (BR-15)
- **AC-16:** Solo Player가 턴 종료를 명시적으로 선택하기 전에는 플레이어 턴이 자동 종료되지 않는다. (BR-19)
- **AC-17:** 비행 위치의 수치 지면으로부터의 높이가 거리·장애물·효과 포함 여부에 반영되고, 3차원 편집은 제공되지 않는다. (G-06, BR-07)
- **AC-18:** 모험 시작 후 확대·축소 시 포인터와 범위 오버레이가 지도상의 위치와 정렬된다. (BR-20)
- **AC-19:** 벽 형상 표시는 기존 가시성·탐험 정책을 따르고 숨겨진 벽을 드러내지 않는다. (BR-21)
- **AC-20:** 자연어로 선언한 이동·주문·행동은 직접 조작과 같은 규칙 검증 및 숨김 정보 정책을 따른다. (G-07, BR-18)
- **AC-21:** 준비 화면은 추출된 주문·행동의 의미, 수치, 조건 및 출처를 사용자가 검토할 수 있게 제시하고 사용자가 내용을 직접 수정하고 승인할 수 있게 한다. 원문과 사용자 수정의 출처·변경 이력은 보존한다. 구조적 완전성과 지원 가능한 규칙 요소는 확인하되, 시스템이 모든 의미상 조건·충돌을 완전하게 결정론 검증한다고 전제하지 않는다. (BR-22)
- **AC-22:** Solo Player가 주문 선언과 함께 또는 별도로 주문 효과의 환경 응용을 제안하면 AI Game Master가 상황별로 판단하고, 필요한 경우 기존 플레이어 굴림 제출 흐름으로 굴림을 요청할 수 있다. 물로 함정을 무력화하는 예는 자동 성공이나 함정 취약성의 보편 규칙을 뜻하지 않으며, 숨겨진 정보는 공개하지 않는다. (UC-004, BR-23)
- **AC-23:** 추가 환경 응용이 실패해도 이미 적용된 주문 기본 효과와 소비된 자원은 유지하고, 추가 환경 응용만 실패 처리한다. (UC-004, BR-24)
- **AC-24:** 추가 환경 응용이 실패하고 관찰 가능한 추가 변화가 없으면 해당 실패를 서술하지 않고 넘어갈 수 있다. 주문 기본 효과와 소비 자원은 기존 UI 규칙대로 표시하며 숨겨진 함정 상태와 내부 실패 사유는 공개하지 않는다. (UC-004, BR-25)
- **AC-25:** AI Game Master는 추가 응용을 계획하기 전에 지원되는 환경 작업 목록, 입력 형식과 제약을 받으며 목록에 없는 작업이나 임의 코드를 실행 요청하지 않는다. (BR-26)
- **AC-26:** 작업 호출 오류 내용이 AI Game Master에 전달되어 입력이나 작업 선택을 수정하고 재시도할 수 있다. 고정 재시도 횟수는 전제하지 않는다. 재시도는 주문 기본 효과나 소비 자원을 중복 적용하지 않는다. (BR-27, BR-28)
- **AC-27:** 사용자는 모험 시작 전에 구조화된 주문·행동 정의를 검토·수정·승인할 수 있다. 승인한 편집본은 현재 모험에만 적용하고 공개된 기본 룰북이나 다른 모험의 정의를 변경하지 않으며, 시작 이후 기존 버전 고정 규칙에 따라 유지한다. (UC-001, BR-29)
