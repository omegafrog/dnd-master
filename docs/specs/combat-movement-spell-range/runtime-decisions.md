# 전투 이동·탐험 이동·조우·주문 및 기술 결정

- 상태: 대화에서 사용자와 합의한 제품 결정 기록
- 기록일: 2026-10-17
- 적용 범위: 모험 런타임
- 이 문서는 기존 명세를 대체하는 완성 Product/Architecture Spec이 아니라, 이번 대화에서 확정한 동작 기준이다. 기존 명세와 충돌하면 이 기록을 반영해 명세를 갱신한다.

## 모험 E2E에서 사용하는 원본 자료

- 모험 런타임 E2E는 별도 내용을 만들어 테스트용 시나리오·지도 파일로 사용하지 않는다. 원본 프로젝트의 `../dnd-master/docs/assets` 자료를 그대로 사용한다.
- A Most Potent Brew 자료는 파일명에 맞춰 다음 역할로 모두 연결한다: `892902-A_Most_Potent_Brew.pdf`는 `MAIN_SCENARIO`, `892902-A_Potent_Brew_Map.pdf`는 `MAP`, `892902-A_Most_Potent_Brew_Player_Handout.pdf`는 `HANDOUT`.
- 기본 룰북은 같은 assets 디렉터리의 `DnD_BasicRules_2018.pdf`를 사용한다. 이 PDF 첫 페이지에 표시된 판본은 “D&D Basic Rules, Version 1.0, Released November 2018”이다. 기존 시스템의 `DND_5E_2014` 식별자는 룰북 자료를 묶음에 연결하는 내부 호환 식별자로만 사용하고, 다른 판본의 룰북으로 대체하지 않는다.
- E2E 실행 전 위 네 원본 파일이 실제 존재하고 읽을 수 있는지 확인한다. 자료가 없거나 역할 연결이 맞지 않으면 임의의 파일을 만들거나 다른 파일로 대체하지 않고 실행을 실패 처리한다.

## 그룹과 대열

- 탐험 중 이동 단위는 개별 캐릭터가 아니라 그룹이며, 그룹마다 토큰 하나를 사용한다.
- 그룹에는 구성원, 현재 위치, 전열·중열·후열 대열을 저장한다. 캐릭터별 탐험 좌표는 관리하지 않는다.
- 그룹은 한 명으로도 구성할 수 있다. 한 캐릭터가 따로 이동하면 그 캐릭터가 속한 1인 그룹과 별도 토큰으로 취급한다.
- 그룹 속도는 구성원 중 가장 느린 캐릭터를 기준으로 한다.
- 그룹을 나누면 현재 위치에서 새 그룹 토큰을 만들고, 구성원과 새 그룹의 대열을 정한 뒤 그룹마다 별도 경로를 지정한다.
- 두 그룹이 같은 위치에 와도 자동으로 합치지 않는다. 사용자가 명시적으로 합치기를 선택하면 그룹을 합치고 새 대열을 정한다.
- 전투가 시작되면 그룹 위치와 대열을 바탕으로 캐릭터별 전투 토큰을 자동 배치한다. 자동 배치가 장면에 맞지 않는 경우 GM이 수정안을 제시한다. 전투가 끝나면 전투 전의 그룹 구성을 복원한다. 여러 명인 그룹의 토큰은 전열 캐릭터의 현재 칸에 두고, 탐험 상태에서는 나머지 구성원의 개별 칸을 추적하지 않는다. 전투가 끝났다는 이유만으로 서로 다른 그룹을 합치지 않는다.
- 대열은 탐험 중 위협·함정을 먼저 마주칠 사람과 발견 판정에 참여할 사람을 정하고, 전투 시작 위치를 구성하는 데 사용한다.
- 이동 경로를 확인해 실행하면 토큰은 경로를 한 칸씩 따라간다. 함정을 발견하거나 발동시키는 경우, 적을 마주치거나 기습을 당하는 경우 등 진행을 멈춰야 하는 사건이 생기면 해당 지점에서 이동을 멈추고 사건을 먼저 처리한다. 사건 처리 중에는 남은 경로를 진행하지 않는다.
- 사건이 전투로 이어지지 않아 이동을 재개할 수 있어도 남은 경로는 자동으로 실행하지 않는다. 플레이어가 현재 상태를 기준으로 경로를 다시 확인해야 한다.
- 플레이어는 모험 시작 시 파티에 속한 모든 캐릭터를 직접 조종한다. 탐험 이동, 전투 행동, 능력 습득 선택, 캐릭터 시트의 설정·수정 결정을 GM이 대신하지 않는다.
- GM은 세계와 NPC·적을 조종하고, 규칙 판정과 결과 서술을 맡는다. 파티 캐릭터들의 일상 대화는 GM이 생성할 수 있다.
- 파티 대화가 전투 행동, 자원 소모, 그룹 분리·합류, 퀘스트나 관계 방향 변경을 결정하게 되면 GM은 진행을 멈추고 플레이어에게 선택을 묻는다. GM은 동료가 선택할 수 있는 선택지를 제시할 수 있고, 플레이어는 별도 대안을 직접 입력할 수도 있다.
- 플레이어가 직접 입력한 동료의 대화 행동이 현재 캐릭터 설명에서 확인되는 가치관·성격과 충돌하면 GM은 그 이유를 설명하고 해당 대화 행동이 성립하지 않는다고 말한 뒤, 다른 선택을 기다린다. 캐릭터 설명에 근거가 없는 가치관을 지어내 거절하지 않는다.
- 일상 대사는 파티 상태를 바꾸지 않는다. 이 대화 규칙은 동료의 대화 선택에 적용하며 플레이어가 직접 조종하는 전투 행동이나 시트 변경을 GM이 거부하는 근거가 되지 않는다.
- 플레이어가 능력 습득이나 시트 변경 내용을 선택·확정하면 agent는 선택된 능력의 근거 있는 상세정보만 준비해 제공한다. 시스템은 확정된 규칙 결과와 자원 변화를 결정적으로 반영한다.

## 전투 이동

- 전투가 시작되면 그룹 위치와 대열을 바탕으로 캐릭터별 전투 토큰을 배치한다. 사용자는 움직일 캐릭터 토큰을 클릭하고 드래그해 경로를 그린 다음 확인해 실행한다. 확인 전에는 위치와 전장의 안개를 바꾸지 않는다.
- 각 캐릭터의 경로는 칸마다 진행한다. 각 칸에 도달할 때 벽·문·지형·그 캐릭터의 남은 이동량을 확인하고 전장의 안개와 발견·공간 요소 반응을 갱신한다.
- 벽을 통과할 수 없고, 각 캐릭터는 적용되는 규칙상 자신의 이동 거리까지만 움직인다. 탐험 시 그룹 속도를 구성원 중 가장 느린 캐릭터 기준으로 정하는 규칙과 구분한다.
- 이동이 중단되면 실제 도달한 위치와 이미 사용한 이동량만 반영한다.

## 전투 밖 이동의 순차 진행

- 중요하지 않은 이동은 GM이 거리와 시간을 요약할 수 있다. 위치·위협·행동 처리가 중요한 탐험은 지도에서 그룹별 경로와 위치를 구체적으로 진행한다.
- 위치·위협·행동 처리가 중요한 탐험에서는 모험 시간을 잠시 멈추고, 이동할 그룹의 우선권을 정한 다음 그 순서대로 각 그룹을 움직인다.
- 모든 그룹의 이동 차례가 끝난 뒤 환경을 한 번 진행한다. 적의 순찰, 제한 시간과 그 밖의 환경 변화는 이 단계에서 반영한다.
- 각 그룹 차례의 이동 허용량은 그룹 속도, 즉 가장 느린 구성원의 이동 가능 거리다. 이동 경로를 여러 번 확정해도 같은 차례의 허용량을 나눠 쓰며, 차례 완료 전까지 누적 이동량을 제한한다. 이동 경로의 각 칸에서 전장의 안개와 발견·공간 요소 반응을 확인한다. 사건이 생기면 모든 그룹의 차례를 멈추고 먼저 그 사건을 해결한다.
- 사건이 전투로 이어지지 않으면 사건을 일으킨 그룹의 차례는 끝내고, 우선권 순서의 다음 그룹부터 같은 순환을 이어간다. 전투가 시작되면 전술 이동 순서를 종료하고 전투 차례로 전환한다.
- 이 순차 진행은 앞서 정한 그룹별 동시 이동 및 가장 느린 그룹 기준의 공통 칸 이동 시간을 대체한다. 그룹별 이동 속도가 다르다는 규칙은 유지한다.
- 그룹 우선권은 해당 그룹 전열 캐릭터들의 우선권 중 가장 높은 값으로 정한다.
- 그룹 우선권이 같은 경우, 해당 그룹들의 이동 순서를 무작위로 정한다.
- 모든 그룹이 한 차례씩 움직이고 환경이 진행되는 한 순환은 6초다. 순찰·제한 시간 등 시간에 따른 환경 변화도 순환마다 6초 진행한다.
- 환경 단계는 6초 진행, 적·순찰 이동 및 감지, 함정·환경 효과, 지속시간·제한 시간 갱신 순서로 처리한다. 저장된 순찰 경로가 없으면 GM이 매 단계 주변 적의 이동과 환경 변화를 판단하고, 제안된 상태 변경은 검증한 뒤 적용한다. 도중 조우가 생기면 환경 처리를 멈추고 조우를 먼저 해결한 뒤 남은 환경 처리를 이어간다.
- 우선권은 전술 이동을 시작할 때 한 번 정하고, 해당 전술 이동 모드가 끝날 때까지 유지한다.
- 맵이 필요한 시츄에이션이 시작되면 전술 이동 모드를 시작한다. 해당 시츄에이션이 끝나거나 맵 없이 요약하는 이동으로 전환하면 종료한다. 전투가 시작되면 전술 이동 모드를 끝내고 전투 차례로 전환한다.

## 시츄에이션과 맵 준비

- 모험 첫 시작은 `opening` 속성이 지정된 시츄에이션을 바로 선택한다. 전체 후보 중 시작 시츄에이션을 고르는 별도 모델 호출은 하지 않는다.
- 모험 시작 시 전체 단계의 상세 내용을 미리 생성하지 않는다. 첫 단계의 후보 시츄에이션만 준비하고, 이후 단계의 내용은 그 단계에 도달했을 때 준비한다.
- 다음 시츄에이션을 고를 때는 현재 단계의 후보 전체와 선택 가능 여부를 GM에게 제공해 하나를 고르게 한다. 선택 후 선택된 시츄에이션의 내용을 읽고 필요한 근거를 검색해 최종 GM 입력을 구성한다.
- 시츄에이션 후보 조회와 시나리오 인물·장소·사건 요소 검색은 별도 MCP 조회다. 후보 조회는 저장된 현재 단계 상세 자료와 진행 상태에서 선택 가능한 후보만 반환한다. 에이전트가 새 식별자를 만들지 않으며, 응답에는 조회 결과의 실제 후보 식별자만 쓴다.
- 출력 계약은 `TRANSITION`일 때 후보 식별자를 필수로 하고, `CONTINUE`일 때는 `null`만 허용한다. 서버는 선택된 식별자가 현재 단계에서 실제 선택 가능한지 검증한다.
- 맵 필요 여부는 시츄에이션의 속성으로 정한다. GM이 매번 임의로 필요 여부를 추론하지 않는다.
- 맵이 필요한 시츄에이션에 진입할 때 대상 시츄에이션의 맵과 초기 상태를 준비한다. 여기에는 적·함정의 칸 배치, 문 상태와 잠금 여부 등이 포함된다. 진입 서술과 관련 근거, 해당 맵 자료를 함께 사용해 그룹 시작 위치를 제안·검증하고, 성공한 뒤에만 진입을 공개한다. 맵이 필요하지 않은 시츄에이션은 맵 준비를 건너뛴다. opening도 그 시츄에이션의 `mapNeeded` 값에 따라 같은 절차를 따른다.
- GM은 시츄에이션을 읽고 관련 근거를 검색해 사실을 반영하며, 근거로 정해지지 않은 장면 배치에는 GM의 판단을 사용할 수 있다. 시나리오 근거에 적힌 사실과 GM이 정한 배치를 구분한다.
- 맵과 초기 배치가 준비되면 사용자 승인 대기 없이 시츄에이션을 시작한다. 필요하지 않은 시츄에이션은 맵 없이 진행한다.
- 적·함정의 비공개 위치와 상태는 플레이어에게 노출하지 않는다.

## 위협 발견과 조우

- 이동 중 위협을 알아차리는지 캐릭터별로 판정한다. 대열상 발견 가능한 위치, 각 캐릭터의 지각 능력, 이동 방식과 숨김 상태를 반영한다.
- 한 캐릭터가 위협을 발견하면 모든 그룹의 이동을 멈춘다. 처음 발견한 사실은 그 캐릭터만 안다.
- 발견한 캐릭터가 동료에게 알리면 그룹도 알게 된다. 알리는 방식이 적에게 들릴 수 있는지는 상황에 따라 GM이 판정한다.
- 적이 먼저 일행을 발견하면 GM이 적의 행동을 정해 서술하고, 사용자가 대응한다. 발견 자체만으로 전투를 자동 시작하지 않는다.
- 조우한 쪽은 공격·대화·도주·대기를 선택할 수 있다. 적대 행동으로 전투가 시작될 때 기습을 판정한다.
- 전투 시작 시 위협을 알아차리지 못한 개체만 기습 상태가 될 수 있다. 양쪽 모두 숨으려 하지 않았다면 서로 자동으로 알아차린다.

## 주문·기술 보유 정보와 상세 정의

- 캐릭터 시트에는 배워서 사용할 수 있는 주문·기술의 식별자만 둔다. 상세 정의는 현재 모험의 데이터베이스에 능력 하나당 한 벌 저장한다.
- 한 벌의 상세 정의는 기존 `StructuredSpellDefinition` 주문·행동 구조를 바탕으로 한다. 기존 사거리와 대상·범위 구조를 재사용하고, 능력 ID·짧은 설명·행동 종류·사용 시점·자원 비용·시야 조건·판정 방식과 효과·지속시간·집중·발동 조건·예외·원문 출처 위치를 포함한다. 에이전트 출력과 DB 저장은 동일한 고정 JSON 구조를 사용하고, 모든 필드를 포함하며 해당 능력에 적용되지 않는 값은 `null`로 둔다. 정의되지 않은 추가 필드는 허용하지 않는다.
- 자원 비용은 필요한 자원 ID, 수량, 소모 시점을 가진 구조화된 항목으로 저장한다. 각 캐릭터 시트에는 해당 캐릭터가 보유한 자원 ID, 현재량·최대량, 회복 조건을 명시하며, 능력 비용은 이 목록의 자원을 참조한다. 자원이나 효과가 달라지는 선택은 사용 전에 사용자에게 묻는다.
- 휴식 등 회복 조건이 충족됐는지는 GM이 판정하고, 충족되면 엔진이 캐릭터 시트에 저장된 회복 규칙에 따라 자원 현재량을 갱신한다.
- 능력을 배우는 시점에 상세 정의가 없으면 현재 모험에서 허용된 룰북·시츄에이션 자료를 RAG로 검색한다. 에이전트는 근거를 조합해 엔진이 처리할 수 있는 고정 구조로 정의를 반환한다.
- 모험 시작 전에 캐릭터가 이미 보유한 초기 능력은 모험 시작 시 같은 절차로 준비한다. 이후 능력은 캐릭터가 배울 때 준비한다. 시츄에이션 선택이나 전체 룰북·ScenarioPackage 자체는 준비 계기가 아니다.
- 근거 충분성은 검색 결과의 개수로 정하지 않는다. 엔진 처리에 필요한 각 규칙 항목이 근거와 출처 위치로 뒷받침되어야 한다. 항목에 근거가 부족하거나 출처가 충돌하면 재검색·복구하고, 끝까지 해결되지 않을 때 사용자에게 원문 입력을 요청한다.
- 구조와 근거를 검증한 에이전트 응답은 사용자 검토를 기다리지 않고 현재 모험 데이터베이스에 저장한다. 실제 사용 때와 이후 사용 때는 저장된 정의를 조회한다.
- 검색·생성·검증이 실패하면 복구를 재시도한다. 모든 복구가 실패하면 사용자에게 원문을 확인해 필요한 내용을 입력하도록 요청한다. 입력한 정의도 필수 구조와 근거를 검증해 현재 모험에 저장한다.
- 상세 정보 준비와 저장이 끝나야 능력 습득을 완료한다. 사용자가 원문 입력을 취소하면 습득 절차를 완료하지 않고, 해당 식별자를 배운 능력으로 확정하지 않는다.
- 상세 정의의 재사용 범위는 현재 모험으로 한정한다. 다른 모험에는 자동 공유하지 않는다.
- 데이터베이스에는 원문 내용이 아니라 원문을 찾을 수 있는 출처 위치만 저장한다. 근거가 서로 충돌하면 에이전트가 임의로 고르지 않고 사용자에게 확인한다.
- GM은 MCP를 통해 현재 모험·캐릭터·능력 ID를 지정해 상세 정의를 조회한다. 이 범위에 속한 캐릭터가 배운 능력의 정보만 반환하며, 조회 결과는 실행 판단에 필요한 상세 정의와 출처 위치를 포함한다.
- MCP 조회 응답은 상세정보 반환, 배운 능력의 상세정보 복구 필요, 배우지 않았거나 찾을 수 없는 능력, 조회 오류를 구분한다. 배우지 않았거나 찾을 수 없는 능력에는 상세정보를 노출하지 않는다.
- 학습이 완료된 능력의 정의가 예기치 않게 조회되지 않으면 GM은 내용을 추측하지 않고 해당 사용 처리를 멈춘다. 배울 때의 RAG 검색·복구 절차로 정의를 복구한 뒤 같은 사용 요청을 이어서 처리한다.

## 전투·비전투 실행과 자원 소모

- 전투 실행과 비전투 실행은 별도 엔진 흐름으로 처리하되, 현재 모험에 저장된 같은 상세 정의를 사용한다.
- 전투 중 사거리·대상·시야·효과 범위 미리보기와 실행 검증은 현재 모험의 능력 상세 정의와 전투 토큰 위치를 사용한다. 실행 시점에 최신 토큰 위치와 상태로 다시 검증한다. 엔진이 효과를 처리할 수 없으면 GM이 전체 해결을 맡는다.
- 사용자가 주문·기술을 사용했다고 선언하고 실행이 확정되면, 의도한 효과가 실패해도 사용 자원을 소모한다. 적의 선택은 GM이 정하고 엔진이 검증한다.
- 같은 사용 요청의 재전송·재시도는 자원을 한 번만 소모한다. 별도의 새 사용 요청은 각각 별도로 소모한다.
- 전투에서는 전투 엔진이 정의된 효과와 규칙을 처리한다. 엔진이 효과를 처리하지 못하면 GM이 효과 판정과 전투 상태 변경까지 포함해 해당 능력의 전체 해결을 대신한다. 자원 소모는 계속 전투 처리 흐름에서 결정적으로 확정한다.
- 비전투에서 덩굴을 태우는 것처럼 환경에 응용할 때는 전투 효과 엔진을 적용하지 않는다. GM이 상황에 맞는 판정과 서술을 맡고, 자원 소모는 비전투 처리 흐름에서 결정적으로 확정한다.
- 반응 능력도 지원한다. 다른 참가자의 차례 중 발동 조건이 충족되면 해당 능력의 조건과 기존 전투 흐름에 따라 사용할 수 있다.

## 필수 시츄에이션 트리 (2026-10-19)

- 필수 시츄에이션은 루트 하나를 갖는 트리다. 루트 외의 모든 시츄에이션에는 부모가 정확히 하나 있어야 한다. 여러 자식으로 분기할 수 있으며 순환·여러 부모·여러 루트·분리된 가지는 허용하지 않는다.
- 생성 입력과 구조화 출력 계약, 저장 전 검증에 같은 규칙을 적용한다. 부모는 이미 출력한 시츄에이션의 목록 인덱스로 지정하며 저장 식별자는 서버가 부여한다.
- RAG 원문 조각 수와 추출된 시츄에이션 수는 같을 필요가 없다. 검증 로그는 검색 조각 수와 시츄에이션 수를 구분하고 실패한 트리 규칙을 기록한다.

## 지도 자르기와 격자 보정 검증 (2026-10-19)

- Potent Brew 원본 지도의 기대값은 22열·23행이다. 제목과 여백을 포함한 페이지 전체를 지도 영역으로 쓰지 않는다.
- 원본 격자 검출 실패로 만든 대체 격자는 사용자 확정 격자로 취급하지 않는다. 지도 자르기·격자 맞춤·벽·문 편집과 저장은 모험 준비 단계에서만 한다. 진행 중인 모험 화면에서는 지도를 편집하지 않고 저장된 설정을 사용한다.
- 시츄에이션에 진입할 때의 서술과 보정된 지도로 시작 위치를 판정한다. 시작 위치 후보가 없으면 재시도 후, 지도 설정은 그대로 둔 채 시작 칸만 선택하는 흐름을 제공한다.
- E2E는 모험 준비 화면에서 원본 자료의 자르기·격자 보정·저장 절차를 수행하고, 저장된 22×23 격자와 이후 지도 진입·이동을 검증한다. 기대값을 자동 생성된 대체 격자 수치로 바꿔 통과시키지 않는다.

- 시작 위치 추론 후보가 0개이면 최초 호출 이후 최대 5회 재시도한다. 후보가 생기면 즉시 재시도를 멈추고, 모두 실패하면 수동 시작 위치 선택 흐름을 제공한다.

- 지도 전환은 장면 이름·서술 변경이 아니라 현재 시츄에이션의 맵 ID로 판단한다. 같은 맵 ID는 현재 지도와 위치·격자·벽·문·안개를 유지한다. 다른 맵 ID는 해당 모험에서 저장된 지도를 조회해 재사용하고, 없을 때만 준비한다. 맵이 필요 없으면 지도 표시를 해제한다. 기존 지도는 준비 명령 이력의 맵 ID 연결도 조회해 보존한다.

- 내부 지도 재사용 조회(`/internal/v1/combat-maps/reuse`)는 모험·소유자·시츄에이션의 맵 ID로 저장된 지도를 찾는다. 재사용 가능하면 공간 자료 준비 이전에 반환한다. 지도 연결은 `MAP_DEFINITION_ID`, 방문 완료는 `MAP_ENTERED` 내부 속성에 저장하며, 기존 데이터는 지도 준비·활성화 명령 이력에서도 확인한다. 지도 미존재(404)만 새 준비로 이어지고, 검수 필요 응답은 검수 요청으로 유지한다.

- 환경 단계에서도 지도 이미지를 별도 이미지 입력으로 전달한다. 이미지 Base64를 텍스트 프롬프트에 넣지 않는다. 지도 이미지와 같은 좌표 기준의 격자·벽·문·토큰·발견 상태를 구조화한 텍스트로 전달하며, 엔진이 제안 경로를 검증한다.


## 탐험 그룹과 전투 토큰 전환 사용자 승인 (2026-10-23, plan-368)

- 승인 근거: 사용자가 각 그룹 위치를 기준으로 가장 가까운 적 방향을 전열로 삼는 배치, 전원 배치 불가 시 지도 무변경·배치 대기와 Solo Player의 전체 배치, 지도 소유자의 원자적·재시도 안전 전환 및 종료 복원을 명시적으로 승인했다. UC-005·BR-44·BR-45·AC-36에 연결하며, 이 기록은 승인된 목표·구현 전이다.
- 각 탐험 그룹 토큰 칸을 기준점으로 사용한다. 가장 가까운 적은 기존 지도 거리로 정하고 같은 거리이면 서버 적 토큰 식별자 오름차순을 사용한다. 적이 없거나 기준점과 같은 칸이면 북쪽이다. 적까지 열·행 차이의 부호로 8방향을 정한다.
- 다음 수치와 같은 대열의 순서는 사용자 승인 원문에 포함되지 않은 후속 기계적 설계 선택이다. 승인 원문은 [요청·승인 기록](request.md)에 보존한다. 기계적 고정 배정은 전열 깊이 0, 중열 뒤 1칸, 후열 뒤 2칸이다. 같은 대열은 서버 캐릭터 식별자 순으로 수직 옆 간격 0, -1, +1, -2, +2, …에 배정한다. 전열 방향 (dx, dy)에 수직인 방향은 (-dy, dx)이고, 배정 칸은 기준점 - 깊이 × 전열 방향 + 옆 간격 × 수직 방향이다. 하나라도 지도 범위·벽·닫힌 문·통과 불가 지형·도달 가능성·기존 점유·그룹 안팎 중복 조건에 맞지 않으면 다른 빈칸으로 자동 이동시키지 않는다.
- 전원 배치를 확보하지 못하면 지도·토큰·안개를 그대로 유지하고 배치 대기를 저장한다. Solo Player가 기존 전투 지도 화면에서 전원의 배치를 제출하고 지도 소유자가 전체 구성원·중복·화면에 표시된 최신 지도 버전·공간 조건을 검증한 뒤 같은 작업을 재개한다. 제출 버전이 오래되면 지도나 배치 상태를 바꾸지 않고 거부한다.
- 모험 진행은 그룹·대열·전투 진행 상태와 전투·진입/종료 방향별 서버 작업 식별자를 저장한다. 지도 소유자는 전체 토큰 교체와 작업 결과를 기존 저장 경계에서 원자적으로 저장한다. 재시도·응답 유실·재시작은 같은 식별자로 저장 결과를 조회·재개하며 중복·부분 전환을 허용하지 않는다. 지도 완료 응답 확인 뒤에만 전투 진행 상태를 확정한다. 새 분산 트랜잭션 기반 시설은 도입하지 않는다.
- 종료 시 원본 그룹 식별자·구성원·대열을 복원하고 그룹 토큰은 전열 캐릭터의 현재 칸에 둔다. 전열이 여러 명이면 서버 캐릭터 식별자 순 첫 구성원을 사용한다. 서로 다른 그룹은 자동 병합하지 않는다. #367의 적 토큰·전투 참여자 대응, 적별·캐릭터별 인지와 참여자별 첫 차례 기습은 그대로 보존한다.
