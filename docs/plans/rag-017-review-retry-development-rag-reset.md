# RAG-017: 페이지 검토 재시도와 개발 RAG 데이터 초기화

- Issue: #193
- Parent: #189
- Status: planned
- Dependencies: RAG-014, RAG-015

## 구현 목적

검토가 필요한 특정 페이지만 전처리 프로세스로 재시도하여 새 후보를 검증·공개하고, 개발 환경에서는 명시적인 보호 장치 아래 RAG DB 상태만 초기화할 수 있게 한다.

## 구현 범위

- 페이지 선택 재시도를 `PreprocessingProcessPort.retryPages`로 연결하고, 후보 버전/페이지 상태/재시도 lease를 일관되게 갱신한다.
- 재시도 성공 후 RAG-015의 공개 규칙으로만 새 버전을 벡터 공개하고, 실패/중복 요청은 기존 공개 검색 결과를 바꾸지 않는다.
- 상태 API에 사용자용 재시도 가능 여부와 안전한 진단을 제공한다.
- development profile에서만 동작하는 명시적 확인 방식의 RAG DB reset 경로를 제공한다. 문서·업로드 자산·`docs/` 파일은 삭제하지 않는다.
- production 및 profile 미확정 환경에서 reset 요청을 거부한다.

## 제외 범위

- 최초 전처리 연결은 RAG-014, 공개 벡터의 모델/전환은 RAG-015, 시나리오 인용은 RAG-016에서 구현한다.

## 완료 조건

- 검토 대상 페이지만 재시도되어 새 후보가 만들어지며, 검증·색인 성공 전에는 공개 검색이 바뀌지 않는다.
- 재시도는 중복 실행과 stale 응답을 안전하게 처리한다.
- 개발 RAG reset은 DB 레코드와 벡터만 비우고 파일 자산을 보존하며, production에서는 실행될 수 없다.

## 검증

### 정책 단위 테스트

- 페이지 재시도의 idempotency, lease, stale 응답, 공개 버전 불변성을 단위/통합 테스트한다.
- reset이 development 명시 확인 없이는 거절되고 production에서 항상 거절되는지, 관련 DB 테이블/벡터만 비우는지 검증한다.
- reset 뒤 재업로드했을 때 과거 벡터와 후보 상태가 검색되지 않는지 pgvector 통합 테스트로 검증한다.

### UI-엔터티 E2E

- `NEEDS_REVIEW` 문서의 특정 페이지를 UI에서 재시도해 검증·색인·검색 가능 상태가 되는 실제 여정을 검증한다.
