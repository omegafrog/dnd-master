# 모험 상황 단계별 Codex 하위 작업 출력 계약 계획

## 목적

모험 준비의 상세 상황을 한 번의 Codex 오케스트레이션 요청에서 단계별 하위 작업으로 병렬 생성한다. 요청한 단계 ID와 각 상세 상황 출력 JSON 스키마를 정확히 연결하고, 반환 단계가 누락·중복·추가되거나 구조가 다르면 결과를 저장하지 않는다.

## 플랫폼 확인

설치된 Codex CLI `0.162.1`의 `app-server` schema를 확인했다. `thread/start.dynamicTools`는 실험적 기능이며, 초기화에서 `capabilities.experimentalApi=true`를 보내고 `item/tool/call`에 JSON-RPC 응답을 돌려줘야 한다. 동적 도구 사양은 `type=function`, `name`, `description`, `inputSchema`를 사용한다. `turn/start.outputSchema`는 해당 turn의 최종 응답에 적용된다.

앱은 동적 위임 도구 하나를 등록한다. 그 도구는 코드에 보존된 모든 단계 작업을 최대 네 개씩 병렬 실행하고, 각 하위 app-server turn에 해당 단계의 `outputSchema`를 직접 전달한다. 각 자식 응답은 JSON 중복 키를 거부하고 같은 스키마로 다시 검증한다. 부모의 최종 응답도 같은 방식으로 검증하며, `stages` 값이 검증된 자식 출력과 의미상 동일하지 않으면 거부한다. 도구 호출 누락, 잘못된 단계 ID, 반복 호출, 자식 실패와 부모 응답 불일치도 저장 전에 실패 처리한다.

자식 실행은 사용자 PC의 Codex app-server에서 별도 프로세스로 실행해 기존 사용자 로그인 정보를 사용한다. 서버의 Codex를 대신 사용하지 않는다. 자식 deadline은 부모 turn의 남은 시간으로 설정하며 하나라도 실패하면 나머지 작업을 취소하고 자식 프로세스를 종료한다. 이 기능은 내장 `spawn_agent` 호출이 아니라 앱이 실행하는 별도 Codex app-server 작업이다.

## 변경 범위

- 각 단계 작업에 고정 `stageId`, 해당 단계의 작업 내용과 출력 JSON 스키마를 구조화된 요청 필드로 함께 전달한다. prompt 문자열에서 작업이나 ID를 다시 읽지 않는다.
- 부모 Codex에 동적 위임 도구를 제공하고 요청에 포함된 전체 고정 단계 ID 집합에 대해서만 실행을 허용한다.
- 각 자식 turn에 단계별 출력 JSON 스키마를 전달하고 결과를 코드에서 다시 검증한다.
- 취합 출력 JSON 스키마에서 요청한 모든 ID를 필수로 지정하고 추가 ID를 금지한다. 부모 출력을 검증된 자식 결과와 비교해 불일치하면 거부한다.
- 상세 상황 객체 변환·검증 실패 및 일괄 생성의 동적 참조 번호 오류는 별도 GM 요청으로 고치지 않는다.
- 실패·취소 시 실행 중인 자식 프로세스를 종료하고 중복 도구 호출을 재실행하지 않는다.
- 개발 진단 로그에는 요청 ID, 단계 ID, 예상·반환 ID, 입력·응답 구조, 검증 결과와 소요 시간을 남긴다. 프롬프트·응답 원문은 기록하지 않는다.
- 앱의 Codex JSON 스키마 검증기는 Spring AI의 MCP 모듈이 사용하는 `2.0.0`에 맞춘다. 사용자 PC 실행 환경의 실제 의존성 묶음에서 검증 API 호출을 확인한다.
- 하위 작업 실패를 위임 도구에 돌려준 뒤 부모 turn을 계속 기다리지 않고 즉시 실패 처리한다. 형제 작업 취소에서 생긴 중단은 시간 초과와 구별한다.

## 검증

- HTTP와 relay 계약이 구조화된 단계 작업과 각 스키마를 보존하는지 확인한다.
- 동적 위임 도구가 고정된 단계 ID 집합만 받고 자식 turn마다 개별 출력 스키마가 전달되는지 확인한다.
- 자식 결과 검증, 위임 누락, 부모 결과 수정·누락 거부 및 deadline 실패 시 형제 작업 종료를 확인한다.
- 취합 schema가 정확한 ID를 필수로 요구하고 추가 ID를 막으며 정상 결과가 기존 상세 상황 객체로 변환되는지 확인한다.
- `user-pc-agent`의 실제 runtime classpath에서 `SchemaRegistry` 검증 호출이 성공하는지 테스트한다. Codex 하위 작업 실패 시 부모 turn 즉시 종료와 형제 프로세스 정리도 확인한다.
- relay 경로는 전송 계약 테스트로 확인하고, 로그인된 사용자 PC의 실제 Codex app-server에 두 개의 작은 작업을 보내는 smoke를 별도로 수행한다. 규칙 원문이나 큰 E2E 자료는 사용하지 않는다.

실제 smoke에서는 서로 다른 `stageId`와 각기 다른 문자열 `enum` 스키마를 가진 두 작업이 동시에 시작되고, 두 자식 출력이 각 스키마를 통과했다. 부모는 두 결과를 변경 없이 최종 schema로 반환했으며 코드의 의미상 동일성 검증을 통과했다. 두 자식 app-server 프로세스 모두 정상 종료했다. 선택 모델은 사용자 PC Codex 기본 설정(`model=default`)을 사용했다. 이 smoke는 relay를 거치지 않았으며 relay 보존은 별도 전송 계약 테스트로 검증했다. 진단 로그는 `/tmp/codex-stage-smoke-final.log`에 있다.
