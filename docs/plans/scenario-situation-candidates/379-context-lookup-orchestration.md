# 턴 조회 에이전트와 오케스트레이션 구현 계획

## 목적

턴 실행을 조회·진행·저장까지 한 AI가 맡지 않도록 분리한다. 오케스트레이터는 순서와 상태 확정을 담당하고, 조회 담당 AI와 턴 진행 AI는 각각 하나의 고정 JSON 계약으로 호출한다.

## 실행 흐름

1. 오케스트레이터가 현재 모험 상태를 읽고, 활성 시츄에이션이 없으면 필수 선행 관계에 따라 준비된 시츄에이션을 선택한다.
2. 조회 담당 AI를 별도 문맥에서 한 번 호출한다. 입력에는 이번 행동, 현재 장면·시츄에이션, 선택된 준비 시츄에이션, 게임 상태, 플레이 중 추가 사실, 잠긴 시나리오 모델, 관련 장기 모험 기록, 검색 범위와 이미 확인한 고정 문서 근거 ID를 포함한다. 전체 대화 기록은 포함하지 않는다.
3. 한 번의 dense 임베딩 검색 요청에서 허용된 STORYBOOK과 RULEBOOK 문서를 함께 검색한다. 이 요청은 BM25를 호출하지 않는다. 검색 결과에서 출처별 상위 5개까지를 바로 선택해 추가 재정렬·충분성 판단 AI 호출 없이 조회 담당 AI에 넘긴다.
4. 턴 진행 AI는 전체 진행 문맥과 조회 결과를 받아 턴 결과를 계획한다. 오케스트레이터가 결과·도구 요청을 검증하고 도구를 순서대로 실행한 뒤 상태를 함께 확정한다.

## 문맥과 중복 방지

- 관련 장기 모험 기록은 조회에 전달해 이미 알려진 사실을 다시 찾지 않도록 한다. 이전 대화 전체는 조회에 전달하지 않는다.
- 고정된 문서 근거만 `IMMUTABLE_DOCUMENT:RULEBOOK:<문서 ID>:<추출 버전>:<위치>` 또는 `IMMUTABLE_DOCUMENT:STORYBOOK:<문서 ID>:<추출 버전>:<위치>`로 식별한다.
- 이전에 확정된 턴의 근거 묶음에서 ID를 재구성해 다음 조회의 제외 목록으로 전달한다. 데이터베이스 구현은 근거 묶음만 읽고 대화·응답 전체를 읽지 않는다. 이미 확인한 고정 문서 근거는 검색 응답에서 제외하며, 추출 버전이 달라지면 새 근거로 취급한다.
- 게임 상태, 플레이 중 추가 사실, 현재·준비된 시츄에이션과 판정 결과는 변할 수 있으므로 고정 문서 근거처럼 제외하거나 캐시하지 않는다.

## 에이전트 JSON 계약

- 조회 입력·출력과 검색 요청에 버전 경로의 JSON Schema를 둔다. 요청 경계는 미정의 필드를 거부하고, 조회 출력은 상태·자료형·정확한 필드 수·상태별 값을 검증한다.
- 조회 출력은 발견 또는 미발견, 간단한 답과 잠긴 시나리오 요소 식별자를 반환한다. 문서 검색 응답은 출처 유형·문서·추출 버전·인용 위치가 서버가 허용한 검색 범위와 일치하는지 검증한다.
- 확정된 필수 시츄에이션의 흐름은 준비된 시츄에이션 집합과 선행 관계를 기준으로 선택한다. 검색 결과만으로 원문 이야기의 필수 상황을 빠짐없이 찾았다고 주장하지 않는다.

## 입력 토큰 캐시

- 조회 AI 요청에서 고정 지침과 출력 계약을 앞에 두고, 행동·상황·장기 기록·근거 ID 등 바뀌는 값은 뒤에 둔다.
- OpenAI 지원 모델은 캐시 입력 토큰 사용량을 관측해 실제 적중과 절감 여부를 확인한다. 지원이 확인되지 않은 제공자에는 절감을 가정하지 않으며, 캐시 길이를 채우려고 입력을 인위적으로 늘리지 않는다.

## 구현 범위와 검증

- 기존 `RuntimeTurnApplicationService`, `RuntimePlayerActionEvidenceAcquirer`, `RuntimeFactLookupService`, typed lookup endpoint와 근거 검색 계약을 재사용해 경계를 확장한다. 새 배포 서비스는 만들지 않는다.
- 계약 테스트: 엄격 JSON Schema 입력·출력, 한 번의 혼합 문서 dense 검색, BM25·재정렬·충분성 판단 미호출, 장기 기록·준비 시츄에이션 전달, 출처·버전 범위 확인, 기존 ID 제외와 추출 버전 변경 시 재검색, 캐시 사용량 관측을 확인한다.
- 턴 통합 테스트: 시츄에이션 선택 → 단일 조회 요청 → 턴 진행 AI → 검증·순차 실행 → 상태 확정 순서를 확인하고, 굴림 대기·재시도·재시작에서도 선택·근거 ID가 중복 확정되지 않는지 검사한다.
- 단위·계약 테스트 통과 뒤 `EXE.md`에 따라 실제 턴 흐름을 E2E로 검증한다.
