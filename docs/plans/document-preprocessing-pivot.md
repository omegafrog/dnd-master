# 문서 전처리 전환 계획

## 목표

PDF의 제목 계층·표 격자를 완벽히 복원하는 것을 게시 조건으로 삼지 않는다. 모험 준비에 쓸 수 있는 페이지와 자료를 최대한 확보하고, 사용할 수 없는 페이지·양식·지도 같은 자료는 원본과 출처를 유지한 채 별도로 보존한다. 일부 페이지가 실패해도 필요한 시나리오 자료가 남아 있으면 준비를 계속한다.

## 유지할 기반

- 업로드한 원본 파일과 파일 해시, 소유자 범위 중복 확인
- 페이지 번호와 원문 위치를 연결하는 출처 정보
- 페이지별 처리 결과와 실패 원인, 재처리 이력
- 텍스트 정규화와 출처 범위를 보존하는 검색용 분할
- 반복 머리글·바닥글 제거
- 양식·지도·삽화·핸드아웃의 원본 보관 및 관련 페이지 연결
- 기존 구조 정답 평가 도구: 전처리 개발·회귀 비교용으로만 유지
- 북마크·인쇄 목차: 검색에 쓸 보조 정보로만 보존

## 기본 처리에서 제외할 것

- 제목 계층 추론을 게시 조건으로 사용하지 않는다.
- 페이지 사이의 절·문단 관계를 추론하지 않는다.
- 자체 표 격자 복원을 기본 경로에서 사용하지 않는다. 표는 추출 가능한 텍스트로 검색하고, 필요하면 기성 문서 분석기나 OCR을 대체 경로로 사용한다.
- `section_path`가 없거나 불확실하다는 이유로 페이지·문서를 차단하지 않는다.

## 처리와 준비 상태

자료 처리 결과와 모험 준비 가능 여부를 분리한다.

| 자료 상태 | 의미 | 준비 처리 |
|---|---|---|
| 사용 가능 | 페이지 텍스트 또는 활용 가능한 자료가 출처와 함께 확보됨 | 검색 및 준비에 사용 |
| 일부 확인 필요 | 일부 페이지만 읽지 못했거나 보조 자료 처리가 실패함 | 확보된 자료로 진행하고 영향 범위 표시 |
| 준비 차단 | 전체 파일을 읽지 못했거나 필수 시나리오 내용·출처를 확보하지 못함 | 누락된 필수 자료를 알리고 중단 |

양식 분류와 검색 활용 여부는 분리한다. 빈 양식은 일반 검색에서 제외하고 원본 페이지 자산으로 보관한다. 이미 작성된 캐릭터 시트는 텍스트와 출처를 보존해 검색·준비에 활용할 수 있어야 한다. 사용자가 지정한 파일 역할과 복수 태그는 페이지 분류가 덮어쓰지 않는다.

## 전환 순서

1. 페이지별 텍스트 추출과 검색용 분할을 구조 검증과 분리하고, 사용 가능한 페이지가 있으면 부분 산출물을 만든다. 실패 페이지는 원본과 진단 정보에 남긴다.
2. 검색 발행이 `사용 가능` 페이지를 발행하고 실패 페이지의 진단을 함께 보존하도록 바꾼다. 원본 출처가 없거나 잘못된 청크는 계속 거부한다.
3. 문서 처리 상태와 모험 준비 상태를 별도로 표현한다. 일부 자료 확인 필요 상태를 번들 구성과 준비 흐름에 전달한다.
4. 페이지 분류를 확장해 빈 양식·작성된 양식·지도·삽화·핸드아웃을 검색 본문과 별도 자산으로 구분한다.
5. 기본 PDF 추출 결과가 사용 불가한 페이지에 Docling/OCR 대체 처리를 연결한다. 대체도 실패하면 해당 페이지만 미완료로 남긴다.
6. 파일 해시와 추출기 버전으로 불변 추출 결과를 재사용한다. 새 시나리오와 자료만 처리한다.
7. 개발용 구조 평가 자료로 기존 방식과 새 방식의 누락·출처·검색 품질을 비교한다. 낮은 점수는 검토 정보로 전달하고, 그 자체로 모험 준비를 일괄 차단하지 않는다.

## 우선 완료 기준

- 제목 계층이나 `section_path` 없이도 출처가 명확한 텍스트 청크를 발행할 수 있다.
- 일부 페이지가 실패해도 정상 페이지의 검색 자료가 발행된다.
- 실패 페이지 번호·실패 이유·사용한 대체 처리 결과가 보존된다.
- 빈 양식은 검색 청크에 들어가지 않고 원본 자산으로 남는다. 작성된 양식의 실제 내용은 보존된다.
- 필수 시나리오 내용이나 출처가 없는 경우에는 준비 완료로 표시하지 않는다.
- 기본 룰북은 파일 해시와 추출기 버전이 일치하면 재처리하지 않는다.
- 기존 구조 정답 평가기는 개발 도구로 계속 실행할 수 있다.

## 현재 코드 경계

Python `ExtractionVersionService`와 `PdfDocumentParser`가 현재 페이지 구조 검증을 먼저 수행하며, 모든 페이지가 승인되어야 청크 산출물을 만든다. Java `RulebookPipelineApplicationService`는 `READY` 결과만 발행하고, `RagExtractionPublicationService`도 검토 페이지가 하나라도 있으면 발행을 거부한다. 이후 `ScenarioBundleApplicationService`가 부분 처리 상태를 일부 허용하더라도 `NEEDS_REVIEW`는 제외한다. 따라서 첫 전환은 페이지별 검색 산출물 생성과 Java 검색 발행 계약을 함께 바꾸는 작업이다.

## 첫 전환 단계의 응답 계약

- 페이지 `VALIDATED`: 텍스트와 페이지 출처를 확보했고 검색에 사용할 수 있음.
- 페이지 `USABLE_WITH_WARNINGS`: 텍스트와 페이지 출처는 확보했지만 구조 진단에서 확인할 항목이 남음. 구조 진단만으로 검색 사용을 막지 않음.
- 페이지 `EXCLUDED_FORM`: 일반 검색에서 제외한 양식 페이지. 원본 PDF와 페이지 상태는 보존함.
- 페이지 `NEEDS_REVIEW`: 텍스트나 출처를 안전하게 확보하지 못해 검색에서 격리한 페이지.
- 실행 `READY`: 검색 가능한 페이지가 있고 검토 페이지가 없음.
- 실행 `PARTIAL`: 검색 가능한 페이지와 경고 또는 검토 페이지가 함께 있음. 검색 가능한 페이지만 청크를 발행함.
- 실행 `NEEDS_REVIEW`: 검색 가능한 텍스트가 없어 발행하지 않음.
- 검색 발행 뒤 문서 상태 `INDEXED_WITH_WARNINGS`는 번들에 포함할 수 있고, 페이지별 경고를 모험 준비 화면에 전달함.

이 단계는 부분 발행과 모험 준비의 연결을 먼저 바꾼다. 작성된 양식과 빈 양식의 분류, 지도·이미지 파일의 별도 저장, Docling 대체 처리, 파일 해시와 전처리기 버전만으로 공유하는 재사용은 후속 전환 항목이며 아직 완료로 간주하지 않는다.
