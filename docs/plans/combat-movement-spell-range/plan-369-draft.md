# [전투 이동·주문 07/15] 전투 이동 중 사건 판정·서술과 차례 유지

## 상태

Planned

## 의존성

#368

## 구현 목적

전투 이동 중 GM 판정이 필요한 사건을 처리하면서 이미 이동한 위치·이동량을 보존하고 같은 플레이어 차례에서 다음 행동을 기다리는 기존 이동 흐름을 구현한다.

## 범위

- 계획 식별자: plan-369.
- 사용자는 경로를 확인한다. Combat Map은 칸별 이동을 검증하고 실제 통과 경로·비용·중단 원인을 Adventure Runtime으로 전달한다.
- 발견·함정·반응 등 GM 처리가 필요한 사건은 적 토큰이 없어도 전용 고정 GM 응답 계약으로 처리한다. 백엔드는 스키마와 현재 작업·차례를 검증하며 이동량·토큰 위치·턴 종료는 서버 소유자가 결정한다.
- 확인한 경로의 남은 칸은 자동 진행하지 않는다. 실제 위치·이미 사용한 이동량은 보존하고 GM 처리 결과가 확정된 뒤 같은 플레이어 차례의 다음 입력을 기다린다.
- 기존 CombatEncounter, CombatActionApplicationService, MapMovementCoordinator, Combat Map operation/recovery 경계를 확장한다. 새 aggregate, module, deployment unit, 메시지 broker는 추가하지 않는다.
- 지도 UI 이동과 `/combat/actions` 이동 제출 경로 모두 같은 사건 처리·멱등 복구 규칙으로 연결한다.

## 수용 기준

- 요구사항 추적: AC-05, AC-07, AC-08, AC-16, BR-05, BR-08, BR-16, BR-18, BR-19, EX-08, G-03, ST-UC-002-01, ST-UC-002-02, ST-UC-002-03, UC-002.
- 소유 경계: 전투 차례·이동량 정본(CombatEncounter), 전투 행동 처리 서비스(CombatActionApplicationService), 지도 이동 조정기(MapMovementCoordinator), 전투 지도 서비스(Combat Map); 시행 지점: 전투 지도 서비스가 실제 중단 칸·이동량을 모험 진행 서비스로 전달하고, 전용 GM 응답과 현재 작업·차례를 검증한 뒤 미완료 작업을 이어서 처리.
- UC-002, BR-05/08/16/18/19, AC-05/07/08/16, EX-08, ST-UC-002-01~03을 충족한다. CombatEncounter는 차례·이동 예산의 정본이고 Combat Map은 실제 토큰 위치·이동 결과의 정본이다. 행동 전·사이·후에 실제 도달 거리만큼 이동을 이어 쓸 수 있고, 저장된 속도·사용량·잔여량이 일치하며 CombatScreen이 같은 값을 표시한다.
- 사건이 중간 칸에서 발생하면 실제 통과 경로의 위치·이동량만 반영한다. 경로의 필수 이동 검증이 끝나기 전 지도는 바뀌지 않는다. 그 뒤 사건의 GM 판정에서 플레이어 굴림이 요구되면 이미 확정한 이동 결과를 되돌리지 않고 `GM_INTERVENTION_PENDING`으로 이어간다.
- 전용 고정 GM 응답 계약은 판정 결과·공개 서술·기존 `RuntimeCheckProposal`에 따른 필요한 플레이어 굴림·전투 시작 여부를 표현한다. 일반 사용자 선택 필드는 추가하지 않는다. 적 토큰 ID에 사건을 묶지 않고, 서버가 부여한 작업·차례 식별자만 연결한다.
- 두 진입 경로는 각자 기존 내구 작업 저장 경계를 사용한다. 지도 UI는 `RuntimeTurn`과 `RuntimeTurnCommand`를, `/combat/actions`는 `CombatActionOperation`을 사용한다. 구현 엔티티는 달라도 실제 이동 결과를 한 번 확정하고, 같은 서버 발급 작업·차례 식별자에 GM 대기·플레이어 굴림·최종 판정·필수 후속 저장을 묶으며, 완료 전까지 대기를 유지하고 저장 결과를 재사용하는 동일한 복구 불변식을 지킨다. 최초 GM 요청 전에 해당 경로의 기존 작업을 `GM_INTERVENTION_PENDING`으로 저장한다. 대기 중에는 일반 전투 행동 및 턴 종료를 거부한다. 기존 플레이어 굴림이 요구되면 그 굴림만 같은 작업에 제출하도록 허용하고, 굴림 결과를 저장해 AI Game Master의 최종 구조화 판정으로 전달한다. 최종 판정과 필수 후속 변경을 검증·저장한 뒤에만 대기를 해제하고 같은 플레이어 차례를 재개한다.
- 굴림이 필요하지 않으면 최초 GM 응답을 최종 구조화 판정으로 취급한다. 해당 응답과 필수 후속 변경을 검증·저장한 뒤에만 대기를 해제한다. 필수 후속 변경 저장이 실패하면 같은 이동 작업의 대기 상태를 유지한다.
- 초기·최종 GM 응답 실패나 식별자·스키마 검증 거부는 `GM_INTERVENTION_PENDING`을 해제하지 않는다. 이미 확정한 이동 결과와 같은 차례를 유지하고 같은 작업의 재시도·복구만 허용하며, 이동·이동량·굴림·최종 판정·서술을 중복 적용하지 않는다.
- 잘못되거나 작업·차례가 불일치하는 GM 응답은 확정 상태를 바꾸지 않는다. 같은 기존 작업으로 미완료 단계만 재개하며 위치·이동량·비용·굴림·GM 결과를 중복 적용하지 않는다.
- 세 저장 경계와 두 진입 경로를 조합한 장애 복구 여섯 사례를 모두 실행한다. 각 사례는 영속 저장소를 유지한 채 새 처리 서비스 인스턴스에서 장애 전 상태를 다시 읽고 같은 서버 작업 식별자로 재시도한다. 위치·거리·남은 이동량·공개 결과·현재 플레이어 차례는 한 번만 확정하고 이동 예산은 한 번만 차감하며 캐릭터 자원은 바뀌지 않는지 검증한다.
- 사건 판정·서술이 끝나도 플레이어 차례를 유지한다. 새 경로 확인, 다른 허용 행동 또는 명시적 턴 종료만 다음 상태 변경을 확정한다. 남은 경로 자동 이동과 GM 서술 기반 토큰 이동·턴 종료는 없다.
- 금지 사례: 지도 확정 직후·이동 예산 저장 직후·작업 완료 기록 직전의 장애 복구에서 실제 거리의 이동량 차감을 누락하거나 두 번 차감하고, 위치·이동 예산·완료 결과가 서로 어긋나거나 GM 서술을 다시 적용한다. 경로 확인 전에 위치·안개를 바꾸거나 중단 지점 이후 이동량을 소비한다.

## 테스트 계약

- 장애 복구 수용 조건: 지도 확정 직후, 이동량 저장 직후, 최종 판정 저장 후 `COMMITTED` 완료 기록 직전의 세 경계에서 중단되어도 저장 상태를 다시 읽고 동일 서버 작업 식별자로 재시도하여 실제 도달 위치·실제 거리·이동량·완료 기록이 한 번 적용된 결과로 일치해야 한다. 지도 UI 이동과 `/combat/actions` 이동 제출 모두 같은 조건을 충족하며 이동량 차감 누락·이중 차감·GM 판정 재호출·서술 재적용을 허용하지 않는다.
- 장애 복구는 표의 세 저장 경계와 두 진입 경로를 조합한 여섯 사례를 모두 실행한다. 각 사례는 저장소를 유지한 채 새 처리 서비스 인스턴스를 구성해 장애 전 상태를 다시 읽고, 같은 서버 작업 식별자로 재시도한다. 각 사례에서 실제 위치·거리·남은 이동량·공개 결과·현재 플레이어 차례가 한 번만 확정되고, 이동 예산도 한 번만 차감되며 캐릭터 자원은 바뀌지 않는지 검증한다.

| 중단 경계 | 지도 UI 이동 | `/combat/actions` 이동 제출 |
|---|---|---|
| Combat Map이 실제 이동을 저장한 직후 | 이동 결과 저장 후 Runtime 작업 결과 기록 전에 장애를 주입하고, 새 처리 서비스 인스턴스가 같은 지도 작업 UUID를 조회해 이동을 재수행하지 않는지 검증한다. | 이동 결과 저장 직후 전투 이동량·operation 응답 저장 전에 장애를 주입하고, 새 `CombatActionApplicationService`가 저장된 지도 작업 UUID로 위치와 실제 거리를 복구해 이동량을 한 번만 반영하는지 검증한다. |
| 이동량과 완료 상태를 저장한 직후 | Runtime 작업 결과 저장 후 차례 확정 전에 장애를 주입하고, 새 처리 서비스 인스턴스가 저장된 typed 이동 결과를 재적용하지 않고 같은 차례를 유지하는지 검증한다. | encounter·operation 응답·`MOVEMENT_RESOLVED` 원자 저장 직후 장애를 주입하고, 새 서비스 인스턴스가 GM 판정만 재개하며 새 행동을 계속 차단하는지 검증한다. |
| 최종 판정 저장 후 완료 기록 저장 직전 | typed continuation 결과가 영속 저장된 뒤 `RuntimeTurn`의 `COMMITTED` 기록 직전에 저장 실패를 주입한다. 새 처리 서비스 인스턴스는 저장된 최종 판정을 재사용해 차례 완료 기록을 다시 시도하며, 판정·이동·이동량·서술을 중복 적용하지 않고 대기 상태를 완료 기록까지 유지하는지 확인한다. | typed continuation 결과가 영속 저장된 뒤 `CombatActionOperation`의 `COMMITTED` 기록 직전에 저장 실패를 주입한다. 새 서비스 인스턴스가 `GM_INTERVENTION_PENDING`과 저장된 굴림·최종 판정을 다시 읽고 최종 응답만 복구하며, 이동·이동량·GM 호출·서술을 중복 적용하지 않는지 확인한다. |

- `CombatActionMovementFollowUpTest`와 `CombatMapRuntimeTurnCommandAdapterTest`에서 표에 적은 여섯 저장 경계×진입 경로 조합을 장애 주입으로 실행한다. 각 사례는 영속 저장소를 공유하는 새 처리 서비스 인스턴스로 복구해 저장된 작업 UUID·지도 결과·굴림·GM 결과를 재사용하고 효과를 중복 적용하지 않는지 확인한다. `SessionEventTest`는 지도 UI 경로의 저장된 작업 조회와 typed 결과 식별 검증·재생을, `CombatActionOperationRecoveryTest`는 서버 작업 UUID·단계 기록 복원을, `CombatMapFlow.test.tsx`는 같은 명령 재제출과 중단 응답 복원을 확인한다. 다른 동작이 만든 같은 encounter version을 중단된 operation 결과로 추정하지 않는다.
- 필수 플레이어 굴림 흐름은 `GM_INTERVENTION_PENDING` 저장·복원, 같은 작업에 대한 굴림 연결, 굴림 전/후 다른 행동·턴 종료 거부, 최종 GM 판정 실패 또는 검증 불일치 뒤 대기 잠금 유지와 같은 작업 재시도, 최종 판정 저장 후 같은 차례 재개를 확인한다. 새 작업 식별자나 일반 선택 입력 계약을 만들지 않는다.
- 굴림이 없는 사건은 최초 GM 응답을 최종 판정으로 검증·저장하고 필수 후속 변경까지 저장한 뒤에만 대기를 해제한다. 응답 검증 또는 후속 변경 저장이 실패하면 대기를 유지하고 같은 작업만 재시도하며, 다른 행동·턴 종료는 거부되는지 확인한다.
- 지도 화면 복구 검증 (`CombatMapFlow.test.tsx`): 확인 응답 유실 뒤 같은 이동 명령 식별자로 다시 제출하는지, 필수 플레이어 굴림의 최종 GM 판정이 저장된 뒤 서버가 돌려준 중단 위치·공개 사건과 같은 차례를 표시하는지, 재접속 뒤 저장된 중단 결과를 다시 표시하고 임시 저장 상태를 지우는지 확인한다.
- 개발용 진단 검증 (Architecture Spec §9.1·INV-01): 이 계획이 바꾸는 각 시작·완료·대체 경로·재시도·실패 분기에서 기존 `DevelopmentDiagnostics`와 `dev_` 로그 형식을 확인한다. `ADVENTURE_RUNTIME_DIAGNOSTICS_ENABLED`가 꺼졌을 때 상세 로그가 없고, 켜졌을 때 command/operation/turn ID, 입력·경로·이벤트 개수, 기대/실제 상태, 선택한 복구 분기, 소요 시간, 실패 종류와 다음 복구 동작이 드러나야 한다. GM 응답 스키마나 목록 검증 실패에는 기대 구조와 실제 구조를 함께 기록하고, 해당 분기의 테스트에서 두 구조 요약·식별자·다음 복구 동작을 확인한다. 프롬프트·응답 원문, 인증 정보, 불필요한 플레이어 입력, 비공개 지도 정보를 기록하지 않고 실제 동작을 바꾸지 않아야 한다. 테스트는 시작·완료·대체/재시도·실패 로그의 식별자·기대/실제 값·다음 복구 동작을 확인하고 원문·비밀값이 없는지 확인한다.
- 단위/정책: 이동 10피트 뒤 행동, 이동 5피트 뒤 추가 행동, 이동 15피트 순으로 이어 써서 행동 전·사이·후 이동을 확인하고 사용량 30피트·잔여량 0피트·속도 30피트가 저장되는지 확인한다. CombatScreen이 속도·사용·잔여 값을 snapshot과 맞게 표시하는지 확인한다. 확인 전 읽기 전용, 칸별 안개·실제 이동량과 중단 위치, 저장된 이동 결과의 재시도·복구. 요구사항 식별자: AC-05, AC-07, AC-08, AC-16, BR-05, BR-08, BR-16, BR-18, BR-19, EX-08, G-03, ST-UC-002-01, ST-UC-002-02, ST-UC-002-03, UC-002. 소유 경계와 실행 진입점: 전투 차례·이동량 정본(CombatEncounter), 전투 행동 처리 서비스(CombatActionApplicationService), 지도 이동 조정기(MapMovementCoordinator), 전투 지도 서비스(Combat Map); 전투 지도 서비스가 실제 중단 칸·이동량을 모험 진행 서비스로 전달하고, 전용 GM 응답과 현재 작업·차례를 검증한 뒤 미완료 작업을 이어서 처리. 추적 수용 조건: 전투 지도는 상호작용 화면의 중앙에 배치하고, 선택한 캐릭터 토큰을 클릭·드래그해 경로를 정한다. 반례: 경로 확인 전에 위치·안개를 바꾸거나 중단 지점 이후 이동량을 소비한다. 추가 계약 검증: 사건에 적 토큰 ID가 없는 경우, 스키마 불일치·작업/차례 불일치 GM 응답, 응답 유실 후 동일 작업 재개에서 지도 위치·이동량·자원·서술의 중복 적용 없음, 지도 UI와 전투 행동 제출 두 진입점의 같은 정책 적용.
- `ui ~ entity` E2E: 해당 없음 — 경로 실행·중단 지점·이동량·전용 응답은 정책·계약·통합 검사로 검증한다. 실제 에이전트 포함 브라우저 E2E는 원본 자료·지도 준비·자연어 승인까지 포함해 모든 선행 구현 뒤 #375에서 한 번 실행한다.
