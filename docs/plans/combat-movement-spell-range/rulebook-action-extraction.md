# 기본 룰북 주문·행동 정의 추출 계획

## 목표

관리자가 공개할 룰북의 주문·행동을 각 항목이 적힌 근거부터 추출하고, 정의에 실제로 필요한 정보만 제한된 문서 범위 검색으로 보완한다. 문서 ID와 게시 추출 버전을 함께 저장해 다른 룰북이나 다른 게시 버전의 규칙이 섞이지 않게 한다. 공통 규칙은 적용 조건과 출처를 보존한 채 문서·버전 단위로 한 번 저장하고, 적용이 확인된 정의에서만 참조한다. 기존 검토·수정·승인과 런타임 조회 경계는 유지한다.

## 근거와 문제

2026-10-11 재현에서 단검 행동 하나에 대한 요청은 근거 27개, 27,709자, 인용 위치 426개로 커져 약 146KB가 됐고 43.5초 뒤 `OUTPUT_LIMIT`로 실패했다. 구성은 공통 조회 결과 합집합 20개, 후보별 추가 결과 6개, 최초 무기 표 근거 1개였다. 최초 항목 자체의 근거만 보낸 요청은 약 819바이트, 출력 530 토큰으로 성공했다. 현재 흐름은 공통 규칙 근거를 모든 후보에 무조건 붙이고 후보별 검색도 다시 수행해 이 입력을 만든다. 별도 재현에서는 구매 가격 2gp를 행동 실행 비용으로 기록했다. 구매 가격과 실행 때 소모되는 행동·자원은 계약에서 분명히 구분해야 한다.

2026-10-12 실제 검색 실행에서 행동 3개를 처리할 때 한 행동의 완전한 요청 추정치가 79,691토큰으로 측정됐다. 기존 사용 가능 한도 40,000토큰으로는 첫 행동도 처리할 수 없어, 기본 정책을 총 128,000토큰과 외부 입력 여유분 24,000토큰(사용 가능 104,000토큰)으로 조정한다. 이는 관리자가 바꿀 수 있는 요청 입력 정책이며, 특정 제공자나 모델의 문맥 한도 보장은 아니다. 운영 설정은 선택한 제공자의 실제 한도에 맞춰야 한다.

## 구현 범위

1. 각 발견 항목의 최초 정의 요청에는 해당 이름이 적힌 자체 근거만 넣는다. 후보별 출처 검색이나 문서 전반의 공통 규칙 묶음을 일괄 첨부하지 않는다.
2. 출력 계약에 항목별로 필요한 정보 목록과 근거 상태를 포함한다. 필드 값이 `null`이라는 이유만으로 검색하지 않고, 모델이 해당 항목에 필요하다고 명시했으며 자체 근거에서 확인되지 않은 필드만 좁은 밀집 검색으로 보완한다. 이미 확인된 사실은 유지하고, 이미 사용한 근거 ID는 제외한다. 모호하거나 확인되지 않은 정보는 미상으로 유지한다.
3. 공유 규칙은 관련 정보가 실제로 필요해 검색할 때에만 추출한다. 문서 ID·게시 추출 버전·계약 버전을 함께 키로 구조화해 저장한다. 각 규칙에 적용 조건과 출처 근거를 보존하고, 추출 정의는 적용이 분명한 공유 규칙만 참조한다. 게시 버전 또는 계약 버전이 다르면 재사용하지 않는다. 기존 정의 조회 경계에서 참조를 해석해 소비자가 확인된 필드와 출처를 계속 읽도록 한다.
4. 출력 스키마의 인용 ID 열거를 전체 근거 ID 목록 반복 대신 제한된 근거 참조로 바꾸되, 서버는 모든 인용 ID가 해당 요청의 허용된 근거인지 검증한다. 항목별 식별자 일치 및 일대일 결과 검증은 유지한다.
5. 구매 가격과 행동 실행 비용의 의미를 프롬프트·필드 계약에 분리하고, 근거에 없는 실행 비용은 미상으로 둔다.
6. 현재 문서·버전 영속 저장과 묶음 재개 방식을 재사용한다. 모든 새 검색·적용 판정·재시도·검증 실패에 진단 로그를 추가하고, 로그는 기능 플래그가 켜진 경우에만 구조 정보로 출력한다.

7. 상세 조회가 필요한 항목을 먼저 모아 문서·게시 버전·자료 종류를 고정한 `searchBatch`로 최대 16개씩 조회한다. 검색 한도 안에서 반환된 유효 근거는 본문을 자르거나 개수를 줄이지 않고 항목별로 모은 뒤, 실제 요청문과 출력 스키마를 포함한 토큰 추정치로 항목 단위 묶음을 만든다. 기본 입력 정책은 총 128,000토큰에서 외부 입력 여유분 24,000토큰을 뺀 104,000토큰이며 관리자가 조정한다. 이 값은 제공자나 모델의 문맥 한도를 보장하지 않는다. 한 항목만으로 설정 한도를 넘으면 일부 근거를 버리지 않고 해당 항목 ID·추정 토큰·한도를 기록해 실패 처리한다. `INSUFFICIENT_EVIDENCE`이고 정의와 필요한 필드 목록이 모두 비어 있으면 행동 이름만으로 한 번 더 찾는다.
8. 추출 계약을 v8로 올려 이전 계약의 묶음 결과를 재사용하지 않고 새 검색·요청 흐름으로 다시 계산한다. 토큰 한도에 걸린 경우 기존 완료 정의가 있으면 이전 계약 버전과 함께 실패 상태로 보존해 성공 결과로 오인하거나 덮어쓰지 않는다.

## 검증

합성 대체 룰북으로 자체 근거 최초 요청이 공통 구절을 포함하지 않는지, 필요한 미확인 필드만 재검색하는지, 이미 알려진 값과 제외 근거 ID가 유지되는지 확인한다. 공통 규칙의 문서·버전 격리, 적용 불명확 시 미상 처리, 서버 측 인용 ID 검증, 줄어든 스키마의 크기, 구매 가격과 실행 비용 구분을 검증한다. 기존 추출·저장 테스트와 두 서비스의 관련 Gradle 테스트를 실행한다.

## 제외 범위

특정 게임이나 룰북에 고정된 이름·항목 수·파일명을 추가하지 않는다. 원문 전체 순회, 모든 공통 규칙을 모든 항목에 복제, 새로운 추출 서비스나 의존성은 추가하지 않는다. 검색기가 반환한 유효 근거의 본문 보존은 보장하지만, 검색 한도 밖의 자료까지 포함한 룰북 전체 완전성은 보증하지 않는다.
