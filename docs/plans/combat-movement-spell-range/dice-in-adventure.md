# 주사위 굴림을 모험 서비스 내부로 통합

사용자가 별도 주사위 서비스가 불필요하다고 결정하고 계획 작성과 GPT-6 Luna·medium 구현을 요청했다. 이 문서는 해당 변경의 구현 범위이며 전투 발사 기능 전체를 완료한 것으로 취급하지 않는다.

## 목표와 소유 경계

- 굴림 생성·검증·결과 저장은 모험 서비스의 내부 기능으로 둔다. 독립 서비스·배포 모듈과 모험 서비스 자신의 굴림 HTTP 호출을 없앤다.
- 모험의 행동 처리 기록이 굴림 단계 ID와 결과를 참조한다. 같은 단계 ID와 같은 입력은 저장된 결과를 반환하고 다른 입력은 충돌로 거부한다.
- 캐릭터 상태와 지도 상태의 소유권은 기존 서비스에 유지한다.

## 구현 순서

1. 기존 주사위 모듈의 실행·결과 검증·영속 저장·권한 검사·테스트를 모험 서비스 내부로 옮긴다. 이미 존재하는 기능을 재사용하며 두 번째 굴림 엔진을 만들지 않는다.
2. 전투 행동·피해·죽음 내성·우선권·이동 중 판정·적 인지·GM 도구의 모든 운영 호출을 조사하고 내부 호출로 연결한다. 피해 굴림처럼 명령 ID가 없는 경로는 행동 ID에서 안정적인 단계 ID를 정하도록 보완한다. 순수 테스트용 대역과 운영 실행 경로를 구분한다.
3. 모험 서비스 내부에서 사용하는 주사위 HTTP 어댑터와 별도 주소 설정을 제거한다. 기존 외부 API 호출자가 필요로 하는 접근 경로는 모험 서비스 내부 기능을 호출하며 소유권·권한 검사를 유지한다.
4. Gradle 프로젝트와 통합 애플리케이션 의존성에서 독립 주사위 모듈을 제거하고, 애플리케이션 조립·실행 설정·계약 테스트를 함께 수정한다. 기존 굴림 테이블과 적용된 마이그레이션은 삭제하지 않는다. 마이그레이션의 기존 경로·이력은 데이터 보존에 필요한 저장 이력일 뿐 서비스 경계로 취급하지 않는다.
5. 현재 설계 명세·상태 소유 표·다이어그램·실행 문서의 독립 주사위 서비스 설명을 이번 경계에 맞춘다. 과거 문서 전체를 고쳐 쓰지 않는다.

## 실행·복구 계약

- 난수 결과는 저장 완료 후 반환한다. 재시도와 프로세스 재시작 후에도 같은 명령은 같은 결과를 사용한다.
- 동시에 같은 명령이 들어와도 하나의 결과만 확정한다. 저장 충돌 시 새 굴림을 실행하지 않고 확정된 결과와 입력을 확인한다.
- 굴림 결과 저장 자체는 게임 자원 소비가 아니다. 기본 효과·비용 확정 전 실패에는 기존 예약 해제 규칙을 적용한다.
- 굴림 식·개수·눈 수·보정치와 역할별 실행 권한 검사를 유지한다. AI가 플레이어 권한을 우회하거나 임의 결과를 확정할 수 없다.
- 진단은 기존 `DevelopmentDiagnostics`와 `dev_` 형식을 사용한다. 시작·완료·저장 결과 재사용·입력 충돌·실패·복구 단계, 식별자·개수·소요 시간을 기록한다. 원문·인증 정보는 기록하지 않는다.

## 검증과 완료 조건

- 동일 입력 재시도, 다른 입력 충돌, 권한 거부, 잘못된 굴림 식, 저장 실패 후 재시도, 동시 요청 및 저장소 재생을 검증한다.
- 모든 기존 주사위 테스트를 이전 위치에서 실행하고, 모험 서비스 전체 테스트와 통합 애플리케이션 조립·관련 계약 테스트를 통과시킨다.
- 운영 굴림 경로에 주사위 HTTP 주소 호출이나 저장되지 않는 난수 대체 경로가 남지 않았는지 확인한다.
- 새 개발용 로그의 주요 식별자·분기·기대/실제 값·결과를 테스트에서 확인한다.
- 현재 작업 트리의 다른 변경을 되돌리거나 함께 커밋하지 않는다. 필요한 수정이 이미 변경된 파일과 겹치면 이번 작업의 변경만 분리해 보존한다.
- 코드 변경 후 `graphify update .`를 실행한다. 실제 전체 모험 E2E는 이 통합만으로 발사 기능 전체를 증명하지 않으므로 완료 근거로 주장하지 않는다.
