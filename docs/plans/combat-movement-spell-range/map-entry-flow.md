# 시츄에이션 진입 시 지도와 시작 위치 결정 계획

## 목표

지도는 오프닝 턴의 기본 요구사항이 아니다. `mapNeeded`가 참인 시츄에이션에 처음 진입할 때, 그 진입을 설명하는 장면 서술과 해당 시츄에이션의 지도 자료를 함께 사용해 그룹의 시작 위치를 결정한다. 오프닝과 이후 시츄에이션은 같은 규칙을 따른다.

## 확정할 동작

1. 모험을 시작하면 opening 시츄에이션을 선택하고 해당 시츄에이션의 진입 서술을 생성한다.
2. `mapNeeded=false`이면 지도 준비·시작 위치 추론·지도 활성화를 요구하지 않고 서술을 플레이어에게 전달한다.
3. `mapNeeded=true`이면 해당 시츄에이션에 연결된 지도와 적·함정·문·잠금 초기 배치를 준비한다. 전투 시작 여부와 무관하게 필요한 적의 종류·수량·위치·발견 상태를 지도 정본에 저장하고, 필수 배치 누락은 활성화를 차단한다. 에이전트가 지도·원문/RAG 근거를 읽어 고정 응답 계약으로 배치를 제안하고, 준비 경계가 수량·근거·좌표·상태를 검증하며 영속 식별자는 서버가 부여한다. 진입 서술, 지도 이미지와 기하 자료, 시츄에이션 내용 및 관련 근거를 시작 위치 제안에 함께 제공한다.
4. 제안 위치가 지도에서 유효하고 이동 가능한지 검증한다. 초기 배치 준비와 위치 검증이 모두 성공하면 그룹 토큰과 초기 시야를 설정하고 진입 서술을 플레이어에게 전달한다.
5. 위치가 모호하거나 유효하지 않으면 진입을 완료된 것으로 저장하거나 서술을 중복 공개하지 않는다. 재시도 또는 지도 UI에서의 사용자 위치 선택을 통해 같은 진입 요청을 이어간다.
6. 이후 다른 시츄에이션으로 이동할 때도 대상 시츄에이션의 `mapNeeded`와 지도 식별자를 기준으로 이 절차를 반복한다. 장면 이름 변경이나 GM의 지도 진입 표시만으로 지도를 활성화하지 않는다.
7. 적·함정 등 비공개 배치는 플레이어 지도 응답에 노출하지 않는다.

## 구현 순서

1. Product Spec, Architecture Spec, 결정 기록에서 “시작 전 지도 준비”가 모험 전체 시작을 뜻하는지 시츄에이션 진입을 뜻하는지 일치시킨다. ADR-023은 오프닝 컨텍스트가 빈 대화로 시작한다는 결정만 담고 있으며 지도 필요 여부는 새 계약에서 명시한다.
2. 모험 시작 코드에서 오프닝 맵을 무조건 선택·초안 준비·활성화하는 경로를 제거한다. 맵 필요 여부는 계속 시츄에이션 속성의 정본 값을 사용한다.
3. opening과 이후 상황 전환이 공유하는 시츄에이션 진입 경로를 마련한다. 대상 시츄에이션, 지도, 진입 서술, 근거를 하나의 요청 맥락으로 연결한다.
4. 지도 시작 위치 제안기에 진입 서술과 실제 지도 자료가 함께 전달되는지 확인하고, 정적 지도 좌표를 진입 서술 기반 제안보다 우선 적용하는 경로를 제거한다. 지도 서비스는 제안 위치를 유효한 칸인지 검증하고 그룹 토큰·시야 상태를 확정한다.
5. 위치 미확정·지도 준비 실패 때 진입 상태와 재시도 식별을 보존하고, 사용자 지도 선택 후 같은 진입을 이어갈 수 있도록 기존 지도 선택 UI/API를 연결한다.
6. 개발 진단 로그에 처리 단계, 시츄에이션·지도 식별자, 입력 크기, 제안/검증 결과, 재시도 여부와 다음 복구 경로를 남긴다. 서술 원문은 기록하지 않는다.
7. 단위·통합 테스트를 새 계약에 맞게 갱신하고, `ui ~ entity` E2E로 맵 없는 오프닝과 맵이 필요한 후속 시츄에이션 진입을 확인한다.

## 수용 기준

- 맵이 필요 없는 opening은 지도가 없어도 시작하고 첫 플레이어 입력을 받을 수 있다.
- 맵이 필요한 opening은 예외가 아니라 일반 시츄에이션 진입 절차로 지도를 준비하고, 진입 서술과 그 지도를 사용해 시작 위치를 정한다.
- 맵 필요 후속 시츄에이션 진입 때 해당 시츄에이션의 지도 정의를 선택·준비하고 진입 서술을 위치 제안에 전달한다.
- 제안된 시작 위치는 지도 서비스에서 검증되며, 성공 전에 진입 서술/턴이 중복 커밋 또는 중복 공개되지 않는다.
- 위치 미확정 결과는 사용자 지도 선택 또는 재시도로 복구할 수 있다.
- 맵 불필요 시츄에이션 전환은 이전의 준비된 지도를 잘못 활성화하지 않는다.
- 전투를 시작하지 않은 상황에서도 필요한 적 토큰·함정·문·잠금 초기 상태가 지도 활성화 전에 저장된다.
- 필수 배치가 준비되지 않으면 활성화·진입 공개를 보류하고 기존 요청 맥락을 유지한다.
- 재방문과 같은 준비 요청의 재처리는 저장된 배치·발견 상태를 보존하며 토큰을 중복 생성하지 않는다. 같은 지도 ID 전환·재방문은 시작 위치 제안기를 다시 호출하지 않고 저장 위치·격자·벽·문·안개를 보존한다.
- 시작 위치 후보 없음·제공자 실패 시 최초 포함 최대 6회 시도하고 후보가 나오면 즉시 중단한다. 소진한 경우에만 수동 위치 선택으로 이어간다. 검증은 호출 횟수·조기 종료·재방문 호출 0회를 검사한다.
- 비공개 배치 정보가 플레이어에게 반환되지 않고, 발견·시야 조건에 따라 확인된 적 토큰이 공개된다.

## 검증 범위

- `AdventureSessionStageStartTest`: opening의 `mapNeeded` 참/거짓에 따른 시작 경로.
- `PreparedMapEntryCommitGateTest` 또는 대체 진입 흐름 테스트: 대상 시츄에이션 속성 기준의 맵 활성화와 위치 추론 입력.
- `HttpCombatMapPreparationGatewayTest` 및 Combat Map 위치 제안 테스트: 진입 서술·지도 자산 전달, 이동 불가 위치 거부, 실패/재시도.
- `ui ~ entity` E2E: 맵 없는 opening → 플레이어 행동 → 맵 필요 시츄에이션 진입 → 지도와 진입 서술로 그룹 위치 확정.

## 범위 주의

- 이번 작업은 오프닝 서술의 문체·길이 자체를 전반적으로 다시 설계하지 않는다. 다만 맵 위치 추론에 쓰는 진입 서술은 해당 시츄에이션으로의 실제 진입을 설명해야 한다.
- 현재 작업 트리에는 이 계획과 무관한 변경이 이미 있으므로, 구현은 위 흐름과 직접 관련된 파일만 수정하고 다른 변경을 되돌리지 않는다.
