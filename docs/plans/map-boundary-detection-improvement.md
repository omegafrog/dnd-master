# 맵 벽·문 감지 고도화 계획

- 작성: 2026-09-09
- 상태: 외부 기술 조사와 현재 코드 검토를 바탕으로 한 구현 계획
- 범위: 사용자가 저장한 격자 정렬·자르기 값을 기준으로 지도 이미지에서 벽·문 후보를 만들고 검수 가능한 초안으로 반환하는 흐름
- 제외: 사용자의 승인 없이 후보를 플레이 맵의 최종 상태로 바꾸기, 비밀 정보 공개 범위를 넓히기, 격자 정렬값 다시 계산하기

## 1. 현재 동작과 문제

현재 [이미지 초안 보정 코드](../../src/ai-game-master-service/src/main/java/com/dndmaster/aigamemaster/api/AiGameMasterApiConfiguration.java)의 대체 경로는 저장된 `gridOriginX`, `gridOriginY`, `gridCellSize`를 읽어 격자 선 주변의 어두운 픽셀을 표본으로 삼는다. 이 방식은 외부 AI 응답이 늦어도 초안을 만들 수 있다는 장점이 있지만 다음 한계가 있다.

| 문제 | 현재 결과 | 고도화 방향 |
| --- | --- | --- |
| 색·밝기 차이 | 어두운 장식과 실제 벽을 같은 선으로 볼 수 있음 | 밝기만 보지 않고 경계 강도·연속성·양쪽 영역 차이를 함께 계산 |
| 끊긴 선 | 한 칸만 비어 있으면 문으로 추정하지만 장식의 빈틈도 문이 됨 | 선분 연결·문틀·틈 길이·양쪽 방 연결을 함께 검증 |
| 고정 임계값 | 지도 해상도와 스캔 품질이 바뀌면 누락·과검출이 커짐 | `cellSize`에 비례한 표본 폭과 이미지별 자동 임계값 |
| 결과 설명 부족 | 사용자가 왜 후보가 생겼는지 알 수 없음 | 후보별 근거와 불확실한 정도를 검수 화면에 표시 |
| 격자 밖 결과 | 이미지 여백·잘라내기 변경 뒤 이전 후보가 남을 수 있음 | 저장된 정렬 버전과 자르기 지문에 후보를 묶고 다시 계산 |

분석 입력은 항상 사용자가 적용한 정렬 버전과 그 정렬에 대응하는 자르기 범위를 함께 사용한다. 분석기가 격자를 다시 찾거나 초기 `GRID_BOUNDS`로 되돌아가는 경로는 허용하지 않는다.

## 2. 조사한 기술과 채택 이유

이번 조사는 구현 근거가 공개된 공식 문서와 연구를 우선했다.

1. [OpenCV 허프 선 변환 공식 문서](https://docs.opencv.org/4.x/d9/db0/tutorial_hough_lines.html)는 경계 영상에서 직선 후보를 찾고 최소 선분 길이와 선분 사이의 허용 간격을 조절하는 방법을 설명한다. 지도 벽처럼 수평·수직으로 이어지는 선분을 합치는 2차 후보 생성에 사용한다.
2. [OpenCV 캐니 경계 검출 설명](https://opencv.org/edge-detection-using-opencv/)은 흐림 처리 뒤 두 임계값을 이용해 강한 경계와 연결된 약한 경계를 보존하는 절차를 설명한다. 단순히 검은 픽셀 수만 세는 현재 방식의 보완으로 사용한다.
3. [OpenCV 형태학·영상 처리 목록](https://docs.opencv.org/4.10.0/d7/da8/tutorial_table_of_content_imgproc.html)과 [연결 요소 분석 문서](https://docs.opencv.org/doc/doxygen/html/d3/dc0/group__imgproc__shape.html)는 작은 점 노이즈 제거, 끊긴 선 연결, 연결된 덩어리 분석을 제공한다. 선분 병합 전에 사용한다.
4. [Segment Anything 연구 논문](https://arxiv.org/abs/2304.02643)은 점·상자 등 사용자가 준 단서로 낯선 이미지의 영역을 분할하는 모델을 제시한다. 벽 전체를 자동 확정하는 용도가 아니라, 규칙 기반 분석이 애매한 문·문틀 후보를 재검토하는 선택적 보조 수단으로만 둔다.

OpenCV를 바로 서비스의 필수 실행 파일로 추가하지는 않는다. 현재 서비스가 자바와 `ImageIO`만으로 배포되므로 1단계는 같은 좌표 투영·연속성 계산을 순수 자바로 구현해 재현성을 확보한다. 2단계에서 공식 문서의 경계·선분 알고리즘이 실제 대표 지도에서 이득을 보일 때만 자바 바인딩 또는 별도 분석 작업자의 도입을 결정한다.

## 3. 목표 계약

### 입력

- `imageRevision`: 분석할 이미지 내용의 해시
- `gridConfirmed: true`
- `gridWidth`, `gridHeight`
- `gridOriginX`, `gridOriginY`, `gridCellSize`: 원본 이미지 픽셀 좌표
- `crop`: 사용자가 저장한 자르기 범위
- 기존 사용자가 그린 벽·문: 자동 후보가 덮어쓰지 않도록 별도 목록으로 전달

### 후보 출력

기존 선분 인코딩은 계속 읽을 수 있게 유지하고, 새 응답에는 다음 설명을 추가한다.

```json
{
  "x": 7,
  "y": 4,
  "orientation": "HORIZONTAL",
  "kind": "WALL",
  "confidence": 0.91,
  "evidence": ["continuous-edge", "cell-spanning", "room-contrast"],
  "source": "IMAGE_RULES"
}
```

`confidence`는 정답 확률이라고 표시하지 않고 여러 영상 특징이 얼마나 일치하는지를 나타내는 검수용 점수로 설명한다. `source`는 규칙 기반 분석 또는 선택적 AI 재검토를 구분한다. 사용자는 후보를 승인·거절·수정할 수 있고, 서버는 승인 전 후보를 이동 충돌이나 시야 차단에 사용하지 않는다.

## 4. 단계별 분석 흐름

### 1단계 — 정렬·자르기 고정과 기준 자료

1. 감지 시작 시 맵의 정렬 버전·이미지 해시·자르기 값을 한 번 읽어 분석 요청에 고정한다.
2. 응답 저장 전에 같은 정렬 버전인지 확인한다. 버전이 바뀌었으면 늦게 도착한 후보를 버리고 다시 감지하도록 한다.
3. 대표 지도 20장 이상(선명한 지도, 흐린 스캔, 장식이 많은 지도, 여백이 있는 지도, 문이 많은 지도)에 사람이 승인한 벽·문 선분을 기준 자료로 저장한다. 원본 이미지나 비밀 지형을 로그에 남기지 않는다.

### 2단계 — 규칙 기반 선분 후보

1. 자르기 범위 안에서만 원본 픽셀을 읽고 회색조·가벼운 흐림 처리를 적용한다.
2. 수평·수직 격자 선마다 `cellSize`에 비례한 띠를 표본으로 만든다. 평균 밝기 하나 대신 중앙값, 어두운 픽셀 비율, 경계 강도, 선분 안의 빈틈 길이를 계산한다.
3. 작은 점은 열기, 짧은 끊김은 닫기 연산에 해당하는 순수 자바 연결성 규칙으로 정리한다. 실제 OpenCV 도입 시에는 공식 형태학 연산으로 같은 단계의 결과를 비교한다.
4. 인접한 후보를 한 선분으로 병합한다. 허프 선 변환은 긴 수평·수직 선을 찾는 보조 실험으로 두고, 선분 끝점은 반드시 `origin + cell × cellSize` 좌표로 되돌려 격자 선분에 맞춘다.
5. 각 후보에 다음 점수를 합산한다.
   - 칸 한 변의 대부분을 덮는지
   - 주변 선분과 이어지는지
   - 선 양쪽의 색·질감 차이가 방 경계와 맞는지
   - 이미지 장식으로 보이는 작은 연결 요소인지
   - 기존 사용자가 그린 선과 충돌하는지
6. 점수가 낮은 후보는 자동 벽으로 만들지 않고 ‘확인 필요’ 목록으로 보낸다.

### 3단계 — 문 후보 분리

문은 벽 한 칸의 빈틈만으로 확정하지 않는다.

- 양쪽에 이어지는 벽 선분이 있는지
- 빈틈이 한 칸 전체가 아니라 문 폭에 가까운지
- 문틀로 보이는 짧은 평행 선이 있는지
- 인접한 두 방 또는 복도 영역을 연결하는지
- 기존 벽과 중복되는 후보가 없는지

위 특징 가운데 최소 두 가지가 맞을 때만 문 후보로 제시한다. 나머지는 벽 후보를 유지하고 검수 화면에서 사용자가 문으로 바꿀 수 있게 한다. 열린 문·닫힌 문 상태는 후보 종류와 별도 값으로 둔다.

### 4단계 — 애매한 후보만 AI 재검토

규칙 기반 점수가 중간인 선분만 작은 자르기 영역과 격자 좌표를 포함해 선택적 AI 요청으로 보낸다. 요청에는 “수평·수직 선분, 문틀, 장식, 바닥 무늬”의 구분과 JSON 형식을 명시한다. AI가 내놓은 좌표는 서버가 격자 범위·중복·사용자 수정과 다시 대조한다. AI가 응답하지 않아도 2단계 결과와 수동 검수로 완료할 수 있어야 한다.

### 5단계 — 검수·저장

- 전체 지도에서 후보를 벽·문 색으로 겹쳐 표시한다.
- 불확실한 후보에는 근거와 점수를 보여주고 한 번에 승인·거절할 수 있게 한다.
- ‘애매한 후보만 다시 감지’를 제공한다. 전체 재감지는 사용자의 수정본을 덮어쓰지 않고 별도 후보 버전을 만든다.
- 저장할 때 정렬 버전·이미지 해시·자르기 지문·후보 버전을 함께 기록한다.
- 초안 저장 후 모험 시작은 저장된 정렬 버전과 후보 버전이 일치할 때만 허용한다.

## 5. 구현 순서와 검증 기준

| 단계 | 구현 | 검증 증거 |
| --- | --- | --- |
| A | 입력 고정, 버전 지문, 기준 자료와 결과 계측 | 재정렬·재자르기 뒤 이전 후보가 저장되지 않음 |
| B | 밝기·경계·연속성 점수와 선분 병합 | 대표 자료에서 기존 고정 임계값보다 누락·과검출 감소 |
| C | 문 후보 특징과 ‘확인 필요’ 목록 | 문이 아닌 장식 틈이 자동 문으로 확정되지 않음 |
| D | 선택적 AI 재검토와 구조화 응답 검증 | AI 시간 초과·잘못된 JSON에도 수동 완료 가능 |
| E | 후보별 검수 화면, 부분 재감지, 최종 승인 버전 | 사용자 수정 보존, 재접속 복원, 정렬 버전 불일치 거절 |

측정값은 벽과 문을 따로 집계한다. 사람이 승인한 선분을 기준으로 자동 후보의 정확률(후보 중 맞는 비율), 재현율(실제 선분 중 찾은 비율), 두 값을 함께 본 종합점수를 기록한다. 초기 목표는 대표 자료를 만든 뒤 확정하며, 목표를 충족하지 못하면 자동 확정 범위를 줄이고 확인 필요 목록을 늘린다.

## 6. 운영·안전 규칙

- 분석 요청과 저장 응답에 원본 이미지나 비공개 좌표를 로그로 남기지 않는다.
- 이미지 버전이 바뀌면 기존 후보를 새 이미지에 재사용하지 않는다.
- 외부 AI 지연은 실패가 아니라 선택적 보조 경로의 중단으로 처리한다.
- 서버가 최종 후보·승인본을 소유한다. 브라우저가 보낸 점수나 ‘확신’을 승인 근거로 신뢰하지 않는다.
- 기존 선분 형식과 기존 맵은 그대로 읽되, 새 형식은 새 버전에서만 저장한다. 진행 중 모험의 벽·문과 탐험 기록을 자동 재분석하지 않는다.
