# 맵 격자 맞추기 구현 계획

- 상태: 초기 제안 기록. 이후 사용자 인터뷰를 거친 [제품 명세](../specs/map-grid-alignment/product-spec.md)와 [아키텍처 명세](../specs/map-grid-alignment/architecture-spec.md)가 우선한다. 이 문서의 추가 제안을 자동으로 구현 범위에 포함하지 않는다.
- 참고: [Owlbear Rodeo — Effortless Map Alignment](https://blog.owlbear.rodeo/effortless-map-alignment/), 2026-05-07. 공식 글의 설명을 확인했으며 제품을 직접 실행하지 않았다.
- 목적: 숫자 시행착오 없이 이미지에 인쇄된 격자와 플레이 격자를 맞춘다.
- 이번 범위: 격자 맞춤 조작·저장·재편집. 벽·문 편집, AI 안개 관리, 전체 지형 검수는 별도 계획으로 보류한다.

## 1. 참고 기능과 적용 범위

공식 글은 기준점 정렬, 한 칸 크기 설정, 전체 격자에서 미세 조정하는 3단계를 설명한다. 기준점을 누르면 확대경이 나타나며 터치에서는 손가락 위로 이동한다. 마지막 단계에서는 각 격자 교차점에 조절점을 표시해 먼 곳에서 보이는 누적 오차를 수정한다. 원문은 내부 계산식이나 이미지 변형 알고리즘을 공개하지 않으므로 아래 수학·저장 방식은 우리 구현 제안이다.

초기에는 기존 정사각 격자를 지원한다. 육각 격자, 이미지 회전·원근 보정, 위치마다 다른 이미지 왜곡 보정은 제외한다. 인쇄 격자가 없는 맵은 사용자가 기준점과 원하는 한 칸 크기를 지정할 수 있다. 자동 탐지 결과가 있으면 시작값으로 재사용하며 새 AI 탐지 기능은 추가하지 않는다.

## 2. 화면과 사용자 흐름

맵의 ‘격자 맞추기’ → ‘기준점 맞추기’ → ‘한 칸 크기’ → ‘미세 조정’ → ‘적용’.

편집 화면에는 현재 단계, 짧은 안내, 이전·다음, 적용·취소를 표시한다. 단계 이동은 되돌릴 수 있으며 전체 화면을 다시 시작하지 않는다. 확대·축소와 화면 이동은 모든 단계에서 가능하다. 숫자 입력은 ‘상세 설정’으로 보조 제공한다.

### 기준점 맞추기

- 안내: ‘지도에 그려진 격자의 교차점에 표시를 맞추세요.’
- 현재 격자 교차점의 조절점을 드래그해 이미지의 교차점에 맞춘다.
- 누르고 있는 동안 원본 이미지 확대경과 십자선을 표시한다. 격자 표시가 원본 선을 가리지 않게 한다.
- 터치는 확대경을 손가락 위에 배치하고 화면 가장자리에서는 안쪽으로 옮긴다.
- 화면 밖에서 놓거나 터치가 취소돼도 드래그가 붙잡힌 상태로 남지 않는다.

### 한 칸 크기

- 안내: ‘표시된 한 칸을 지도 한 칸에 맞추세요.’
- 기준점은 고정하고 반대쪽 조절점으로 정사각형 크기를 조정한다.
- 가로·세로 크기를 함께 바꿔 정사각형을 유지한다. 어떤 방향으로 끌어도 같은 좌표 변환을 사용한다.
- 선택적으로 여러 칸을 표본으로 지정해 한 칸이 작은 이미지에서도 정확히 맞출 수 있게 한다.

### 미세 조정

- 대비가 높은 격자를 겹쳐 표시한다. 선 색·투명도 조절 가능.
- 격자 교차점에 마우스를 올리거나 터치로 선택하면 조절점을 표시한다.
- 처음 기준점에서 멀리 떨어진 교차점을 원본 선에 맞추면 누적 오차를 줄인다.
- 최초 기준점을 유지하며 전체 칸 크기를 조정한다. 한 교차점만 찌그러뜨리지 않는다.
- 원래 기준점은 별도 위치 수정 조작으로 옮긴다. 방향키 미세 이동과 수치 입력도 제공한다.
- 전체 지도를 반드시 훑게 하지 않는다. 사용자가 확인 가능한 구역에서 끝낼 수 있다.

### 적용·취소·재편집

- 편집은 임시 상태에서 수행한다. 적용 전 저장된 맵·토큰·탐험 기록은 변경하지 않는다.
- 적용 성공 뒤 저장된 상태를 다시 읽는다. 실패하면 편집값을 보존하고 재시도를 제공한다.
- 취소는 진입 시 상태로 돌아간다. 실행 취소·다시 실행은 드래그 완료 또는 수치 입력 확정을 한 단위로 처리한다.
- 수동 보정한 맵도 ‘격자 맞추기’를 다시 열 수 있다.
- 격자 보정과 플레이어 시작 위치 변경은 별개 조작으로 분리한다.

## 4. 계산·저장 계약

원본 이미지 좌표, 게임 격자 좌표, 화면 좌표를 구분한다. 화면 확대율과 이동량은 편집 표시만 바꾸며 저장하는 원점·칸 크기는 원본 이미지 기준이다.

- 이미지 위치 = 격자 원점 + 격자 좌표 × 한 칸 크기.
- 기준점의 격자 좌표를 a, 이미지 위치를 p라 하면 원점 = p − a × 한 칸 크기.
- 미세 조정할 교차점 b와 드래그한 이미지 위치 q에서 칸 크기는 `(q−p)·(b−a) / |b−a|²`로 계산하는 방안을 사용한다. 정사각 격자의 단일 크기에 맞춘 최소제곱 해이며 b=a인 경우는 크기 조절 대상에서 제외한다.
- 드래그 중과 저장 시 소수점 정밀도를 유지한다. 전체 칸 수와 실제 토큰 칸 인덱스만 정수다.
- 0 이하 크기, 유한하지 않은 값, 허용 해상도·칸 수 초과를 서버에서 거절한다. 이미지 크기는 클라이언트 주장 대신 저장된 원본으로 검증한다.
- 이미지 테두리의 부분 칸은 화면에서 잘라 표시할 수 있다. 실제 이동 가능한 칸은 별도 유효 범위로 정의하며 단순 반올림으로 추가하지 않는다.
- 기존 정수 데이터는 그대로 읽을 수 있게 한다. 정렬값을 별도 저장할지 기존 계약을 확장할지는 첫 구현 단계에서 관련 저장 경로까지 확인해 결정한다.

### 기존 플레이 상태 보호

초기 적용은 기존 게임 격자 좌표를 유지하는 정렬 변경으로 제한한다. 토큰·문·장애물의 칸 인덱스와 탐험 집합을 칸 수 비율로 자동 재배치하지 않는다. 이미지와 격자의 대응이 바뀌면 이 요소의 화면 위치는 변경될 수 있으므로 공개된 요소만 결과 미리보기에 표시한다.

게임 칸 수 변경이나 기존 요소가 이미지 유효 범위 밖으로 나가는 변경은 자동 확정하지 않는다. 이번 기능에서 저장을 거절하고 사유를 안내한다. 전체 지형 좌표 재구성은 별도 작업이다. 격자 정렬 적용만으로 게임 턴을 소비하거나 새로운 탐험을 기록하지 않는다.

플레이 중 편집은 이미 공개된 영역만 표시한다. 확대경도 같은 공개 범위를 지킨다. 현재 보정값으로 이미지를 가린 뒤 표시하고, 임시 정렬 조작으로 가림 영역 너머 원본을 끌어낼 수 없게 한다. 원본 전체가 플레이 응답으로 제공되는 문제까지 해결하는 것은 별도 범위지만, 이번 UI가 숨겨진 영역을 새로 표시해서는 안 된다.

## 6. 검증 기준

- 알고 있는 기준점과 소수점 칸 크기로 만든 시험 지도에서 좌표 변환과 저장 후 복원을 검증한다.
- 같은 이미지 지점을 서로 다른 확대율에서 선택해도 동일한 정렬값이 나온다.
- 먼 교차점을 맞춘 후 최초 기준점은 유지된다. 제안 허용 오차는 두 시험 교차점 모두 원본 이미지 기준 1픽셀 이내이며 합성 지도에서 검증한다.
- 기준점에 가까운 지점, 가로·세로축 위 교차점, 작은 칸, 큰 이미지, 여백 있는 지도, 격자 없는 지도 처리.
- 확대경의 십자선 위치와 실제 저장 좌표 일치. 터치·화면 가장자리·포인터 취소·키보드 입력 확인.
- 취소·단계 이동·재편집·저장 실패·재시도·오래된 버전 저장 거절 확인.
- 적용 후 토큰 좌표·문·장애물·탐험 기록이 보정 전과 같고 숨겨진 원본이 편집·확대경에서 보이지 않음.
- WSL에서 필요한 정책·API·화면 테스트 실행. 실제 브라우저 검증은 `src/start-dev.sh`와 서버 상태 확인 후 진행.

## 7. 후속 범위

육각 격자, 회전·왜곡 지도, 플레이 전 독립 맵 편집 화면, 게임 칸 수 변경에 따른 모든 위치 재구성은 후속이다. 이번 계획은 기존 맵 화면에서 사용할 수 있는 정사각 격자 맞춤 기능에 집중한다.
