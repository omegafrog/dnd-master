# 035-1 모험 자료 계약과 삭제 보호

- 상태: `completed`
- Issue: [#156](https://github.com/omegafrog/dnd-master/issues/156)
- 의존성: 없음
- 대상: `adventure-service`, `web-ui`, adventure 계약

## 구현 목적

사용자가 모험 자료를 UUID가 아닌 이름으로 식별하고, D&D 5판/5.5판 룰북을 별도로 선택하며, 파일별 역할을 일관되게 저장할 수 있도록 한다. 진행 중인 모험이 연결된 자료는 삭제하지 못하게 하여 세션 참조가 깨지는 것을 막는다.

## 범위

- 모험 자료 이름과 명시적 룰북 판본을 bundle 모델·DTO·저장소에 추가
- bundle 생성/수정 시 룰북 정확히 1개, 비어 있지 않은 이름, 메인 시나리오 최대 1개 검증
- 선택한 문서의 준비 완료 상태를 서버에서 검증
- bundle 삭제 전 연결된 진행 중 모험/세션 조회
- 삭제 불가 시 안정적인 `ACTIVE_ADVENTURE_REFERENCES_BUNDLE` 오류 반환
- 목록·상세 응답에 이름, 룰북, 자료 수, revision, 상태 제공
- `SetupApi`와 관련 UI가 새 계약을 사용하도록 변경

## 제외 범위

- 자료 처리 진행률 UI
- 게임 준비 팝업
- AI endpoint 로그인 구현
- 실제 모험 삭제 또는 보관 기능

## 정책 테스트

- 이름이 공백이면 저장 거부
- 룰북 판본이 없거나 두 개로 해석되면 저장 거부
- 메인 시나리오가 두 개면 저장 거부
- 준비 완료가 아닌 문서가 포함되면 저장 거부
- 활성 세션이 참조하면 삭제 거부
- 완료된 세션만 연결된 경우 삭제 가능 여부를 명시된 정책에 맞게 검증

## UI ↔ Entity 통합 테스트

- 이름·판본·파일 역할을 입력한 뒤 bundle create 요청의 JSON을 검증
- 목록 카드가 UUID 대신 이름과 판본을 표시하는지 검증
- 삭제 시 409 오류가 사용자용 삭제 불가 메시지로 표시되는지 검증

## 완료 조건

- 서버가 모든 bundle 불변식을 강제한다.
- 기존 bundle revision/패키지 참조 호환성이 유지된다.
- API 계약 테스트와 도메인 정책 테스트가 통과한다.
- 프론트가 새 이름·판본·삭제 충돌 계약을 사용한다.
