# 모험 마무리 단계 구현 계획

## 목적

목표가 해결됐다는 사실만으로 모험과 세션을 즉시 끝내지 않는다. 목표 해결 뒤에 이야기의 정리와 보상 처리를 진행하고, 연결된 던전이 남아 있으면 다음 던전으로 이어간다. 마지막 구간의 마무리가 끝난 때에만 전체 모험을 완료한다.

## 확인한 문제

현재 `docs/specs/scenario-model-runtime/product-spec.md`는 해결 조건을 충족한 GM 턴에서 결말 장면을 생성하고, 턴 저장 후 모험을 `COMPLETED`로 처리하도록 정의한다. `GmAgentRuntimePlanningAdapter.validatedCompletion()`은 후보의 완료 여부와 목표·해결 조건 충족 여부로 완료 제안을 만들며, `CompletionProposal`에는 별도 마무리 상태나 보상 지시가 없다. `RuntimeTurnApplicationService.saveAdventureTurn()`은 완료 제안을 받으면 `adventureCompletionCommitPort.saveCompleted(...)`를 호출한다.

이 경계에서는 목표 해결과 이야기의 끝이 같은 사건이 된다. 따라서 마을로 돌아가 결과를 알리거나, 자료에 명시된 보상을 수령하거나, 연결된 다음 던전으로 이동하는 장면을 완료 전에 안정적으로 진행할 수 없다. `A Most Potent Brew` 실행에서도 쥐 소탕과 통로 차단 뒤 완료 처리됐지만 스토리북의 보상은 지급되지 않은 사례가 확인됐다.

현재 제품 명세는 이 계획과 충돌하므로 구현 전에 완료 시점과 모험 범위를 명세에 반영해야 한다.

## 설계 원칙

- 목표 해결, 현재 던전 마무리, 전체 모험 완료는 서로 다른 상태로 표현한다.
- 결말 장면은 모험 자료와 실제 플레이 기록에 근거한다. 자료에 없는 귀환, 보고, 보상 장면을 필수 절차로 만들지 않는다.
- 단일 던전은 해당 던전의 마무리가 끝나면 전체 모험 완료로 진행한다.
- 여러 던전은 사용자가 하나의 모험으로 연결한 경우에만 구간을 이어간다. 중간 던전 완료는 전체 모험 완료가 아니다.
- 보상은 선택한 모험 자료나 사용자가 지정한 캠페인 구성에서 근거를 확인하고, 캐릭터 상태에 중복 없이 반영한다.
- 세션 종료는 플레이어가 임의로 선언하는 경로와 목표 충족에 따른 완료 처리를 분리해 다룬다.

## 구현 순서

### 1. 완료 경계와 모험 범위 확정

제품 명세에 `목표 해결 → 마무리 진행 → 던전 마무리 → (다음 구간 진행 또는 전체 모험 완료)` 흐름을 정의한다. 마무리 진행 중에 필요한 GM 서술과 플레이어 응답, 보상 처리 완료 조건을 구체화한다. 연결된 던전이 같은 전체 모험에 속하는지 판별하는 기준과, 실패·포기·미완료 상태의 의미도 명세에서 정한다.

완료 조건은 적어도 다음을 만족해야 한다.

- 목표 충족만으로 모험 또는 세션이 완료되지 않는다.
- 현재 구간의 마무리가 완료되기 전에는 다음 구간으로 넘어가거나 전체 모험을 완료하지 않는다.
- 다음 구간이 있으면 전체 모험은 열린 상태로 유지한다.
- 전체 모험의 마지막 구간에서 마무리와 필수 보상 처리가 끝나면 완료할 수 있다.

### 2. 시나리오 자료에 마무리 정보를 보존

시나리오 컴파일 결과에 자료에서 추출한 보상, 종료 조건, 보고·귀환 등 마무리 단서, 다음 구간 참조를 저장한다. 각 항목은 출처와 연결해 검증할 수 있게 한다. 출처가 확인되지 않는 보상은 자동 지급하지 않는다. 독립 시나리오를 임의로 하나의 연속 모험으로 합치지 않는다.

### 3. 런타임에 마무리 진행 추가

완료 판정 어댑터는 목표 충족 시 즉시 완료를 제안하는 대신 마무리 진행을 시작한다. 마무리 중 GM은 남은 결과를 서술하고 필요한 플레이어 응답을 기다리며, 보상 지급을 확정한다. 마무리 상태 전이와 장면 저장은 턴 저장 경계에서 일관되게 처리한다.

중간 구간의 마무리가 완료되면 해당 구간을 닫고 다음 구간을 준비한다. 마지막 구간에서만 전체 모험 완료 제안을 만들 수 있게 한다. 기존 세션 상태와 모험 상태가 함께 저장되는 경계도 검토해 한쪽만 완료되는 상태를 막는다.

### 4. 보상 지급의 검증과 중복 방지

보상 지시를 명시적인 형식으로 표현하고, 출처·수령 대상·수량·종류를 검증한다. 골드·아이템·경험치처럼 캐릭터 상태를 바꾸는 보상은 기존 캐릭터 관리 기능과 연결한다. 재시도 및 중복 요청에도 한 번만 적용되도록 멱등성을 보장한다. 보상 지급과 마무리 상태 저장이 실패할 때 재시도해도 장면이나 보상이 중복되지 않는 처리 경계를 정한다.

### 5. 화면에서 진행 상태 표시

플레이 화면에 마무리 진행, 보상 처리, 다음 던전 진행, 전체 모험 완료를 구분해 표시한다. 현재 구간 목표가 해결됐지만 마무리가 남았다는 사실을 알아볼 수 있어야 한다. 플레이어가 받을 응답을 기다리는 장면에서는 완료로 오인되는 종료 동작을 제공하지 않는다.

### 6. 명세 기반 검증

- 목표를 달성해도 마무리 전까지 모험이 완료되지 않는지 검증한다.
- 단일 던전은 마무리 완료 후 전체 모험이 완료되는지 검증한다.
- 연결 모험의 중간 던전은 다음 구간으로 이어지고 전체 모험을 열린 상태로 유지하는지 검증한다.
- 마지막 구간의 마무리 후에만 전체 모험을 완료하는지 검증한다.
- 자료에 없는 보상을 만들지 않고, 명시된 보상은 캐릭터에게 정확히 한 번 적용하는지 검증한다.
- 저장 재시도와 중복 요청 시 마무리 서술, 상태 전이, 보상이 중복되지 않는지 검증한다.
- `A Most Potent Brew` 전체 진행에서 쥐 소탕·통로 차단 뒤 귀환/보고 등 자료가 요구하는 마무리와 명시된 보상 반영을 확인한다.

## 웹 참고 자료

- [Dungeon Master's Guide (2024), D&D Beyond](https://www.dndbeyond.com/sources/dnd/dmg-2024): 목차에서 모험 끝맺기, 모험 보상, 캠페인 종료를 별도 항목으로 다룬다.
- [Let's Prepare an Adventure Using the 2024 Dungeon Master's Guide!, D&D Beyond](https://www.dndbeyond.com/posts/1851-lets-prepare-an-adventure-using-the-2024-dungeon): 목표 해결 뒤 귀환과 보상 같은 끝맺음 장면을 보여주는 모험 준비 사례다.
- [A Hero's Welcome: Making Your Characters Feel Good about Saving the World, D&D Beyond](https://www.dndbeyond.com/posts/404-a-heros-welcome-making-your-characters-feel-good): 구출 이후의 인정과 물질적·비물질적 보상을 다룬다.
- [Remixing Avernus – Part 8: The End, The Alexandrian](https://thealexandrian.net/wordpress/47025/roleplaying-games/remixing-avernus-part-8-the-end): 주요 갈등을 마무리하고, 앞서 나온 요소를 결말에 다시 연결해 전체 이야기에 결속감을 주는 방식을 논한다.

## Astra 서브에이전트 실행 기록

계획 작성 시 `gpt-6-astra` 모델과 medium 추론 수준의 서브에이전트를 요청했으나, 기존 대화의 에이전트 슬롯 제한으로 시작되지 않았다. 따라서 본 계획은 저장소 조사와 웹 자료를 직접 확인해 작성했다.
