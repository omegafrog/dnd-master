# 표 후보 비교 수정 확인

표 탐지 방식별 후보를 보존하고, 셀 격자·원문 문자 대응·행 연속성 근거를 함께 검증하도록 수정했다. 근거가 충분하지 않으면 표 셀을 만들지 않고 원래 텍스트 블록을 유지한다. 모든 후보와 채택·보류 사유는 `document_structure.json`의 `native_table_diagnostics`와 `ADVENTURE_RUNTIME_DIAGNOSTICS_ENABLED=true` 로그에 남는다.

### Basic Roleplaying 8페이지 상세 진단

원본 대조 정답에는 5행·2열 표 1개가 있다. 선 기반 탐지는 후보를 만들지 못했고(172ms), 전체 페이지 텍스트 정렬 탐지는 72행·10열 후보 1개를 만들었다(351ms). 이 후보는 페이지 면적의 76.7%를 차지하고 정답 표와의 경계 IoU가 0.1977에 그쳤다. 후보의 72행 중 23행은 원문 셀 내용으로 뒷받침되지 않아 `TEXT_DETECTION_EMPTY_ROWS_REQUIRE_GEOMETRIC_CONFIRMATION`으로 보류됐다. 셀은 하나도 게시되지 않았다.

후보 위치를 사람이 눈으로 확인한 표 영역으로 잘라 다시 탐지하는 실험도 했다. 표 전체를 포함한 영역은 16행·12열, 데이터 행만 포함한 영역은 14행·12열, 주변 문단까지 포함한 더 넓은 영역은 22행·14열로 나왔다. 세 결과 모두 정답인 5행·2열을 복원하지 못했다. 이 실험은 표 경계를 이미 알고 넣은 진단용 클립이므로 자동 후보 생성의 성공으로 계산하지 않는다.

| 측정 항목 | 결과 | 해석 |
|---|---:|---|
| 실제 표 탐지 | 0/1 | 재현율 0%; 미해결 |
| 채택된 표 구조 | 0/1 | 구조 정확도는 측정 불가 |
| 전체 페이지 후보 | 1개, 보류 1개 | 후보 보류율 100% |
| 잘못된 표 구조 채택 | 0개 | 오확정은 막았지만 표를 복원하지 못함 |
| 페이지 원문 토큰 보존 | 994/994 | 추출 산출물의 토큰 집합이 원본과 일치; 표 내용은 텍스트 청크에 남음 |

따라서 이 사례는 “표 후보를 안전하게 보류했다”는 안전성 결과와 “실제 표 구조를 찾았다”는 복원 결과를 분리해 봐야 한다. 현재는 전자는 통과했고 후자는 실패했다. 표 영역 안에 한 개의 가로선과 반복되는 왼쪽 번호·오른쪽 설명 배치가 보이지만, 이를 일반 규칙으로 분할하는 방법은 이번 자료 하나로 검증되지 않았다. 특정 제목이나 표 문구를 이용하는 예외는 추가하지 않았다.

재현 가능한 후보·원문 보존 측정값은 [BRP 8페이지 표 진단 JSON](brp-page-008-table-diagnostic.json)에 저장했다. 원본 PDF와 정답 라벨의 SHA-256은 모두 `d38af1fc2c27326b0ee8e42af0579684220ccf30809b195275d9daf29cedbb28`이다.

Cairn Player에서 보충 행을 자동 추가하는 조건은 특정 페이지나 자료 이름이 아니다. 검출된 열 수와 같은 수의 열에 원문 텍스트가 하나의 행으로 정렬되고, 셀마다 좌표가 하나의 열에만 대응하며, 전체 원문 토큰과 복원 셀 토큰이 일치해야 한다. 이 조건이 충족되지 않으면 후보를 검토 대상으로 남긴다.

빈 행은 문자 정렬만으로 만든 후보에서 표 구조의 근거로 사용하지 않는다. 실제 빈 행일 가능성을 배제하지 않고, 별도 기하 근거가 없을 때 자동으로 채택하지 않는 정책이다.
