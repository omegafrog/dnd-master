# ADR-018: 판정이 필요한 지도 이동을 예약 후 최종 반영

## 상태

Accepted

## 배경

전술 지도 이동은 통과 칸마다 시야와 탐험 영역을 바꾸고, 함정·비밀문·위험 지역·마법 범위 효과와 적의 인지를 처리한다. Combat Map은 지도 상태의 정본이지만, 지각·해제·내성·피해 같은 룰북 판정과 캐릭터 상태 변경은 Adventure Runtime, Dice Roll, Character Management가 소유한다.

Combat Map이 먼저 이동을 저장한 뒤 외부 판정을 요청하면 판정 실패나 서비스 장애 때 위치·공간 요소·전장의 안개가 부분 반영될 수 있다. 반대로 Adventure Runtime이 숨겨진 지도 상태를 복제해 이동을 해결하면 Combat Map의 정본 소유권과 비공개 정보 경계가 깨진다.

## 결정

- Combat Map은 지형, 토큰 위치, 공간 요소, 시야·탐험 상태의 정본을 유지한다.
- 공간 요소는 `CombatMap` aggregate 내부 entity다. 별도 저장소, bounded context, module, 배포 service를 만들지 않는다.
- 직접 드래그와 자연어 이동은 상태 변경 권한이 없는 이동 제안을 만든다. 경로 미리보기는 플레이어에게 공개된 통행 정보만 사용하며 숨겨진 적과 공간 요소를 입력이나 응답에 포함하지 않는다.
- 확인된 이동은 Combat Map 내부의 durable 이동 예약으로 시작한다. 예약은 명령 ID, 지문, 기준 지도 버전, 검증된 경로, 현재 처리 위치, 필요한 판정과 결과, 상태를 보존한다.
- 이동 예약은 aggregate가 아니라 Combat Map application layer의 장기 실행 작업 기록이다. 같은 지도에는 한 번에 하나의 상태 변경 예약만 허용한다.
- Combat Map은 경로를 칸 순서대로 평가하고 필요한 판정 요청만 Adventure Runtime에 반환한다. Adventure Runtime은 룰북 규칙과 굴림 소유권에 따라 판정을 해결하고 결과를 같은 예약에 돌려준다.
- 모든 필수 판정 결과가 준비되면 Combat Map이 위치, 공간 요소, 시야·탐험 상태를 하나의 로컬 트랜잭션으로 최종 반영한다. 최종 반영 전 검증·판정·연동 실패는 예약을 취소하며 공개 지도 상태를 바꾸지 않는다.
- 플레이어 굴림 대기는 자동 만료하지 않는다. 시스템 판정과 서비스 호출은 기존 재시도 정책을 따르고, 서버 재시작 뒤에는 명령 ID와 저장된 진행 상태로 이어서 처리한다.
- Combat Map 최종 반영 뒤의 HP·상태·자원 변경은 ADR-003의 Runtime Command Saga가 멱등하게 완료한다. 후속 서비스 장애로 이미 확정된 이동이나 함정 발동을 되돌리지 않으며, 필수 변경이 끝나기 전 성공 서술은 확정하지 않는다.
- 이동 중 적이 플레이어를 새로 알아차리면 Combat Map은 해당 칸의 공간적 사실과 이동 중단만 확정한다. 전투·경고·대화·추격 결정은 Adventure Runtime이 소유한다.
- 자연어 이동의 확인 대기는 Adventure Runtime이 진행 단위와 함께 보존한다. Combat Map은 확인 전 이동 제안을 저장하지 않는다.
- 기존 `TRAP`·`OBJECT` 토큰은 공간 요소로 한 번 이전한다. 부족한 규칙 정보 때문에 이전된 항목은 자동 발동 없는 표시용 상태로 시작하며, 새 함정·상호작용 대상은 토큰으로 생성하지 않는다. 기존 enum 입력은 호환 기간에만 읽기 허용한다.

## 경계 판단

- 단일 동기 메서드는 외부 판정을 기다리는 동안 재시작·재시도·플레이어 굴림 대기를 보존할 수 없어 충분하지 않다. 따라서 application layer의 durable 작업 기록이 필요하다.
- 별도 bounded context나 배포 service는 필요하지 않다. 이동 예약은 Combat Map의 상태를 안전하게 변경하기 위한 내부 capability이며 독립 언어·데이터 생명주기·운영 주기가 없다.
- 분산 트랜잭션은 도입하지 않는다. 최종 지도 반영 전에는 로컬 예약으로 변경을 보류하고, 최종 반영 뒤의 다른 서비스 변경은 기존 Runtime Command Saga로 복구한다.

## 결과

- 이동 중 외부 판정이 필요해도 공개 지도 상태는 최종 반영 전까지 일관된다.
- 같은 지도에 장기 예약이 있으면 다른 지도 변경은 충돌하므로, 대기 상태와 복구 상태를 사용자·운영자가 확인할 수 있어야 한다.
- Combat Map API에는 이동 예약 시작, 판정 결과 재개, 최종 결과 조회·취소 계약이 필요하다.
- Adventure Runtime은 자연어 확인 대기와 이동 예약 진행을 재접속·재시작 뒤에도 복원해야 한다.
- 이동 최종 반영 이후 Character Management 장애는 지도 롤백이 아니라 Saga 재시도로 처리한다.
