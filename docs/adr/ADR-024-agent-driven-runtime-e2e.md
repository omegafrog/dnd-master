# ADR-024: 모험 시작 이후 E2E를 에이전트가 직접 진행

## 상태

승인됨 — 사용자가 모험 시작 이후 Playwright E2E를 사용하지 말고 개별 Markdown 절차를 읽어 직접 검증하라고 지시했다. 2026-10-20에 실행 문서가 참조하던 누락 파일을 이 지시로 복원했다.

## 배경

모험을 시작한 뒤에는 실제 AI 게임 마스터의 응답과 플레이어 굴림 요청에 따라 진행이 달라진다. 정해 놓은 응답이나 화면 순서를 재생하면 실제 에이전트와 상태 저장을 거치는 사용자 흐름을 확인할 수 없다.

## 결정

- 모험 시작 이후 E2E는 검증 에이전트가 작업별 Markdown 절차를 읽고 실제 앱과 실제 게임 마스터 응답을 보며 브라우저를 직접 조작한다. Playwright로 고정된 대화와 진행 순서를 실행하지 않는다.
- 절차에는 전제, 사용자 행동, 매 단계 확인할 화면과 저장 상태, 굴림 대기·실패 시 복구, 종료 조건을 적는다. 모델의 답변 원문을 예상값으로 고정하지 않는다.
- 실제 실행·연결·복구는 [EXEC.md](../agents/EXEC.md), [BROWSER.md](../agents/BROWSER.md) 및 실행 프로필을 따른다. 연결이 끊기면 저장 상태와 마지막 성공 화면을 확인해 연결을 복구하고 이어 간다. 실패·차단·미실행을 통과로 기록하지 않는다.
- 이번 상황 생성 검증에서는 기존 3종 자료와 룰북의 추출 결과를 사용한다. 같은 지도 파일이면 저장된 격자를 재사용할지 직접 수정할지 사용자가 선택한 뒤 따른다. 이미 재사용을 선택한 실행에서 같은 선택을 반복해서 요구하지 않는다. 자료 재추출·DB 초기화·기존 모험 삭제는 이 검증에 포함하지 않는다.
- 사용자가 브라우저를 열어 두라고 지정한 실행에서는 창을 유지하며, 수동 격자 조정을 기다리는 동안 진행하지 않는다.
- 모험 시작 전의 준비 화면처럼 실제 모델 응답에 의존하지 않는 경로와 단위·정책·저장소 검증은 각 작업의 기존 검증 방식을 사용할 수 있다.

## 결과

검증 결과에는 실제 진행 분기, 화면과 저장 상태에서 확인한 사실, 실패·복구 여부를 기록한다. 실행 증거는 Harness 세션 디렉터리에 보존하며, 준비된 이름과 설명의 서사 적합성은 실제 생성 결과를 원문 근거와 대조해 판단한다. 형식 검사가 통과했다는 사실만으로 서사 품질을 검증했다고 표시하지 않는다.
