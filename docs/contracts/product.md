# 제품 계약

이 문서는 현재 제품 기능의 합의된 동작을 모은다. 티켓별 명세는 근거이며, 적용 상태는 통합 계약의 상태와 구현·검증 근거로 판단한다.

<a id="map-runtime"></a>
## 전장 지도 준비와 공개
수정일: 2026-10-21

### 설명
모험을 시작하기 전에 맵 초안을 준비하고 플레이어가 `STARTING` 상태에서 격자·벽·문을 검수해 확정한다. 맵이 필요한 시츄에이션을 활성화할 때 시작 위치와 공개 영역을 정해 플레이어용 지도를 제공한다. 근거: [맵 준비 제품 명세](../specs/278/product-spec.md), [격자 맞추기 제품 명세](../specs/map-grid-alignment/product-spec.md).

### 비즈니스 규칙
- 시츄에이션의 맵 필요 속성이 시작 전 준비 여부를 결정한다.
- 지도가 필요한 시츄에이션은 지도 활성화 전에 적·함정·문·잠금 등 초기 배치를 준비한다. 비공개 배치를 저장한 뒤 공개 여부를 시야와 발견 상태로 판단한다. 이 조건은 승인된 목표이며 현재 E2E에서 적 배치 누락이 확인돼 미완료다. 근거: #365, BR-40.
- 진입 서술과 맵 자료를 바탕으로 시작 위치를 정한다. 시작 위치 후보가 없거나 생성 요청이 실패하면 최초 요청을 포함해 최대 6회 시도하고, 후보가 나오면 멈춘다. 모두 소진하면 플레이어의 수동 배치로 이어간다. 비공개 요소는 플레이어에게 공개하지 않는다.
- 모험에 연결한 지도 정의는 시작 뒤 바꾸지 않는다. 같은 지도에 다시 들어가면 저장된 지도 상태를 이어 쓰고 시작 위치를 다시 추론하지 않는다.
- 맵 검수와 격자·벽·문 수정은 취소와 재시도에서 기존 플레이 상태를 보존한다. 준비 중 가로·세로 칸 수를 명시적으로 바꾸면 범위 밖 콘텐츠는 허용하지 않으며, 기존 벽 경계는 새 격자 기준으로 다시 그릴 수 있도록 삭제한다.

### 수용 조건
- 맵이 필요하지 않은 시츄에이션은 지도 없이 시작할 수 있다.
- 모험은 필요한 맵 초안을 검수하고 저장한 뒤 시작할 수 있다.
- 준비 중 연결할 맵 파일이 같은 모험에서 이미 격자를 맞춘 맵 파일과 동일하고 저장 격자가 있으면, 저장 격자를 재사용할지 직접 수정할지 먼저 사용자에게 묻는다. 선택 전에는 맵 준비를 마치지 않는다. 재사용은 저장 정렬을 바꾸지 않으며, 직접 수정은 기존 격자 편집 흐름을 사용한다.
- 맵이 필요한 시츄에이션은 활성화 전에 시작 위치가 정해져야 한다.
- 같은 지도의 재방문은 기존 지도 상태를 유지하며 시작 위치 재추론을 일으키지 않는다.
- 플레이어 화면은 공개된 영역과 허용된 토큰 정보만 표시한다.

<a id="combat-loop"></a>
## 전투 진행과 전투 화면
수정일: 2026-10-22

### 설명
전투 진입, 차례와 라운드, 플레이어 행동, 반응, 적 행동과 전투 종료를 관리한다. 근거: [전투 화면 제품 명세](../specs/combat-ui/product-spec.md), [전투 행동 제품 명세](../specs/combat-ai-actions/product-spec.md).

### 비즈니스 규칙
- 전투 순서와 행동 자원은 전투 상태에 따라 검증한다.
- 플레이어는 캐릭터 차례의 행동 전·사이·후에 허용된 남은 이동량을 사용할 수 있다. 이동은 플레이어가 확인한 경로를 한 칸씩 반영한다. 이동 중 GM 판정·서술이 필요한 사건에 도달하면 실제 위치와 사용한 이동량을 보존하고 멈춘다. GM 서술만으로 플레이어 토큰을 옮기거나 차례를 끝내지 않는다. (전투 이동·주문 사거리 Product Spec UC-002, BR-05, BR-08, BR-16, BR-18, BR-19)
- 적의 전투 수치는 룰북·시나리오 근거를 읽은 에이전트가 고정 응답 계약으로 반환하고, 백엔드가 값과 근거 범위를 검증해 저장한다. 원문 글줄을 정규식으로 해석하는 것을 전투 시작의 선행 조건으로 사용하지 않는다.
- 플레이어 소유 캐릭터의 행동은 사용자가 정한다. GM은 세계·NPC·적·판정과 서술을 맡는다.
- 잘못되거나 오래된 행동은 상태를 바꾸지 않는다. 비공개 적 정보는 공개 결과에서 제거한다.
- 전투가 시작될 때 발견되지 않은 참가자에게만 첫 차례 건너뛰기를 적용한다. 이미 알아차린 참가자의 차례는 그대로 진행한다. (전투 이동·주문 사거리 Product Spec AC-41, BR-49)

### 수용 조건
- 전투 진입 시 차례, 지도와 행동 정보가 표시되고, 종료 시 일반 진행으로 돌아간다.
- 행동은 검증을 통과한 경우 한 번만 적용된다.
- 반응은 발동 조건과 차례 외 사용 조건을 확인한 뒤 처리한다.
- 이동 중 사건을 처리한 뒤에도 차례를 유지하고, 플레이어가 남은 이동량으로 새 경로를 확인하거나 다른 허용된 행동을 하거나 명시적으로 차례를 끝낼 수 있다. 확인하지 않은 경로 나머지는 실행하지 않는다.

<a id="spatial-movement"></a>
## 지도에서 이동과 조우 해결
수정일: 2026-10-22

### 설명
탐험 그룹과 전투 토큰의 이동 경로를 칸별로 해결하고, 발견·함정·충돌에서 이동을 멈춘다. 근거: [공간 이동 제품 명세](../specs/spatial-movement-resolution/product-spec.md), [이동·조우 결정](../specs/combat-movement-spell-range/runtime-decisions.md).

### 비즈니스 규칙
- 확인 전 경로는 의도일 뿐이며 위치와 전장의 안개를 바꾸지 않는다.
- 확인된 경로는 칸마다 지형·이동량·시야·위협을 확인한다. 중단 사건이 생기면 해당 칸에서 멈춘다.
- 전투 이동에서 GM 처리가 필요한 사건이 이동 도중 발생하면 캐릭터 토큰은 실제 도달한 칸에 머물고, GM은 사건을 판정·서술한 뒤 플레이어의 다음 행동을 기다린다. 플레이어가 확인하지 않은 경로는 이어서 이동시키지 않는다. (전투 이동·주문 사거리 Product Spec UC-002, BR-08, BR-16, BR-19)
- 지도 탐험에서는 시간을 멈춘 뒤 전열 캐릭터의 우선권으로 그룹 순서를 정하고, 동점 그룹 순서는 무작위로 정한다. 각 그룹은 차례대로 자기 이동량만큼 이동하고, 모든 그룹 차례가 끝난 뒤 환경을 6초 진행한다.
- 한 그룹의 이동 중 사건이 생기면 모든 그룹 차례를 멈추고 그 사건부터 처리한다. 전투가 아니면 사건을 일으킨 그룹의 차례를 끝내고 다음 그룹부터 이어간다. 그룹 우선권은 지도 탐험이 끝날 때까지 유지한다.
- 모든 그룹 차례가 끝나면 환경을 6초 진행한다. 환경 단계 중 조우가 생기면 환경 처리를 멈추고 사건을 해결한 뒤 남은 환경 처리를 이어간다.
- 그룹은 구성원과 대열을 저장한다. 이동 속도는 가장 느린 구성원 기준이다. 전투에서는 대열을 바탕으로 캐릭터 토큰을 배치한다.
- 위협 발견은 캐릭터별 대열·이동·사용 가능한 시트 사실·숨김 상태로 GM이 판정한다. 필요한 숫자 정보가 없으면 캐릭터 굴림을 꾸미지 않고 고정 응답으로 발견자를 판정한다. 발견자와 공유 상태는 탐험 순환에 저장하지만, 누구인지에 관한 발견 정보는 동료에게 알릴 때까지 공개 응답에서 제외한다. GM 결과는 알림이 적에게 들렸는지도 기록한다. (전투 이동·주문 사거리 Product Spec BR-49)
- 양쪽이 숨지 않았다면 파티와 적이 서로 알아차린다. 위협 발견만으로 전투를 시작하지 않으며, 적대 행동으로 전투가 시작되면 알아차리지 못한 참가자만 첫 차례를 건너뛴다. (전투 이동·주문 사거리 Product Spec AC-41, BR-49)

### 수용 조건
- 벽과 통과 불가 지형은 이동을 차단하고, 통과한 칸의 안개만 순서대로 갱신된다.
- 발견·함정·기습 등 중단 사건이 발생한 칸과 소비한 이동량이 보존되고, 사건 처리 중 남은 경로는 자동 진행하지 않는다.
- 전투 이동 중 GM 처리가 필요한 사건을 판정·서술한 뒤 플레이어 턴이 자동 종료되지 않고, 남은 이동량과 규칙이 허용하는 다음 입력을 플레이어가 선택할 수 있다.
- 각 지도 탐험 순환은 모든 그룹 차례 뒤 환경을 6초 진행하며, 그 순서와 시간이 적·순찰·함정·지속시간 처리에 적용된다.
- 환경 단계 도중 조우가 생기면 처리 위치와 남은 환경 단계를 보존하고, 사건 해결 후 이어서 처리한다.
- 발견 사실은 발견한 캐릭터에게만 알려지고, 알리는 행동으로 그룹에 공유된다.
- 그룹 알림은 발견한 캐릭터의 명시적 행동이며 한 번 적용된다. 그 캐릭터가 알리면 같은 그룹이 알게 되고, 적이 들었는지에 따라 적도 전투 시작 전에 알아차릴 수 있다.

<a id="ability-use"></a>
## 주문·기술 준비와 사용
수정일: 2026-10-19

### 설명
캐릭터 시트에 있는 능력만 현재 모험에 준비하고, 전투와 비전투 실행을 분리해 처리한다. 근거: [전투 이동·주문 사거리 제품 명세](../specs/combat-movement-spell-range/product-spec.md).

### 비즈니스 규칙
- 캐릭터 시트는 능력 식별자를 보유하고, 상세 정보는 현재 모험의 DB에 한 벌 저장한다.
- 모험 시작 때 초기 능력, 새 능력을 배울 때 그 능력만 RAG 근거로 구조화해 저장한다. 저장된 능력은 DB 값으로 조회한다.
- GM은 기존 MCP 조회 경로로 모험·캐릭터·능력 식별자를 전달해 실제로 배운 능력인지 확인하고 상세정보를 조회한다. 다른 모험 자료나 배우지 않은 능력은 반환하지 않는다.
- 서로 충돌하는 근거는 사용자에게 확인한다. 자동 준비가 끝까지 실패하면 원문 입력을 요청하고, 입력 취소 시 습득을 확정하지 않는다.
- 전투 엔진과 비전투 엔진은 분리한다. 사용이 확정된 능력은 효과 성공 여부와 무관하게 자원을 차감한다. 엔진이 효과를 처리하지 못하면 GM이 엔진을 대신해 해결한다.
- 전투 지도는 행동 공간의 중심에 표시한다. 주문·원거리 공격·투척의 조준 미리보기는 읽기 전용으로 사거리·경로·효과 범위와 공개된 대상만 보여 준다. 미리보기는 상태와 자원을 바꾸지 않고 숨겨진 정보를 드러내지 않는다.
- 사용자는 능력과 대상을 선택한 뒤 명시적으로 실행을 확정한다. 실행 시 최신 상태로 다시 검증하고, 오래된 요청은 자원 소모 없이 거부한다.

### 수용 조건
- 능력 상세 정보가 출처 위치와 함께 모험별로 저장되고 다른 모험에서 재사용되지 않는다.
- MCP 조회는 현재 모험에서 캐릭터가 배운 능력 ID만 반환한다. 조회 상태는 상세정보 있음·복구 필요·미습득 또는 없음·오류를 구분한다.
- 범위 미리보기는 읽기 전용이며 실행 전 확인 단계와 실행 시 검증을 분리한다.
- 선택에 따라 자원이나 효과가 달라지면 실행 전에 사용자에게 묻는다.
- 전투와 비전투 모두에서 자원 변화가 한 번만 결정적으로 반영된다.

<a id="character-sheet"></a>
## 캐릭터 시트와 모험 중 상태
수정일: 2026-10-19

### 설명
캐릭터 시트의 공통 항목과 모험 중 상태를 룰북 근거와 승인된 플레이 결과에 따라 관리한다. 근거: [캐릭터 시트 제품 명세](../specs/character-sheet-shared-fields-runtime-state/product-spec.md).

### 비즈니스 규칙
- 추가 항목은 추천 근거를 확인하고 사용자가 선택한다.
- 모험 시작에 필요한 값이 완성되어야 시작할 수 있다.
- 게임 중 정본 상태는 해결되고 승인된 결과로만 바뀌며 파생 값은 다시 계산한다.

### 수용 조건
- 여러 플레이어 캐릭터 시트의 공통 항목 변경은 전부 적용되거나 전부 적용되지 않는다.
- 필요한 시작 값이 빠졌으면 누락 항목을 식별해 시작을 막는다.
- 체력·자원 등의 변경이 해결 기록과 함께 반영된다.

<a id="scenario-runtime"></a>
## 시츄에이션 기반 모험 진행
수정일: 2026-10-21

### 설명
모험 시작 전에 필수 시츄에이션 그래프와 필요한 연결 후보를 준비한다. 플레이 중에는 확정된 세계 상태와 플레이어 행동에 따라 준비된 시츄에이션만 선택한다. 근거: [시나리오 런타임 제품 명세](../specs/scenario-model-runtime/product-spec.md), [시츄에이션 후보 제품 명세](../specs/scenario-situation-candidates/product-spec.md). 이전 `Stage Backbone` 명세는 이 시츄에이션 런타임으로 대체되었으며 역사 자료로만 보존한다: [이전 이야기 진행 명세](../specs/story-runtime/product-spec.md).

### 비즈니스 규칙
- 모험 전체의 모든 사실을 미리 구조화하지 않는다. 현재 진행에 필요한 근거를 검색한다.
- 유저 입력이 없는 시작 요청에서는 비어 있는 대화 영역으로 입력 컨텍스트를 구성하고, GM이 오프닝을 서술한다.
- 한 GM 차례의 상태 변경과 플레이어 결과는 함께 확정한다. 숨겨진 사실은 정당하게 드러나기 전 공개하지 않는다.
- 플레이어는 파티 캐릭터를 조작한다. GM은 세계, 적, 판정, 대화와 결과 서술을 맡는다.
- 모험 시작 때 선택한 룰북과 판본에 맞는 적용 규칙 모음을 저장하며, 세션 복구 때 같은 소유자의 저장 자료를 이어 쓴다.
- 준비 상황은 구체적인 이름과 간결한 장면 설명을 가지며, 정보 공개 같은 내부 의도 유형을 장면 이름으로 대신하지 않는다. 장면은 플레이어의 행동과 해결 결과를 미리 고정하지 않는다. 이 내용 계약은 승인된 구현 목표이며 현재 구현 완료를 뜻하지 않는다.
- 준비 중 사용자는 짧게/보통/길게 슬라이더로 이야기 길이를 고른다. 필수 상황 그래프 노드 수에 각각 0.25/0.5/1.0을 곱해 올림한 선택 상황 최대 완료 수를 내부 계산하고 정확한 수는 표시하지 않는다. 선택 값과 허용량·사용량은 모험 진행 상태에 보존한다.
- 필수 상황은 확인된 원문 관계를 보존한 비순환 그래프다. 시작 상황은 하나이며 원문에서 명시한 끝 상황은 하나 이상이다. 모든 끝이 아닌 상황은 끝에 도달할 수 있고 끝에는 후속 필수 상황이 없다. 끝 표시는 원문에서 명시 추출·저장하며 후속 관계 없음으로 추론하지 않는다. 여러 선행 상황과 합류를 허용한다.
- 상황 종료 뒤 현재 상황에 명시적 끝 표식이 있으면 다른 후보를 확인하지 않고 이번 턴의 기존 확정 경계에서 모험 완료를 함께 반영한다. 그 외에는 자연스러운 같은 단계 선택 상황을 허용량이 남았을 때만 고른다. 그런 후보가 없으면 모든 선행 필수 상황이 `USED`이고 아직 `USED`가 아닌 필수 상황만 단계와 무관하게 고를 수 있다. 현재 상황 종료가 확정될 때 해당 상황을 `USED`로 처리하고 선택 상황이면 완료 수를 한 번 증가시킨다. 임의 새 장면으로 순서나 허용량을 우회하지 않는다.
- 필수 opening에 완료되지 않은 선행 필수 상황이 있으면 초기 준비 게시와 실제 모험 시작을 거부하며 시작 상태와 현재 상황을 만들지 않는다.

### 수용 조건
- 필수 상황과 현재 상황, 압축된 이전 대화, 최근 대화 원문, 캐릭터 개요가 GM 입력에 포함된다.
- 출처에 없는 최소 사실만 연속성 확보를 위해 추가하고 그 범위를 기록한다.
- 진행을 막는 근거 부족과 충돌은 임의로 확정하지 않고 진단 또는 사용자 확인으로 보낸다.
- 저장·복원한 상황 이름과 설명이 GM의 현재·후보 상황 문맥에 전달되어 실제 선택과 서술에 사용된다. 의도 분류와 사용 상태도 보존한다.
- 같은 모험 안에서 이미 격자를 맞춘 맵과 동일한 파일에 저장 정렬이 있으면 사용자에게 저장 격자 재사용 또는 직접 수정을 먼저 묻고, 선택 결과를 사용한다.

<a id="gm-context"></a>
## GM 입력과 대화 압축
수정일: 2026-10-19

### 설명
한 번의 GM 요청에 최신 상태, 필요한 근거와 대화 기록을 구성하고 확정된 차례 뒤 오래된 대화를 압축한다. 근거: [GM 문맥 압축 제품 명세](../specs/gm-context-compaction/product-spec.md).

### 비즈니스 규칙
- 캐릭터 시트와 현재 시츄에이션은 정본에서 읽고 대화 요약으로 덮어쓰지 않는다.
- 압축 대상은 최근 대화 기록이며, 전체 모험 상태를 압축하지 않는다.
- 도구를 통해 빠진 정보를 필요할 때 조회할 수 있도록 한다. 내부 프롬프트와 비공개 상태는 사용자에게 출력하지 않는다.

### 수용 조건
- GM 입력은 정본 상태·관련 근거·대화 이력을 분명히 구분한다.
- 압축 실패는 확정된 대화나 모험 상태를 손실시키지 않는다.
- AI 요청 로그는 길이·지문·구조만 남기고 원문 프롬프트와 응답을 기록하지 않는다.

<a id="rule-evidence"></a>
## 룰북 근거 검색과 판정 공개
수정일: 2026-10-20

### 설명
허가된 자료에서 판정에 필요한 근거를 찾고, 해결 과정과 공개할 결과를 분리한다. 근거: [런타임 근거 확장 명세](../specs/runtime-source-context-expansion/product-spec.md), [판정 공개 명세](../specs/runtime-reveal-filter/product-spec.md).

### 비즈니스 규칙
- 일반 GM 턴은 [#379 상황 선택·턴 조회·오케스트레이션 계획](https://github.com/omegafrog/dnd-master/issues/379)에 따라 허용된 STORYBOOK과 RULEBOOK을 한 번의 dense 검색으로 조회하고 출처별 최대 다섯 발췌를 조회 담당 AI에 전달한다. 별도 재정렬·충분성 판단 AI 호출은 추가하지 않으며 미발견 상태를 규칙 추측으로 덮지 않는다.
- 그 밖의 준비·판정 작업은 기존 작업별 근거 충분성 정책을 따른다. 해당 작업의 확장 정책이 적용되는 경우 근거 미발견 시 선택한 원문 위치의 같은 페이지 근거를 확장 검색하고 한 번 재조회한다. 이 경로의 한도와 재조회 정책을 일반 GM 턴에 다시 적용하지 않는다.
- 플레이어 행동에 필요한 굴림은 플레이어가 제출하고, 세계 사건은 시스템이 해결한다.
- GM 서술에는 공개 허용된 결과만 입력한다.

### 수용 조건
- 근거의 문서·출처 위치가 검색부터 GM 입력까지 이어진다.
- 검색 실패와 검증 실패는 숨겨진 정보나 내부 값 없이 사용자에게 설명 가능한 상태로 끝난다.
- 공개되지 않은 판정 정보는 API 응답과 서술에 포함되지 않는다.

## AI 제공자 연결
수정일: 2026-10-19

### 설명
클라이언트에서 Codex CLI 계정을 연결하고, 연결 상태와 해제·재연결을 관리한다. 근거: [Codex CLI 연결 제품 명세](../specs/codex-cli-oauth/product-spec.md).

### 비즈니스 규칙
- 기존 CLI 로그인을 재사용할 수 있다.
- 취소·만료·무효화는 원인을 표시하고 다시 연결할 수 있게 한다.
- 인증 정보는 로그와 플레이어용 계약에 노출하지 않는다.

### 수용 조건
- 연결 성공 후 다음 실행에서도 인증 상태를 사용할 수 있다.
- 연결 해제와 다른 계정으로의 재연결이 가능하다.
- 실패 시 세션 또는 모험 상태를 잘못 변경하지 않는다.

<a id="remote-agent"></a>
## 사용자 PC의 AI 요청 실행
수정일: 2026-10-19

### 설명
서버에서 완성된 AI 요청을 인증된 사용자 PC 실행기로 전달하고 응답을 호출자에게 돌려준다. 근거: [원격 Codex 실행 제품 명세](../specs/remote-codex-agent-port/product-spec.md).

### 비즈니스 규칙
- 로컬 개발 실행과 배포 실행은 하나의 실행 경계를 사용한다.
- 연결된 요청 사용자 실행기만 호출하고, 최종 응답 이전의 실패는 게임 상태를 변경하지 않는다.
- 중계 경로는 여러 인스턴스에서도 원래 요청과 응답을 연결한다.

### 수용 조건
- 요청이 맞는 사용자 실행기에 전달되어 동기 요청에 결과가 반환된다.
- 연결 단절과 실행 실패는 명확한 오류가 되고 모험 상태는 그대로다.
- 프롬프트 원문과 비밀 인증값은 진단 로그에서 제외된다.

## 폐기된 검색 설계
수정일: 2026-10-19

### 설명
고정 후보 수와 별도 충분성 정책을 중심으로 한 이전 검색 명세는 현재 기준으로 사용하지 않는다. 이전 자료: [폐기된 복합 검색 명세](../specs/hybrid-rag-evidence-selection/product-spec.md).

### 비즈니스 규칙
- 현재 검색 계약은 [룰북 근거 검색과 판정 공개](#rule-evidence) 및 활성 시나리오 명세를 따른다.
- 폐기된 명세는 현행 구현 요구나 검증 기준으로 사용하지 않는다.

### 수용 조건
- 폐기 상태가 검색 흐름의 소유 기능과 연결되어 있다.
- 신규 변경은 폐기 명세를 기준으로 설계되지 않는다.
