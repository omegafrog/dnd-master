# 룰북 검색 품질 개선 조사 및 적용 제안

- 작성일: 2026-10-16
- 상태: 조사 및 실험 제안. 아래 개선 효과는 아직 측정하지 않았으며 운영 경로에 적용하지 않았다.
- 범위: 기존 벡터 검색 개선. BM25는 사용하지 않는다.

## 현재 측정 결과와 단위 정정

Basic Roleplaying, Cairn Player, Cairn Warden의 저장된 추출 결과로 원문 질문 21개와 바꿔 묻기 63개를 평가했다. 상위 20개 검색 결과에 질문의 필수 정답 근거가 모두 포함되는지를 측정했다.

| 본문 분할 설정 | 원문 질문 | 바꿔 묻기 | 청크 수 |
| --- | --- | --- | --- |
| 200 | 20/21 | 52/63 | 2,480 |
| 300 | 19/21 | 54/63 | 2,062 |
| 350 | 19/21 | 54/63 | 1,999 |

위 설정값은 글자 수도, 임베딩 모델이 계산하는 실제 토큰 수도 아니다. 현재 `src/preprocessing_agent/utils/tokens.py`는 정규식 `\S+`로 공백 사이의 문자열 개수를 센다. 영어에서는 대략적인 단어 수에 해당한다. 이전에 이를 모델 토큰 수로 설명한 것은 부정확했다. 표는 별도의 기존 분할 제한을 유지했으므로 이 실험은 모든 청크의 크기를 동일하게 제한한 실험도 아니다.

200 설정에서는 원문 질문 결과가 개선됐지만 바꿔 묻기는 악화됐다. 청크 크기를 계속 줄이는 것만으로 품질이 개선된다고 볼 근거는 없다. 이후에는 실제 모델 토큰 수와 문자 수를 함께 기록한다.

정답 라벨은 아직 사용자 최종 승인 전이다. 바꿔 묻기 63개는 21개 원문 질문에서 파생됐으므로 독립적인 정답 사례 63개로 취급하지 않는다. 이 결과는 실제 AI 답변 품질이나 PDF 전체 내용 보존율을 측정한 것이 아니다.

## 1. 실패 원인을 먼저 분리

새 추출 없이 저장된 자료에서 실패 질문마다 다음을 확인한다.

1. 원본에서 확인한 정답 문구가 저장된 추출 텍스트에 존재하는가?
2. 청크로 나눈 뒤에도 조건·예외를 포함한 필요한 근거가 보존되는가?
3. 필요한 근거가 처음 등장하는 검색 순위는 어디인가? 여러 근거가 필요하면 각각 기록한다.
4. 최종 전달 범위에 들어온 근거가 입력량 제한 때문에 제거되지는 않는가?

텍스트에 없는 근거는 검색 재정렬로 복구할 수 없다. 후보 밖에 있는 근거도 후보 내부 순서만 바꾸는 재정렬로 복구할 수 없다. 반대로 텍스트와 후보에 이미 존재한다면 PDF 재추출보다 검색·선별 경로를 먼저 점검한다.

## 2. 질문 임베딩에 검색 목적 명시

Qwen 공식 문서는 질문에 작업 지시문을 붙이고, 검색 대상 문서에는 동일 지시문을 붙이지 않는 사용법을 제공한다. 공식 권장 형식은 다음과 같다.

```text
Instruct: Given a tabletop roleplaying rules question, retrieve passages that contain the rules needed to answer it.
Query: 사용자 질문
```

위 작업 문장은 이번 적용을 위한 제안이며 공식 예제 문장을 그대로 옮긴 것은 아니다. 최근 평가 스크립트는 질문 원문만 요청에 전달한다. 제공 서버가 지시문을 자동으로 추가하는지는 별도 확인해야 하며, 중복으로 붙이지 않는다.

적용 실험:

- 동일한 문서 벡터, 질문, 정답 라벨, 검색 개수를 유지한다.
- 지시문 없는 질문과 지시문을 붙인 질문을 비교한다.
- 문서 벡터를 재사용하고 질문 84개만 다시 임베딩한다.
- 질문 입력 형식이 바뀌었으므로 기존 질문 벡터를 잘못 재사용하지 않도록 캐시 입력을 구분한다.

전체 재임베딩 없이 시험할 수 있어 최우선으로 권장한다. 공식 자료의 개선 수치는 우리 룰북에서의 성능 보장이 아니다.

근거: [Qwen3-Embedding-0.6B 공식 모델 설명 및 사용법](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B).

## 3. 후보를 넓힌 뒤 질문과 본문을 함께 비교해 재정렬

벡터 검색으로 후보를 확보한 뒤, 질문과 후보 본문을 함께 입력받는 모델로 관련성을 다시 계산한다. 후보 검색은 넓게 하되 최종 답변 입력은 제한한다.

| 항목 | 초기 비교 설정 |
| --- | --- |
| 벡터 검색 후보 수 | 20개, 40개, 80개 |
| 재정렬 모델 후보 | Qwen3-Reranker-0.6B |
| 최종 전달 개수 | 5개, 10개 |
| 최종 전달 제한 | 개수뿐 아니라 실제 모델 토큰 예산도 적용 |

이 값들은 실험 시작점이며 검증된 최적값이 아니다. 80개 후보를 검색해도 80개 모두를 답변 생성 모델에 전달하지 않는다. 동일 후보 집합에서 재정렬 유무를 먼저 비교해 후보 수 증가 효과와 재정렬 효과를 구분한다. 기존 서비스의 재정렬 기능이 있다면 먼저 확인하고 재사용한다.

후보의 정답 근거 포함률, 최종 전달의 정답 근거 포함률, 추가 처리 시간과 메모리를 함께 측정한다. 후보에도 없는 정답을 재정렬 실패로 집계하지 않는다.

근거: [Sentence Transformers 검색 및 재정렬 안내](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html), [Qwen3-Reranker-0.6B 공식 모델](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B).

## 4. 확인된 제목과 표 머리글로 청크 문맥 보완

짧은 청크가 무엇을 설명하는지 알 수 있도록 원본에서 확인한 룰북 이름, 항목 제목, 표 제목과 열 머리글을 임베딩 입력에 포함하는 방식을 비교한다.

```text
룰북: Cairn
표 제목: 원본에서 확인한 제목
열 머리글: 원본의 열 이름

원래 청크 내용
```

- 미확정 제목 계층이나 근거 없는 설명을 생성하지 않는다.
- 원문과 추가된 검색용 문맥을 구분하고 원문 출처를 유지한다.
- 기존 제목 보강 실험을 확인해 같은 실험을 반복하지 않는다.
- 표 행 단위 분할은 별도 변수로 유지한다. 제목 보강과 동시에 변경해 효과를 혼동하지 않는다.
- 입력 본문이 바뀌므로 해당 문서 벡터는 다시 생성해야 한다.

Anthropic은 청크에 설명 문맥을 붙여 임베딩하는 방식을 소개한다. 여기서는 그중 벡터 검색에 문맥을 보강하는 접근만 참고한다. 원문의 BM25 결합이나 생성형 AI 기반 설명 작성은 이번 제안에 포함하지 않는다. 기존 제목만 붙이는 실험은 해당 연구 방법 전체를 재현하는 것이 아니므로 연구의 성능 수치를 그대로 기대하지 않는다.

근거: [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval).

## 5. 검색된 조각에 필요한 주변 문맥만 복원

검색된 조각이 문장 중간에서 시작하거나 조건·예외가 다음 조각에 있다면 같은 항목임이 확인되는 범위에서 문맥을 보완한다. 부모 청크 전체나 인접 청크를 무조건 합치지 않는다. 원문 범위가 겹치는 부분은 중복을 제거하고, 최종 입력 예산을 적용한다.

평가는 실제 최종 전달 텍스트에 필요한 정답 근거가 모두 포함되는지로 수행한다. 같은 부모 청크를 찾았다는 이유만으로 성공 처리하지 않는다.

긴 입력에서 근거의 위치에 따라 답변 성능이 달라질 수 있다는 연구가 있으므로, 단순히 더 많은 텍스트를 전달하는 것을 개선으로 간주하지 않는다. 해당 연구 결과가 현재 사용 모델에서도 동일한 크기로 나타난다는 뜻은 아니다.

근거: [Lost in the Middle: How Language Models Use Long Contexts](https://arxiv.org/abs/2307.03172).

## 적용 순서와 비교 기준

| 순서 | 작업 | 전체 문서 재임베딩 |
| --- | --- | --- |
| 1 | 정답 문구 존재 여부와 최초 검색 순위 확인 | 불필요 |
| 2 | Qwen 질문 지시문 유무 비교 | 질문만 재계산 |
| 3 | 후보 40·80개 확보 및 재정렬 비교 | 불필요 |
| 4 | 확인된 제목·표 머리글 보강 | 변경된 문서는 필요 |
| 5 | 필요한 주변 문맥 복원 및 최종 입력 평가 | 대체로 불필요 |

각 단계에서는 한 가지 변수부터 바꾸고 이전 단계와 비교한다. 입력 PDF·추출본·청크·정답 라벨·코드·모델·질문 형식의 버전 또는 해시를 기록한다. 캐시 재사용량과 새 임베딩 개수를 기록해 전체 재처리 시간과 추가 계산 시간을 구분한다.

필수 측정 항목:

- 후보 단계와 최종 전달 단계 각각의 질문별 필수 근거 완전 포함률
- 정답 근거가 처음 등장하는 순위와 누락된 근거 종류
- 최종 전달 문자 수와 실제 모델 토큰 수
- 질문 임베딩, 후보 검색, 재정렬, 문맥 구성 단계별 시간
- 개선된 질문과 새로 실패한 질문, 룰북별 결과
- 원문 질문과 바꿔 묻기의 결과를 분리한 집계

현재 21개 정답은 개발·회귀 비교용으로 사용한다. 최종 일반화 판단에는 개선에 사용하지 않은 질문과 룰북이 필요하다. 실제 답변 생성의 정확성·출처 일치도는 검색 근거 포함률과 별도로 검증한다.

## 재정렬 모델 오프라인 시험 결과 (2026-10-16)

200 설정의 동일한 2,480개 청크와 Qwen 임베딩 질문 지시문을 유지하고, 84개 질문에 대해 벡터 검색 상위 80개 후보를 Qwen3-Reranker-0.6B로 한 번씩 점수화했다. 같은 점수에서 상위 40개와 80개 후보 폭, 최종 전달 상위 5개와 10개를 각각 계산했다. BM25는 사용하지 않았다.

| 후보 폭 → 최종 전달 | 원문 질문 정답 근거 포함 | 바꿔 묻기 정답 근거 포함 | 평균 전달 문자 수 (원문 / 바꿔 묻기) |
| --- | --- | --- | --- |
| 벡터만 상위 5개 | 17/21 | 49/63 | 3,301 / 3,153 |
| 40개 재정렬 → 상위 5개 | 18/21 | 55/63 | 3,267 / 3,073 |
| 80개 재정렬 → 상위 5개 | 18/21 | 57/63 | 3,370 / 3,042 |
| 벡터만 상위 10개 | 19/21 | 53/63 | 6,755 / 6,310 |
| 40개 재정렬 → 상위 10개 | 20/21 | 57/63 | 6,385 / 5,921 |
| 80개 재정렬 → 상위 10개 | 20/21 | 60/63 | 6,159 / 5,890 |

필수 근거 단위로는 80개 재정렬의 상위 10개가 원문 질문 29/30, 바꿔 묻기 87/90을 포함했다. 같은 상위 10개 벡터 결과는 각각 28/30, 78/90이었다. 상위 80개 후보 풀 자체에는 84개 중 82개의 질문에 필요한 근거가 있었고, 상위 40개에는 77개가 있었다. 그러므로 후보 폭을 늘린 효과와 재정렬 효과를 구분해서 해석해야 한다.

80개 후보의 상위 10개 결과에서는 원문 질문 성능이 19/21에서 20/21, 바꿔 묻기는 53/63에서 60/63으로 개선됐다. 정답 근거가 후보 풀에는 있지만 최종 10개에서는 빠진 사례가 남아 있다. 특히 `cairn_pc_attributes__p2`, `cairn_pc_attributes__p3`, `warden_dungeon_die_one`, `warden_dungeon_die_one__p3`가 상위 80개 재정렬 뒤에도 완전한 근거를 포함하지 못했다. 뒤의 두 질문은 후보 80개에도 정답 근거가 없어서, 재정렬만으로 해결할 수 없다.

재정렬된 상위 10개의 평균 전달 텍스트는 벡터만 사용한 결과보다 원문 질문에서 약 9%, 바꿔 묻기에서 약 7% 짧았다. 따라서 이 표본에서는 정답 포함률 상승과 전달량 감소가 함께 나타났다. 상위 5개에서는 `cairn_alchemist_daily_cost`가 벡터 결과에서 성공했지만 재정렬 뒤 실패하는 작은 회귀가 있었고, 상위 10개에서는 회복됐다.

6,720개 질문·문서 쌍의 GPU 재정렬 계산은 약 2,190초(36.5분)가 걸렸다. 첫 실행의 모델 다운로드와 로딩 시간은 이 수치에 포함되지 않는다. 모든 쌍이 모델 입력 제한 안에 들어가 잘림은 0건이었다. 로컬 RTX 3060에서 진행했으며, 이 시간은 온라인 서비스 지연을 직접 예측하지 않는다.

결과 산출물: `/tmp/dnd-preprocessing-e2e-20261016/retrieval-eval/prose-limit-200-instruct-reranker-v1/reranker-evaluation.json`. 이 시험은 오프라인 검색 평가이며 서비스 경로에는 재정렬 모델을 적용하지 않았다. 정답 라벨은 사용자 승인 전 잠정본이다.
